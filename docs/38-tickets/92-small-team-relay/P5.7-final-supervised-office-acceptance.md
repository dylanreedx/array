## Goal

Complete real-host deployment, Linux proof when selected, sleep/wake and restore drills, office soak, security review, and retire the legacy relay path only after owner approval.

## Context and design direction

Read `_DESIGN.md`, `_RUNBOOK.md`, `_DECISIONS.md`, and `_ACTION_ITEMS.md` before editing. The trusted relay is a durable small-team control/data mirror; execution hosts retain provider secrets and final authority over local resources. Class-B authenticated transcript/tool content may cross only through the typed protocol, while Class-C credentials, environment values, signing keys, raw process handles, and unrelated filesystem content remain host-only. Exactly one ticket and one fenced production/check change set belong in an iteration.

This is the release gate. It combines deterministic evidence with real hardware/network/provider observations; no unit test alone can certify full-control phone behavior, APNs, forced sleep, backup custody, or low-cost VPS operation.

## Approach

1. Deploy on the owner-selected office machine or budget VPS with firewall/private route/TLS, service supervision, encrypted off-host backup, and no secrets in repo/argv/logs. Record actual monthly cost and provider terms at that date.
2. Run the full physical-phone flow plus two workspaces, two devices, two environments, live revoke, relay crash/restart, network partition, slow client, quota, backup/restore to replacement directory, and original/restored identity collision refusal.
3. Use an external phone/VPS witness for UI quit, lock/display off, idle sleep with policy, explicit Sleep/pmset sleepnow, lid close where applicable, wake replay, and an independent awake host.
4. Run the full target-hardware soak and actual Linux build/process/systemd smoke if Linux/VPS is supported.
5. After explicit approval, remove legacy raw BSD long-poll/token-registration production paths and their insecure baseline allowances; retain migration/refusal diagnostics as needed.

## Watch out

- Do not delete compatibility code before rollback/real-route proof.
- Do not claim progress while the execution host is actually asleep.
- Do not run restored/original relay identity concurrently.
- Never commit deployment credentials, APNs material, VPN keys, or recovery kit.
- Never stage, commit, reset, clean, stash, branch, rebase, merge, push, or alter queue/loop machinery from a worker session; the harness owns those actions.
- If the packet conflicts with compiled reality or an unresolved owner decision, return `WORKER: BLOCKED <evidence>` rather than inventing a second architecture.
