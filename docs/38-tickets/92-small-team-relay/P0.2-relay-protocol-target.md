# P0.2 — Relay Protocol Target

Phase: 0 · Program and contract foundation
Execution: **autonomous**
Depends on: P0.1

## Goal

Create a Foundation-only RelayProtocol target and fast check target so iPhone, Mac, execution hosts, and the server share wire types without inheriting GRDB, CloudKit, NIO, or host runtime code.

## Context and design direction

Read `_DESIGN.md`, `_RUNBOOK.md`, `_DECISIONS.md`, and `_ACTION_ITEMS.md` before editing. The trusted relay is a durable small-team control/data mirror; execution hosts retain provider secrets and final authority over local resources. Class-B authenticated transcript/tool content may cross only through the typed protocol, while Class-C credentials, environment values, signing keys, raw process handles, and unrelated filesystem content remain host-only. Exactly one ticket and one fenced production/check change set belong in an iteration.

The current RelayWire lives inside ContinuumRevivedSync, which links CloudKit and imports Core. Full-control frames need a narrower dependency direction. This ticket adds empty/seed vocabulary only; it does not migrate the live relay.

## Approach

1. Add ContinuumRevivedRelayProtocol and ContinuumRevivedRelayProtocolChecks targets. The protocol target may import Foundation and AgentContent only if a later packet proves the need; begin with Foundation only.
2. Add compiler/source/manifest gates that reject imports of Core, Sync, GRDB, NIO, CloudKit, AppKit, SwiftUI, Network, or Security.
3. Wire the fast check executable into the matrix before RelayChecks.
4. Keep current RelayWire unchanged as the compatibility source until P3.1.

### Implementation sketch

```text
target RelayProtocol -> Foundation only
target RelayProtocolChecks -> RelayProtocol only
forbiddenImport(any host, db, network, or UI module) => fail
```

The sketch fixes ownership and failure semantics, not exact spelling. Adapt names to compiled code without collapsing protocol, durable authority, network adapter, host execution, or client reduction into one type.

## Done when

- The new target builds on macOS and for the iOS package graph without linking CloudKit or GRDB.
- A negative import mutation fails at compile/check time.
- No existing relay behavior or wire version changes.
- New behavior has deterministic positive assertions and at least one required final-code mutation witness observed red, restored byte-for-byte, then rerun green.
- Existing expectations are not changed merely to bless the implementation; RED, implementation, and GREEN evidence are recorded separately.
- No matrix leg, assertion floor, privacy boundary, authorization denial, limit, or failure case is removed or weakened.
