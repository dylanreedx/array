# P5.4 — Launchd Service Lifecycle

Phase: 5 · Operations and deployment
Execution: **autonomous**
Depends on: P5.3

## Goal

Package a per-user macOS launchd service with stable paths, restart-on-failure, graceful stop, log/config ownership, and honest login/sleep semantics.

## Context and design direction

Read `_DESIGN.md`, `_RUNBOOK.md`, `_DECISIONS.md`, and `_ACTION_ITEMS.md` before editing. The trusted relay is a durable small-team control/data mirror; execution hosts retain provider secrets and final authority over local resources. Class-B authenticated transcript/tool content may cross only through the typed protocol, while Class-C credentials, environment values, signing keys, raw process handles, and unrelated filesystem content remain host-only. Exactly one ticket and one fenced production/check change set belong in an iteration.

Closing the Array UI should not stop an awake relay. A LaunchAgent survives UI quit but not logout/system sleep; the service contract and status output must say exactly that.

## Approach

1. Render/install/uninstall/status a stable absolute executable/config/data path; credentials are referenced through protected secret source, never ProgramArguments.
2. Set RunAtLoad/KeepAlive/throttle/log paths and graceful TERM timeout without respawn storm.
3. Provide side-effect-free __contract rendering for deterministic checks and use temporary HOME/support paths for install tests.
4. Status distinguishes UI closed, service running, logged out, host sleeping/unreachable, and configuration error where observable.

### Implementation sketch

```text
launchd ProgramArguments = [absoluteBinary, "serve", "--config", absoluteConfig]
// no secret values
KeepAlive + ThrottleInterval + safe log paths
```

The sketch fixes ownership and failure semantics, not exact spelling. Adapt names to compiled code without collapsing protocol, durable authority, network adapter, host execution, or client reduction into one type.

## Done when

- Rendered plist has exact supervision/paths/permissions and no fixture secret.
- Install/uninstall tests never touch the real user LaunchAgents.
- Real subprocess TERM/restart and executable replacement behavior are bounded.
- New behavior has deterministic positive assertions and at least one required final-code mutation witness observed red, restored byte-for-byte, then rerun green.
- Existing expectations are not changed merely to bless the implementation; RED, implementation, and GREEN evidence are recorded separately.
- No matrix leg, assertion floor, privacy boundary, authorization denial, limit, or failure case is removed or weakened.

## Watch out

- Do not claim operation during explicit Sleep/lid close.
- Do not use caffeinate forever; active-turn idle assertion is separate host behavior.
- Do not overwrite an existing service/config without backup/confirmation.
- Never stage, commit, reset, clean, stash, branch, rebase, merge, push, or alter queue/loop machinery from a worker session; the harness owns those actions.
- If the packet conflicts with compiled reality or an unresolved owner decision, return `WORKER: BLOCKED <evidence>` rather than inventing a second architecture.
