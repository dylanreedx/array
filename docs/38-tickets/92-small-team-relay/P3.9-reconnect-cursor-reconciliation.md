# P3.9 — Reconnect Cursor Reconciliation

Phase: 3 · Typed protocol and production transport
Execution: **autonomous**
Depends on: P3.8

## Goal

Implement client reconnect/backoff, durable cursors, snapshot reset, duplicate suppression-by-cursor, and protocol downgrade refusal for Mac/iPhone/host adapters.

## Context and design direction

Read `_DESIGN.md`, `_RUNBOOK.md`, `_DECISIONS.md`, and `_ACTION_ITEMS.md` before editing. The trusted relay is a durable small-team control/data mirror; execution hosts retain provider secrets and final authority over local resources. Class-B authenticated transcript/tool content may cross only through the typed protocol, while Class-C credentials, environment values, signing keys, raw process handles, and unrelated filesystem content remain host-only. Exactly one ticket and one fenced production/check change set belong in an iteration.

Clients need deterministic recovery across relay restart, network changes, revoked sessions, and compacted history. Reconnect must never treat an older relay generation as continuation of the previous log.

## Approach

1. Add `ContinuumRevivedRelayClient`, depending on RelayProtocol plus only the reviewed NIO client products needed for HTTP/WebSocket. It must not depend on RelayCore, GRDB, RelayNIO server code, ContinuumRevivedCore, or Sync.
2. Persist per-agent generation/sequence only after a caller-provided reducer/apply acknowledgement; the transport never assumes socket receipt means semantic application.
3. Port the proven injected backoff/network/wake semantics behind RelayClientConnectionState without importing the app's `ConnectionSupervisor`; reset attempt after stable welcome.
4. On generation mismatch or replay hole, request a compatible snapshot and ask the caller to replace only that agent document after validation.
5. Refuse server/client protocol downgrade; credential/auth refusals stop retry until user/admin action.

## Watch out

- Do not advance cursor on receipt of bytes before semantic apply.
- Do not clear every workspace because one agent needs a snapshot.
- Do not reuse legacy seq-only cursor for the new protocol.
- Do not place the client in RelayNIO: that would make phone/host clients inherit server, GRDB, and admin implementation.
- Never stage, commit, reset, clean, stash, branch, rebase, merge, push, or alter queue/loop machinery from a worker session; the harness owns those actions.
- If the packet conflicts with compiled reality or an unresolved owner decision, return `WORKER: BLOCKED <evidence>` rather than inventing a second architecture.
