# P3.7 — Presence Heartbeat Leases

Phase: 3 · Typed protocol and production transport
Execution: **autonomous**
Depends on: P3.6

## Goal

Add execution-host heartbeat leases and derived online/stale/offline presence that survives socket churn without claiming agent progress.

## Context and design direction

Read `_DESIGN.md`, `_RUNBOOK.md`, `_DECISIONS.md`, and `_ACTION_ITEMS.md` before editing. The trusted relay is a durable small-team control/data mirror; execution hosts retain provider secrets and final authority over local resources. Class-B authenticated transcript/tool content may cross only through the typed protocol, while Class-C credentials, environment values, signing keys, raw process handles, and unrelated filesystem content remain host-only. Exactly one ticket and one fenced production/check change set belong in an iteration.

Presence is ephemeral evidence anchored by a durable environment identity. A host is online only while a valid lease is renewed; relay restart or network loss must converge through injected time rules.

## Approach

1. Define heartbeat every 15s, stale after 45s defaults as configuration; checks inject monotonic clock.
2. Only environment sessions may renew their own lease. Multiple connections resolve deterministically.
3. Publish presence.changed only on state transition; store lastSeen metadata without making lease durability imply liveness after restart.
4. Commands consult current presence and refuse offline targets rather than queueing stale execution.

### Implementation sketch

```text
lease.renew(environmentID, sessionID, now)
state = now < expiry ? online : stale/offline
emit only if state changed
```

The sketch fixes ownership and failure semantics, not exact spelling. Adapt names to compiled code without collapsing protocol, durable authority, network adapter, host execution, or client reduction into one type.

- Avoid real sleeps in tests.
