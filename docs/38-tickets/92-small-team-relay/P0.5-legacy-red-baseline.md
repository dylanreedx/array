## Goal

Capture executable RED evidence for the current relay’s restart loss, client-chosen scope, plaintext in-memory credentials, shallow taint boundary, and Darwin server before replacing any of them.

## Context and design direction

Read `_DESIGN.md`, `_RUNBOOK.md`, `_DECISIONS.md`, and `_ACTION_ITEMS.md` before editing. The trusted relay is a durable small-team control/data mirror; execution hosts retain provider secrets and final authority over local resources. Class-B authenticated transcript/tool content may cross only through the typed protocol, while Class-C credentials, environment values, signing keys, raw process handles, and unrelated filesystem content remain host-only. Exactly one ticket and one fenced production/check change set belong in an iteration.

A future green test is not proof unless the pre-change behavior was observed. The committed default check may report the legacy limitations as expected baseline; a --require-hardened mode must exit nonzero today and become green only as named tickets land.

## Approach

1. Start the real legacy relay with a temporary directory, enroll/publish state, restart, and prove credentials/history/cursor state disappears.
2. Exercise POST /v1/tokens with client-supplied scopeRawValue and prove escalation is accepted under today’s operator grant.
3. Inspect the runtime registry through a check-only seam to prove raw token equality is the lookup key; never print the token.
4. Feed an allowed-looking Class-C value whose key avoids the shallow scanner and prove scanning is not an authorization boundary.
5. Gate Darwin-only imports/source assumptions explicitly. Record each expected failing hardening assertion separately.
