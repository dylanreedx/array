# P5.1 — Relay Configuration Secret Sources

Phase: 5 · Operations and deployment
Execution: **autonomous**
Depends on: P4.9

## Goal

Define validated relay configuration and OS/file secret sources for bind, database/blob paths, identity, credentials, APNs, quotas, retention, and deployment mode.

## Context and design direction

Read `_DESIGN.md`, `_RUNBOOK.md`, `_DECISIONS.md`, and `_ACTION_ITEMS.md` before editing. The trusted relay is a durable small-team control/data mirror; execution hosts retain provider secrets and final authority over local resources. Class-B authenticated transcript/tool content may cross only through the typed protocol, while Class-C credentials, environment values, signing keys, raw process handles, and unrelated filesystem content remain host-only. Exactly one ticket and one fenced production/check change set belong in an iteration.

Configuration should be boring and inspectable while secrets remain out of argv, logs, docs, plist ProgramArguments, and ordinary configuration files. Public bind requires explicit acknowledgement.

## Approach

1. Load non-secret TOML/JSON or environment config from an explicit path with strict unknown-key rejection and safe defaults.
2. Load administrator/APNs/encryption secrets from environment/file-descriptor/OS protected provider; never CLI flags.
3. Default loopback and refuse wildcard/public bind unless deploymentMode plus explicit acknowledgement is configured.
4. Render a redacted effective-config/doctor view with source provenance but no values for secrets.

### Implementation sketch

```text
config = try RelayConfiguration.load(file, env)
secrets = try SecretProvider.resolve(config.secretReferences)
validateBind(config)
print(config.redactedSummary)
```

The sketch fixes ownership and failure semantics, not exact spelling. Adapt names to compiled code without collapsing protocol, durable authority, network adapter, host execution, or client reduction into one type.

## Done when

- Malformed/unknown/duplicate config, unsafe permissions, missing secret, and wildcard bind fail before listener start.
- ps/argv/log/effective config do not contain fixture secrets.
- Loopback/private/public profiles have exact checked defaults.
- New behavior has deterministic positive assertions and at least one required final-code mutation witness observed red, restored byte-for-byte, then rerun green.
- Existing expectations are not changed merely to bless the implementation; RED, implementation, and GREEN evidence are recorded separately.
- No matrix leg, assertion floor, privacy boundary, authorization denial, limit, or failure case is removed or weakened.
