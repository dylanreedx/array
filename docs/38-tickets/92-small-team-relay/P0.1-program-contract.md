## Goal

Create the relay program’s self-checking queue/ledger contract and wire its non-skippable checks into the repository matrix before implementation starts.

## Context and design direction

Read `_DESIGN.md`, `_RUNBOOK.md`, `_DECISIONS.md`, and `_ACTION_ITEMS.md` before editing. The trusted relay is a durable small-team control/data mirror; execution hosts retain provider secrets and final authority over local resources. Class-B authenticated transcript/tool content may cross only through the typed protocol, while Class-C credentials, environment values, signing keys, raw process handles, and unrelated filesystem content remain host-only. Exactly one ticket and one fenced production/check change set belong in an iteration.

This is bootstrap infrastructure, not relay behavior. The program must fail closed when a packet, dependency, execution mode, ledger row, loop invariant, or matrix leg drifts. Preserve the existing queue-91 guard and matrix prefix; add this program without weakening or reordering the already locked agent-tile check.

## Approach

1. Extend the bootstrap program checker to cross-validate exactly 50 queue rows against packet title, phase, dependencies, execution mode, required headings, and one ledger row.
2. Add temporary-copy negative cases for missing packets, forward/cyclic dependencies, duplicate IDs, downgraded supervised gates, forged ledger metadata, loop model/review drift, and a removed matrix leg.
3. Wire one reported matrix leg without changing the existing first-four-line agent-tile prefix. Regenerate inventory; no old record may disappear or shrink.
4. Run the loop in a preflight-only mode and prove it refuses the current dirty UX candidate rather than absorbing it.
