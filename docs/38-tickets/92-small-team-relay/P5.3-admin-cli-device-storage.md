# P5.3 — Admin Cli Device Storage

Phase: 5 · Operations and deployment
Execution: **autonomous**
Depends on: P5.2

## Goal

Implement noninteractive and human-readable admin CLI commands for status, doctor, workspace/device/environment management, pairing, revoke, quota, archive/delete, backup, restore validation, and compaction.

## Context and design direction

Read `_DESIGN.md`, `_RUNBOOK.md`, `_DECISIONS.md`, and `_ACTION_ITEMS.md` before editing. The trusted relay is a durable small-team control/data mirror; execution hosts retain provider secrets and final authority over local resources. Class-B authenticated transcript/tool content may cross only through the typed protocol, while Class-C credentials, environment values, signing keys, raw process handles, and unrelated filesystem content remain host-only. Exactly one ticket and one fenced production/check change set belong in an iteration.

Operators must not edit SQLite or plist files manually. Every mutation goes through RelayCore authorization/invariant paths and produces safe auditable output.

## Approach

1. Parse exact subcommands with stable exit codes and optional JSON output.
2. Pairing create prints the one-use QR payload once to an owner-controlled terminal; --json requires explicit secret-output acknowledgement and never writes logs.
3. Revoke/rotate/archive/delete require IDs and confirmation/noninteractive force contract; backup/restore call tested services.
4. Doctor checks permissions, schema, integrity, blob manifest, bind/TLS proxy assumptions, clock, storage headroom, and service unit drift.

### Implementation sketch

```text
continuum-relay admin devices list
continuum-relay admin pairing create --workspace ID --role operator
continuum-relay admin backup --output FD_OR_PATH
```

The sketch fixes ownership and failure semantics, not exact spelling. Adapt names to compiled code without collapsing protocol, durable authority, network adapter, host execution, or client reduction into one type.

## Done when

- Every command runs against a temporary real database and has exact output/exit-code checks.
- Secret-emitting commands write only the intended stdout/TTY channel and redact stderr/logs.
- Invalid/ambiguous IDs never choose “closest” resources.
- New behavior has deterministic positive assertions and at least one required final-code mutation witness observed red, restored byte-for-byte, then rerun green.
- Existing expectations are not changed merely to bless the implementation; RED, implementation, and GREEN evidence are recorded separately.
- No matrix leg, assertion floor, privacy boundary, authorization denial, limit, or failure case is removed or weakened.
