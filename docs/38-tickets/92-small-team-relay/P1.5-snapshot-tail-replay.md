# P1.5 — Snapshot Tail Replay

Phase: 1 · Durable single-node state
Execution: **autonomous**
Depends on: P1.4

## Goal

Add semantic snapshots and lossless snapshot-plus-tail replay for cold, compacted, and stale clients.

## Context and design direction

Read `_DESIGN.md`, `_RUNBOOK.md`, `_DECISIONS.md`, and `_ACTION_ITEMS.md` before editing. The trusted relay is a durable small-team control/data mirror; execution hosts retain provider secrets and final authority over local resources. Class-B authenticated transcript/tool content may cross only through the typed protocol, while Class-C credentials, environment values, signing keys, raw process handles, and unrelated filesystem content remain host-only. Exactly one ticket and one fenced production/check change set belong in an iteration.

Retention until archive/delete does not mean every reconnect should reduce an unbounded log. Snapshots are performance accelerators, not substitutes for missing committed events unless compaction policy explicitly says so.

## Approach

1. Store snapshots with agent, generation, throughSequence, semantic schema version, and canonical document bytes.
2. Choose the newest compatible snapshot at or before the retained tail; return exact tail rows after throughSequence.
3. Reject future generation, ahead-of-head cursor, incompatible snapshot schema, and a retained-history hole.
4. Build snapshots from the same provider-neutral reducer used by clients; prove snapshot+tail equals full reduction across seeded split points.

### Implementation sketch

```text
snapshot = latestCompatible(agent, generation)
tail = events(after: snapshot?.throughSequence ?? 0)
assert contiguous(tail) else throw replayHole
```

The sketch fixes ownership and failure semantics, not exact spelling. Adapt names to compiled code without collapsing protocol, durable authority, network adapter, host execution, or client reduction into one type.

## Done when

- Every fixture history yields byte/equality-equivalent full replay and snapshot+tail replay.
- A client at head receives an empty tail; a stale/holey cursor receives a machine-readable refusal, never partial history.
- Snapshot creation failure does not remove source events.
- New behavior has deterministic positive assertions and at least one required final-code mutation witness observed red, restored byte-for-byte, then rerun green.
- Existing expectations are not changed merely to bless the implementation; RED, implementation, and GREEN evidence are recorded separately.
- No matrix leg, assertion floor, privacy boundary, authorization denial, limit, or failure case is removed or weakened.

- Do not couple snapshot encoding to an AppKit/iOS view model.
- Do not accept a host-authored snapshot without independently validating its cursor/document reduction contract.
- Schema incompatibility must be visible, not silently treated as empty transcript.
