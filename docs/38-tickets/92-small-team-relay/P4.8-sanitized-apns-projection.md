# P4.8 — Sanitized Apns Projection

Phase: 4 · Full-control host and phone flows
Execution: **autonomous**
Depends on: P4.7

## Goal

Persist APNs registrations securely and send optional direct Class-A pushes derived from durable state without transcript, prompt, tool, path, or secret content.

## Context and design direction

Read `_DESIGN.md`, `_RUNBOOK.md`, `_DECISIONS.md`, and `_ACTION_ITEMS.md` before editing. The trusted relay is a durable small-team control/data mirror; execution hosts retain provider secrets and final authority over local resources. Class-B authenticated transcript/tool content may cross only through the typed protocol, while Class-C credentials, environment values, signing keys, raw process handles, and unrelated filesystem content remain host-only. Exactly one ticket and one fenced production/check change set belong in an iteration.

Push is a wake/hint channel, never state authority. The relay may store APNs tokens encrypted with local key material; failure or duplication must not change command/request state.

## Approach

1. Move/share the sanitized payload vocabulary in RelayProtocol so RelayCore does not depend on the Apple app's Core target; preserve compatibility for current app callers.
2. Register the iPhone device token only for the authenticated device; encrypt it at rest using injected key provider and separate sandbox/production/topic metadata.
3. Derive push from committed completion/needs-input transitions and use only safe title/category/opaque IDs within APNs 4 KiB limit.
4. Implement a portable APNs HTTP/2/JWT adapter in RelayNIO using the reviewed portable crypto dependency and FoundationNetworking/NIO facilities that compile on the supported Linux server graph; do not import Apple-only CryptoKit into relay server targets.
5. Deduplicate/coalesce notifications without suppressing durable state; classify APNs invalid-token response to revoke only that registration.
6. Use a fake APNs transport in normal checks and an explicit owner-configured real smoke later.

## Watch out

- Do not distribute the APNs signing key to execution hosts.
- Do not put device token in logs.
- Without APNs configuration the relay remains healthy and foreground reconnect works.
- Do not claim Linux APNs support from conditional compilation alone; P5.7 requires the real Linux process path when Linux is advertised.
- Never stage, commit, reset, clean, stash, branch, rebase, merge, push, or alter queue/loop machinery from a worker session; the harness owns those actions.
- If the packet conflicts with compiled reality or an unresolved owner decision, return `WORKER: BLOCKED <evidence>` rather than inventing a second architecture.
