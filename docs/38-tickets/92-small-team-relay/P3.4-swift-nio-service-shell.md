# P3.4 — Swift Nio Service Shell

Phase: 3 · Typed protocol and production transport
Execution: **autonomous**
Depends on: P3.3

## Goal

Add reviewed SwiftNIO dependencies, a RelayNIO target, and a real process shell with lifecycle, signal, and ephemeral-port readiness behavior.

## Context and design direction

Read `_DESIGN.md`, `_RUNBOOK.md`, `_DECISIONS.md`, and `_ACTION_ITEMS.md` before editing. The trusted relay is a durable small-team control/data mirror; execution hosts retain provider secrets and final authority over local resources. Class-B authenticated transcript/tool content may cross only through the typed protocol, while Class-C credentials, environment values, signing keys, raw process handles, and unrelated filesystem content remain host-only. Exactly one ticket and one fenced production/check change set belong in an iteration.

Networking is an adapter around tested RelayCore. The service target owns NIO and sockets; Protocol/Core remain free of them. This ticket serves health only and composes dependencies without migrating all routes.

## Approach

1. Pin/review swift-nio, NIOHTTP1, NIOWebSocket, and optionally NIOSSL only if direct TLS is approved.
2. Create RelayNIO target depending on RelayCore/Protocol and NIO products; update executable composition.
3. Bind explicit host/port including port 0, emit one secret-free readiness record, handle TERM/INT, stop admission, and close cleanly.
4. Add a real subprocess harness using temp data/config and no credentials in argv/logs. Keep legacy server available behind a compatibility mode.

### Implementation sketch

```text
service = RelayNIOService(core, bind)
try await service.start()
printSafeReady(boundAddress)
await signals.first
try await service.gracefulShutdown()
```

The sketch fixes ownership and failure semantics, not exact spelling. Adapt names to compiled code without collapsing protocol, durable authority, network adapter, host execution, or client reduction into one type.

## Done when

- Dependency checks prove NIO does not leak into RelayProtocol/Core.
- Credential fixtures do not appear in argv, stdout, stderr, or readiness.
- New behavior has deterministic positive assertions and at least one required final-code mutation witness observed red, restored byte-for-byte, then rerun green.
