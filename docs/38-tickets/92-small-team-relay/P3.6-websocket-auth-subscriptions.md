# P3.6 — Websocket Auth Subscriptions

Phase: 3 · Typed protocol and production transport
Execution: **autonomous**
Depends on: P3.5

## Goal

Implement authenticated WebSocket upgrade, version handshake, workspace/agent subscriptions, replay bootstrap, and typed frame dispatch.

## Context and design direction

Read `_DESIGN.md`, `_RUNBOOK.md`, `_DECISIONS.md`, and `_ACTION_ITEMS.md` before editing. The trusted relay is a durable small-team control/data mirror; execution hosts retain provider secrets and final authority over local resources. Class-B authenticated transcript/tool content may cross only through the typed protocol, while Class-C credentials, environment values, signing keys, raw process handles, and unrelated filesystem content remain host-only. Exactly one ticket and one fenced production/check change set belong in an iteration.

Long-poll cannot provide efficient full-control or suspended-iOS semantics. The socket authenticates once at upgrade but each dispatched operation still consults current authorization and operation policy.

## Approach

1. Require Authorization at upgrade, negotiate supported protocol major, and bind session to authenticated principal ID.
2. Accept explicit subscription frames; resolve resource workspace from store and bootstrap snapshot+tail before live activation.
3. Dispatch through OperationPolicy and bounded decoder; one bad frame yields typed error or policy close without crashing other sessions.
4. Implement deterministic session teardown and reverse registration for revocation.

### Implementation sketch

```text
upgrade(auth) -> Session(principal)
on subscribe(agent,cursor): authorize; replay; atomicallyActivateLive
on frame: policy.dispatch(principal, frame)
```

The sketch fixes ownership and failure semantics, not exact spelling. Adapt names to compiled code without collapsing protocol, durable authority, network adapter, host execution, or client reduction into one type.

## Done when

- Real clients receive gap-free replay then live events under concurrent publish.
- Missing/bad/revoked credentials and wrong versions fail at the correct boundary.
- Cross-workspace subscription never discloses whether the agent exists.
- New behavior has deterministic positive assertions and at least one required final-code mutation witness observed red, restored byte-for-byte, then rerun green.
- Existing expectations are not changed merely to bless the implementation; RED, implementation, and GREEN evidence are recorded separately.
