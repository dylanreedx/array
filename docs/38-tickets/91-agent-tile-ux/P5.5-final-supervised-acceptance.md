# P5.5 — Final supervised live acceptance and compatibility removal

Phase: 5 · Live integration
Execution: **supervised**
Depends on: P5.4

## Goal

Approve the installed live agent tile, make v2 the sole production path, and remove temporary compatibility UI only after real use succeeds.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark
tokens, keyboard accessibility, and I5. Visible Aqua dropdown or rounded text-field styling is not
acceptable in new tile UI. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

## Approach

1. Install a verified-fresh app and run a real agent through multiline prompt, Markdown response, tools, code, failure, approval/question when available, Stop, model/effort change, detach/re-attach, and relaunch.
2. Review light/dark and 320/480/640/900 widths with Reduce Motion and keyboard-only navigation.
3. Confirm no Aqua dropdown/text-field chrome remains in the live agent tile.
4. After explicit owner approval, flip v2 default, delete old view-only card path/feature flag, retain semantic compatibility projection only if another caller remains, and update docs.
5. Run focused checks five times, full headless matrix, then supervised surface matrix and save artifacts.

- Owner explicitly approves the live behavior and visual direction.
- No old visible compose field/popups/card factory remain reachable.
- All tests and baseline diffs are green/stable; no I5 leak.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.
