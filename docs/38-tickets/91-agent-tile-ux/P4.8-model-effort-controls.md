# P4.8 — Replace model and effort popups with custom controls

Phase: 4 · Composer
Execution: **autonomous**
Depends on: P4.7

## Goal

Keep per-agent next-turn settings close to the prompt while making them visually coherent, responsive, and truthful.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark
tokens, keyboard accessibility, and I5. Visible Aqua dropdown or rounded text-field styling is not
acceptable in new tile UI. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

- `Sources/ContinuumRevived/Canvas/AgentComposer/AgentComposerFooterView.swift`

The file fence is intentional. If a compile-enforced migration requires a directly related call
site outside it, document the reason in the ledger before touching it. Do not absorb adjacent UX,
relay, FileTree, provider migration, or cleanup work.

## Approach

1. Read options from `AgentModelConfig`; do not retype catalogs.
2. Use compact, friendly custom choice buttons with quiet fills and deliberate chevrons—not stock popup facsimiles—with full labels at wide widths and unambiguous abbreviated labels at narrow widths.
3. Persist through existing `AgentSupervisor.setProviderSettings`.
4. Label them “next turn” through context/help, not a disabled selectable menu header.
5. Keep live tile old controls until final migration flag.

### Implementation sketch

```swift
footer.modelButton.apply(.init(title: displayModel(settings.model), accessibilityLabel: "Model, next turn"))
footer.effortButton.apply(.init(title: settings.thinking, accessibilityLabel: "Reasoning effort, next turn"))
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples parsing, rendering, and agent execution.

### Truthful settings boundary

These controls edit only the compiled setting scope the runtime currently supports. If compiled behavior applies model/effort to the next turn, label and test it as next-turn state; do not claim live RPC mutation. Preserve provider defaults and capability absence without inventing an unsupported selector value.

## Done when

- Non-default values survive detach/re-attach and disk reload.
- Resting, hover, focus, pressed, and open states read as one coherent Continuum control family rather than raw native dropdowns.
- Changing only effort cannot overwrite an off-catalog model and vice versa.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

- Do not disable settings merely because the old popups did if capabilities say next-turn changes are allowed.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
