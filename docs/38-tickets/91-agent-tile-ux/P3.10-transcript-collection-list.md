# P3.10 — Build the reusable transcript collection list

Phase: 3 · Transcript rendering
Execution: **autonomous**
Depends on: P3.9

## Goal

Replace the permanent stack-of-views architecture with a stable-ID list that owns reuse, measurement, and renderer resolution.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark
tokens, keyboard accessibility, and I5. Visible Aqua dropdown or rounded text-field styling is not
acceptable in new tile UI. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

## Approach

1. Implement a view-based `NSCollectionView` with one host item per top-level semantic block/entry.
2. Apply document patches by ID; forbid production `reloadData` after initial load.
3. Pin width correctly in flipped/scroll coordinates and invalidate measurements only for changed IDs or width bucket.
4. Keep behind an internal fixture/feature flag; old live transcript stays visible.

### Implementation sketch

```swift
func apply(document: AgentDocument, patch: AgentDocumentPatch) {
    dataSource.apply(snapshot(from: document, patch: patch), animatingDifferences: false)
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples parsing, rendering, and agent execution.

## Done when

- A one-block update preserves every unaffected host view identity.
- 10,000 semantic blocks do not create 10,000 live NSViews when viewport is small.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.
