# P4.10 — Supervised composer design review

Phase: 4 · Composer
Execution: **supervised**
Depends on: P4.9

## Goal

Review the complete isolated composer—editing, growth, custom choices, action states, and completion popup—before integrating it into the live tile.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark
tokens, keyboard accessibility, and I5. Visible Aqua dropdown or rounded text-field styling is not
acceptable in new tile UI. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

relay, FileTree, provider migration, or cleanup work.

## Approach

1. Render empty, focused, multiline, long, working/Stop, narrow, model menu, effort menu, and completion states in both themes.
2. Exercise real typing, IME/marked text, undo, history, selection, and keyboard navigation in an installed candidate.
3. Ask the owner whether it feels like a polished Claude Code pane rather than a form field.
4. Bless only approved candidate baselines and record corrections.

## Done when

- Owner explicitly approves or sends correction tickets.
- All deterministic key/geometry/contrast/accessibility checks are green.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.
