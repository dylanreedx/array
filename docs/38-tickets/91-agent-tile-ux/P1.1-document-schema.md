# P1.1 — Define AgentDocument, entries, blocks, and inline values

Phase: 1 · Semantic document
Execution: **autonomous**
Depends on: P0.5

## Goal

Introduce the immutable semantic document vocabulary that separates provider events from Markdown syntax and AppKit presentation.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark
tokens, keyboard accessibility, and I5. Visible Aqua dropdown or rounded text-field styling is not
acceptable in new tile UI. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

## Approach

1. Define Sendable/Equatable/Codable value types for document, entry, block, inline run, role, provenance, status, and source range.
2. Make `AgentBlockKind` a validated raw semantic key with built-in constants rather than a UI enum.
3. Keep payloads typed for built-ins and include an opaque payload case for future kinds.
4. Do not include NSFont, NSColor, NSImage, closures, or view state.

### Implementation sketch

```swift
public struct AgentBlock: Identifiable, Codable, Equatable, Sendable {
    public let id: AgentNodeID
    public var revision: UInt64
    public var kind: AgentBlockKind
    public var sourceRange: AgentSourceRange?
    public var payload: AgentBlockPayload
    public var children: [AgentBlock]
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples parsing, rendering, and agent execution.
