# P0.5 — Gate the old and new transcript pipelines side by side

Phase: 0 · Foundations
Execution: **autonomous**
Depends on: P0.4

## Goal

Establish a real-path compatibility harness before replacing the flat card model, so later tickets can evolve semantics without silently losing current behavior.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark
tokens, keyboard accessibility, and I5. Visible Aqua dropdown or rounded text-field styling is not
acceptable in new tile UI. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

relay, FileTree, provider migration, or cleanup work.

## Approach

1. Extract a fixture runner that feeds identical `AgentRuntimeEvent` sequences into projections.
2. Record the current six-kind card order, IDs, bodies, item status, active tool count, and turn status as the compatibility floor.
3. Provide an empty seam for the future document projection but do not implement the new model here.

### Implementation sketch

```swift
struct TranscriptCompatibilitySnapshot: Equatable {
    var ids: [String]
    var kinds: [ManagedTranscriptCardKind]
    var bodies: [String]
    var activeToolCount: Int
    var status: AgentStatus
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples parsing, rendering, and agent execution.

## Done when

- Pre-tool prose, tool record, and post-tool prose remain in order.
- A new turn cannot append into the prior assistant turn.
- Changing a current card ID or dropping completion status fails.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- This is a temporary floor, not a command to preserve every old presentation detail.
- Do not add AppKit to the compatibility check.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
