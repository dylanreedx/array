# P1.2 — Specify stable node identity and revision semantics

Phase: 1 · Semantic document
Execution: **autonomous**
Depends on: P1.1

## Goal

Make identity rules explicit so streaming updates and renderer reuse can be correct rather than guessed from array position or source offset.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark

## Approach

1. Introduce typed `AgentNodeID` with deterministic child allocation scoped to a stable entry/provider item ID.
2. Specify that IDs never derive solely from mutable source offsets or array count.
3. Increment revision only when visible semantic data changes; status-only changes count, timestamps that are not rendered do not.
4. Add invariants for uniqueness across a document and monotonic revision per ID.

### Implementation sketch

```swift
struct AgentNodeID: RawRepresentable, Hashable, Codable, Sendable {
    let rawValue: String
}
// e.g. entry:<turn-id>/block:<stable-ordinal>, never "offset:217"
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples parsing, rendering, and agent execution.
