# P3.9 — Build approval, question, error, notice, and unknown renderers

Phase: 3 · Transcript rendering
Execution: **autonomous**
Depends on: P3.8

## Goal

Complete renderer coverage for action-bearing and exceptional semantic blocks with safe fallback behavior.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark
tokens, keyboard accessibility, and I5. Visible Aqua dropdown or rounded text-field styling is not
acceptable in new tile UI. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

The file fence is intentional. If a compile-enforced migration requires a directly related call
site outside it, document the reason in the ledger before touching it. Do not absorb adjacent UX,
relay, FileTree, provider migration, or cleanup work.

## Approach

1. Render approval/question content but route actions through context closures keyed by request ID.
2. Use custom Continuum buttons/choice rows; no stock popup.
3. Errors expose retry/copy details only when actions exist.
4. Unknown renderer shows safe kind/summary and never dumps opaque payload.

### Implementation sketch

```swift
context.actions.decideApproval(requestID, .approve)
context.actions.submitAnswers(requestID, answers)
// no renderer references AgentSupervisor directly
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples parsing, rendering, and agent execution.
