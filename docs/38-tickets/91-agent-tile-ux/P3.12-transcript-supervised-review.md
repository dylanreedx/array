# P3.12 — Supervised transcript design review

Phase: 3 · Transcript rendering
Execution: **supervised**
Depends on: P3.11

## Goal

Put the isolated transcript system in Component Lab, install a candidate app, and obtain human approval before composer work builds on its density and hierarchy.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark
tokens, keyboard accessibility, and I5. Visible Aqua dropdown or rounded text-field styling is not
acceptable in new tile UI. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

## Approach

1. Create mixed, long, active-tool, failed-tool, approval, and narrow transcript states in both appearances.
2. Run deterministic geometry/contrast/accessibility checks first.
3. Build/install the candidate app and present 320/480/640/900 pt screenshots plus live scroll/selection. Keep the review explicitly on the isolated semantic transcript: the installed app still contains legacy sidebar/inbox, composer popups, and approval dock that are replaced only by the locked P4/P5 packets.
4. Record any feedback about those legacy surfaces against the existing downstream packets rather than absorbing it into the transcript fence or pretending the old UI is the target.
5. Only after explicit owner approval of the isolated transcript, bless narrowly named new baselines and record review notes.

## Done when

- Owner explicitly approves or provides corrections.
- Baseline diffs are inspected in both appearances and stable over three runs.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.
