# P3.8 — Build plan and diff renderers

Phase: 3 · Transcript rendering
Execution: **autonomous**
Depends on: P3.7

## Goal

Give plans and file changes dedicated semantic presentations instead of generic title/body cards.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark
tokens, keyboard accessibility, and I5. Visible Aqua dropdown or rounded text-field styling is not
acceptable in new tile UI. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

## Files

- `Sources/ContinuumRevived/Canvas/AgentTranscript/Renderers/PlanRenderer.swift`
- `Sources/ContinuumRevived/Canvas/AgentTranscript/Renderers/DiffSummaryRenderer.swift`
- `Sources/ContinuumRevived/App/ComponentLab.swift`

The file fence is intentional. If a compile-enforced migration requires a directly related call
site outside it, document the reason in the ledger before touching it. Do not absorb adjacent UX,
relay, FileTree, provider migration, or cleanup work.

## Approach

1. Render plan steps with status/ordinal hierarchy and collapsed completed detail.
2. Render diff summaries with counts and safe display names supplied by the payload; do not parse unified diff text in the view.
3. Route “open review” through render context action.
4. Keep both renderers isolated from the production tile until review/integration.

### Implementation sketch

```swift
context.actions.openDiff(block.id)
// Renderer receives semantic files/hunks summary, never shells out or reads disk.
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples parsing, rendering, and agent execution.

### Passive plan contract

A plan block is provider-owned, read-only progress. It may expose active/completed hierarchy and optional detail, but it may not add checkboxes, reorder controls, local persistence, or prose-derived steps. Diff content remains inspectable transcript evidence with a route to the existing DiffReview surface; it is not a second source-control UI.

## Done when

- Plan and diff fixtures resolve to distinct renderers and accessibility roles.
- No filesystem read occurs during render or measure.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Verify

```bash
swift build
.build/debug/continuum-revived --agent-supervisor-check
CONTINUUM_SKIP_SURFACE_CHECKS=1 ./scripts/run-matrix.sh
```

For AppKit work, also run the exact geometry/appearance/Component Lab flags named by the packet.
Visual baseline changes are forbidden in autonomous tickets unless this packet explicitly says it
is a supervised visual gate. Record commands, exit codes, measured counts, and the negative witness
in `_LEDGER.md`.

## Watch out

- Do not invent full diff UI inside the transcript; Continuum already has a DiffReview tile.
- I5 forbids paths in phone payloads, not necessarily safe local rendering—keep boundaries explicit.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
