# P5.3 — Project provider current work into the tile and FileTree

Phase: 5 · Live integration
Execution: **autonomous**
Depends on: P5.2

## Goal

Show each agent's explicit provider-managed current work and exceptional needs consistently in its tile and the FileTree/agent index, without inventing a Continuum task manager or approval layer.

## Context and design direction

The canvas is the session switcher and one agent tile is one interactive session. Agents may expose todo/plan state as explicit provider events. Continuum observes that state and derives one bounded, read-only snapshot: active item, completed/total progress, and an optional disclosure of provider-owned items. Never infer a plan from assistant prose, tool names, elapsed time, or process liveness. Never create, reorder, check off, or persist a parallel list.

Execution is autonomous/dangerous by default. There is no permanent approval dock. If a provider genuinely suspends a turn on an enforced question/approval, present that exceptional need compactly and nonmodally through the same snapshot; do not add a Continuum permission gate.

## Approach

1. Define one bounded, session-scoped current-work snapshot from explicit provider state already exposed by the runtime.
2. Carry the same snapshot to the tile and agent index; do not create independent reducers or polling paths.
3. Render active item plus concise `completed / total` progress passively. Keep full provider items behind optional read-only disclosure.
4. Surface exceptional provider-enforced needs as a compact attention state that never hides transcript or composer and never becomes a modal dock.
5. Clear/replace the snapshot on explicit provider updates, turn/session replacement, and detach according to the existing agent/tile ownership rules.
6. Add deterministic checks for active/completed progress, cross-surface identity, bounded item count, stale-session rejection, absent state, and exceptional need behavior.

### Implementation sketch

```swift
struct AgentCurrentWorkSnapshot: Equatable, Sendable {
    let sessionID: AgentSessionID
    let activeItem: String?
    let completedCount: Int
    let totalCount: Int
    let items: [ProviderWorkItem] // bounded, read-only
    let exceptionalNeed: ProviderEnforcedNeed?
}
```

Names may adapt to compiled reality. The ownership and negative constraints may not.

## Done when

- Tile and FileTree/agent index display the same explicit active item and progress.
- No provider state produces no fabricated plan UI.
- Prose resembling a checklist cannot create or mutate current work.
- The projection is bounded, session-correct, read-only, accessible, and contains no new approval gate.
- Relevant new behavior has deterministic positive assertions and a required negative witness observed red against the final check.
- I5 and all existing matrix floors remain green.

## Watch out

- Do not infer provider plans from prose, reasoning, tool activity, or liveness.
- Do not add task mutation controls, a second source of truth, a context tile, or a permanent approval dock.
- Do not widen provider/runtime RPCs here; queue 90 owns those capabilities.
- Do not let stale work from one session appear on another attached tile.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
