# P1.4 — Implement the pure AgentDocumentReducer

Phase: 1 · Semantic document
Execution: **autonomous**
Depends on: P1.3

## Goal

Apply content mutations with validated identity, ordering, status transitions, revisions, and minimal patches in one pure reducer.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark
tokens, keyboard accessibility, and I5. Visible Aqua dropdown or rounded text-field styling is not
acceptable in new tile UI. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

## Approach

1. Represent open versus finished entry lifecycle in `AgentDocument`, with checked Codable behavior,
   so `finishEntry` is semantic state rather than a reducer-local marker or no-op.
2. Implement each mutation case without clocks, global state, or provider types. Any lookup or
   streaming cache must be fully reconstructible from `AgentDocument`; two reducers initialized from
   equal snapshots must produce equal results for the same next mutation.
3. Keep updates indexed. Repeated updates to existing structured blocks must not rebuild the entire
   document or exhibit quadratic behavior.
4. Reject append-after-finish, duplicate finish, completion of unknown blocks, and invalid backwards
   status transitions with explicit mutation errors.
5. Exercise interleaved assistant text and structured blocks, reconstruction during an open stream,
   finish boundaries, opaque future blocks, inserted revision normalization, and repeated existing
   structured updates.

The preserved first-attempt diff and final blocking review are available as evidence, not as trusted
code, under `~/.pi/agent-tile-ux-runs/continuum-overnight/run-20260729T002349/tasks/iteration-002/`.
The three unresolved findings were hidden `openMarkup` history, a no-op `finishEntry`, and full-index
rebuilds for existing structured upserts.

### Implementation sketch

```swift
public mutating func apply(_ mutation: AgentDocumentMutation) throws -> AgentDocumentPatch {
    let before = document.version
    // validate → mutate one semantic owner → derive minimal IDs
    document.version += 1
    return AgentDocumentPatch(fromVersion: before, toVersion: document.version, ...)
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples parsing, rendering, and agent execution.

## Done when

- The same mutation sequence always yields the same document and patch sequence, including after
  constructing a new reducer from an intermediate open or finished document snapshot.
- 10,000 mutations and repeated existing-block upserts do not exhibit quadratic lookup behavior in
  the check budget.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.
