# P1.3 — Define transcript mutations and document patches

Phase: 1 · Semantic document
Execution: **autonomous**
Depends on: P1.2

## Goal

Create the only write vocabulary for evolving a document and the minimal patch vocabulary consumed by UI lists.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark
tokens, keyboard accessibility, and I5. Visible Aqua dropdown or rounded text-field styling is not
acceptable in new tile UI. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

## Approach

1. Cover begin entry, append markup, upsert structured block, complete block, finish entry, and remove entry.
2. Define inserted/updated/removed/moved stable IDs plus old/new document versions.
3. Make illegal references and duplicate begin operations explicit errors, not ignored no-ops.
4. Keep mutations content-level; no scroll, selection, focus, or view instructions.

### Implementation sketch

```swift
public struct AgentDocumentPatch: Equatable, Sendable {
    public let fromVersion: UInt64
    public let toVersion: UInt64
    public var inserted: [AgentNodeID]
    public var updated: [AgentNodeID]
    public var removed: [AgentNodeID]
    public var moved: [AgentNodeID]
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples parsing, rendering, and agent execution.

## Done when

- Every successful mutation advances document version exactly once.
- No-op semantic updates produce an empty patch without bumping node revision.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.
