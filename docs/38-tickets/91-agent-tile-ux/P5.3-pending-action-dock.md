# P5.3 — Anchor pending approvals and questions near the composer

Phase: 5 · Live integration
Execution: **autonomous**
Depends on: P5.2

## Goal

Keep required human actions visible at the point of response while preserving resolved records in transcript history.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark
tokens, keyboard accessibility, and I5. Visible Aqua dropdown or rounded text-field styling is not
acceptable in new tile UI. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

## Approach

1. Project the highest-priority unresolved approval/question into a dock above the composer.
2. Use blocker precedence already defined by lifecycle logic.
3. After resolution, remove action controls from dock and leave a resolved semantic transcript record.
4. Support multiple pending items with count/navigation without stacking the composer offscreen.
5. Raise/derive a realistic minimum tile height and responsive compact mode.

### Implementation sketch

```swift
dock.present(pending.sorted(by: LifecycleBlocker.precedence).first, remainingCount: pending.count - 1)
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples parsing, rendering, and agent execution.

## Done when

- Approval cannot disappear under scrollback.
- Resolving one request advances to the next and cannot submit twice.
- Minimum-height tile retains usable transcript and composer.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.
