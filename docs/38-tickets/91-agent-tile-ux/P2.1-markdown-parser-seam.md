# P2.1 — Add the Markdown parser seam and pin swift-markdown

Phase: 2 · Markup parser
Execution: **autonomous**
Depends on: P1.9

## Goal

Adopt a real CommonMark parser behind an owned protocol so provider text gains structure without coupling the document model to a third-party AST.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing. The semantic document—not a view and not a
Markdown-library AST—is the source of truth. Preserve the agent/tile ownership split, light/dark
tokens, keyboard accessibility, and I5. Visible Aqua dropdown or rounded text-field styling is not
acceptable in new tile UI. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

## Approach

1. Add Apple `swift-markdown` at an exact reviewed compatible version.
2. Define an owned parser result containing AgentContent values and parser diagnostics.
3. Convert a plain paragraph first; do not expose `Markdown.Document` outside the adapter.
4. Prove offline matrix behavior after dependency resolution and record license/source.

### Implementation sketch

```swift
public protocol AgentMarkupParsing: Sendable {
    func parse(_ source: String, entryID: AgentNodeID, previous: [AgentBlock]) -> AgentMarkupParse
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples parsing, rendering, and agent execution.
