# P1.12 — iOS consumes the same tokens
Phase: 1 · Depends on: P1.3, P1.8 · Tag: autonomous · Execution-mode: medium

## Goal
Make "build once, render twice" real. Today `StatusChipView` — the shared component we built for
iOS — is **compiled but referenced nowhere**; the phone renders its own `StatusPill` with an
untested contrast path, and its private `AppColors` disagrees with the desktop's surfaces.

## Files
- `ios/Continuum/Sources/ContinuumApp.swift` (`AppColors` ~:2143-2157, `zoneTint` ~:1929, `StatusPill`/`StatusGlyphView` ~:1198-1209)
- `ios/Continuum/Sources/StatusChipView.swift`
- `ios/Continuum/Sources/DesignTokens+SwiftUI.swift` (new: `Color(token:theme:)` bridge)

## Approach
Add a thin SwiftUI bridge resolving `TokenColor` → `Color(.sRGB, …)` (explicit sRGB, per ticket 87
watch-out #1), with theme from the environment `colorScheme`. Delete `AppColors` and `zoneTint`'s
private palettes and route both to tokens. Replace `StatusPill`/`StatusGlyphView` internals with
`StatusChipView` (or have them consume `StatusChipPresenter` directly) so the phone stops carrying a
second status vocabulary — this completes the `colorToken` removal begun in P1.8.

Keep iOS's semantic font styles (`.headline`/`.caption`) — they give real Dynamic Type, which the
desktop lacks. Map `TextRole` → the nearest semantic style rather than forcing fixed sizes onto iOS.

## Done when
`grep -n "AppColors" ios/` returns nothing; `StatusChipView` (or the presenter) is used in shipped
iOS UI; the iOS build leg (P0.1) is green.

## Verify
Matrix green including the iOS build. Token contrast checks (P1.6) already cover the values, and
they are now the values iOS actually renders. Boot the simulator and confirm agent rows show the
same glyph and hue as the desktop sidebar for the same status.

## Watch out
- iOS light mode is real (no `.darkAqua` pin there), so both theme values get exercised immediately —
  this ticket is the first true test of the light palette.
- `xcodegen generate` after adding the new file, or the target won't see it.
- Do not restyle iOS layout here; this is color/status unification only. iOS UX work is Phase 8.
