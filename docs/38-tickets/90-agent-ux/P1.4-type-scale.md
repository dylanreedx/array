# P1.4 — Type scale
Phase: 1 · Depends on: P1.1 · Tag: autonomous · Execution-mode: medium

## Goal
Replace five ad-hoc sizes (10/11/12/13/18, with four different weights at size 12 alone) with
semantic roles. Today size 12 is simultaneously card title, card body, phase label, compose input
and dock header — so "change body text" is a grep-and-pray.

## Files
- `Sources/ContinuumRevivedAgentUI/Typography.swift` (new)
- `Sources/ContinuumRevivedAgentUIChecks/TypographyChecks.swift` (new)

## Approach
```swift
public enum TextRole: String, CaseIterable, Sendable {
    case titleL, title, body, bodyMono, label, caption, captionMono
}
public struct TextStyle: Sendable { public let size: Double; public let weight: TokenWeight; public let monospaced: Bool }
public enum Typography { public static func style(for: TextRole) -> TextStyle }
```
`TokenWeight` is a neutral enum (regular/medium/semibold/bold) mapped to `NSFont.Weight` /
SwiftUI `Font.Weight` in the thin views — no AppKit here.

**Must compose with `ReadabilityPolicy`** (`Sources/ContinuumRevivedCore/ReadabilityPolicy.swift`):
at 0.35× canvas zoom an 11pt label renders ~4px. Expose
`Typography.minimumLegibleSize(atZoom:)` and document which roles are legal below the
`.managedAgent` readability threshold (0.7×).

## Done when
Every role has a style; the agent tile's sizes are expressible as roles (no new size invented at a
call site later).

## Verify
Checks: totality over `TextRole.allCases`; monotonic size ladder (titleL > title > body > label >
caption) with a **minimum step** so the hierarchy is actually visible — today 11→12→13 is a ~1px
step doing almost no work; mono roles report `monospaced == true`.

## Watch out
- Do not adopt into views here (P1.10/P1.11).
- Do not introduce Dynamic Type on macOS in this ticket; desktop uses fixed points today and
  changing that is a separate, larger decision.
