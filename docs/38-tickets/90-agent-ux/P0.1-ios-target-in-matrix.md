# P0.1 — Build the iOS target in the matrix
Phase: 0 · Depends on: none · Tag: autonomous · Execution-mode: low

## Goal
`./scripts/run-matrix.sh` must build the iOS app, not just the macOS package. Tonight a
`Process`-on-iOS break (Core is shared with the phone; `Process` does not exist on iOS) reached
the owner because the matrix never compiled the iOS target. Any future cross-platform break must
turn the matrix red instead.

## Files
- `scripts/run-matrix.sh`

## Approach
Add one leg near the other build legs:
`xcodebuild -project ios/Continuum.xcodeproj -scheme Continuum -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' build`
Use the script's existing `run`/`run_app_check` logging idiom so failures print like every other
leg. Gate on `command -v xcodebuild` so a machine without Xcode skips with an explicit SKIPPED
line (same honesty convention as `CONTINUUM_SKIP_SURFACE_CHECKS`) rather than failing opaquely.

## Done when
- A clean run builds iOS and reports it as a matrix leg.
- Deliberately breaking iOS (e.g. referencing `Process` in a Core file without `#if os(macOS)`)
  makes the matrix exit non-zero.

## Verify
`./scripts/run-matrix.sh` → green, and the output contains the iOS build leg.
Then temporarily add `let _ = Process()` to a Core file, re-run, confirm red, revert.

## Watch out
- `xcodebuild` writes a lot; keep the output captured like the other legs, not streamed raw.
- Do not add `-quiet` in a way that hides the failure reason.
- Do not make this leg conditional on anything other than `xcodebuild` being absent.
