# P6.1 — Per-agent model and effort, in the tile

Phase: 6 · Depends: P2A.3, P0.10

**PULLED FORWARD OUT OF PHASE ORDER at the owner's explicit instruction (2026-07-26).** Same reason
as `P6.0`: the owner reported this on sight. Do it after `P6.0` and before returning to Phase 4.

## Goal

The owner's words, unedited:

> "you can't change the model/effot level wtf happened"

What actually happened is narrower than "it's gone", and the difference decides this ticket's shape:
`AgentModelConfig` (`Sources/ContinuumRevivedCore/AgentModelConfig.swift`, ticket `P0.10`) holds the
full fully-qualified catalogue and both defaults, and `SettingsSchema` already exposes them as
`.choice` fields. So model and thinking level **are** configurable — **globally, in Settings, for
every future agent at once, and nowhere near the agent you are looking at.**

After this ticket the managed-agent tile has a **model control and an effort control for THAT agent**,
seeded from the global default, changeable per agent, persisted with the agent, and applied to its
next turn.

## Why this is real and not a placeholder

`AgentRecord` already declares `public var model: String` and `public var thinking: String` — mutable,
`Codable`, persisted, round-trip-tested by `P2A.1`'s 200-value sweep. And `AgentSupervisor`
constructs its runner as `PiAgentRunner(config: runnerConfig(for: record))` (~line 119), where
`runnerConfig` reads `model: record.model, thinking: record.thinking` (~line 139) — with the comment
already in place explaining that these come from the RECORD because the role decided them.
`PiAgentRunner` then builds `["-p", "--mode", "json", "--model", model, "--thinking", thinking, …]`
per invocation (`PiAgentRunner.swift:61`).

**So a runner is constructed per turn from the record.** Mutating `record.model` before the next
`send` genuinely changes which model answers. This needs **no schema change, no new persistence, and
no Pi RPC**. It is UI plus a supervisor mutator.

**What it CANNOT do, and must therefore say out loud:** change the model *mid-turn*. That requires
Pi's `set_model` / thinking-level RPC calls, which are `P5.4` and `P5.5` over the `--mode rpc`
client `P5.1` builds. `AgentSupervisor.send` already **refuses** a prompt on a busy agent rather than
replacing the in-flight runner (`P2A.3`'s fixed HIGH), so there is no code path where a mid-turn
switch could half-work. The control must communicate "next turn", not pretend.

## Approach

1. **Two `NSPopUpButton`s, options straight from `AgentModelConfig`.** `modelOptions` (7 entries) and
   `thinkingOptions` (7 entries) are the single source shared by `SettingsSchema` and the matrix
   check — read them, never re-type the strings. A hardcoded list here would be a second catalogue
   that drifts from Pi's, which is the exact bug `P0.10` closed (the old hardcoded
   `"openai-codex/gpt-5.6"` fuzzy-matched across three models and the tile silently ran whichever
   Pi picked).

2. **Build the menu by hand, not with `addItem(withTitle:)`.** `P3.8` recorded this trap and paid for
   it: `addItem(withTitle:)` **removes an existing item with the same title**, shifting every tag
   after it. Model ids are distinct so it would probably survive today, but the popup pattern in
   this codebase is a hand-built `NSMenu` with an explicit tag range, and `P3.14` reused it. Match
   that.

3. **`menu.autoenablesItems = false`.** Both `P3.12` and `P3.14` wrote this down as load-bearing and
   `P3.14` measured it red: with AppKit's default, `NSMenu.update()` re-derives enablement just
   before the menu draws and a deliberately-disabled item comes back live. If you disable anything
   here (see 5), this line is what makes it stick.

4. **Where they go.** Put them in the compose area, not the header: they are about the prompt you are
   about to send. **The compose row's height is pinned** —
   `composeRow.heightAnchor.constraint(equalToConstant: Metrics.rowHeight(for: .body, insets: Inset.card))`
   (~line 366). Two popups will not fit that height, and `P3.11` recorded exactly this failure mode
   on its bulk bar: an `NSPopUpButton` spilled its parent vertically
   (`frame y 17.0…41.0 outside parent 0…40.0`) and the geometry gate caught it. Derive the new height
   from the controls' own metrics — `Metrics.rowHeight(for:insets:)`, as the existing constraint
   does — **never a literal**. `P3.8` did the same for `scopeControlHeight` and the reason is
   recorded there: a literal makes the committed PNGs depend on the host's font metrics.

5. **Disable during a turn, and say why.** While a turn is in flight the tile already latches
   `promptInFlight` and disables compose (`applyComposeAvailability()`, called at ~96/206/238/281).
   Route the two popups through that SAME method — do not add a second notion of "busy". A change
   picked mid-turn cannot apply until Phase 5, and a control that silently does nothing is worse
   than one that is visibly unavailable.

6. **Label the effect honestly.** The controls apply to the **next** turn. Use the placeholder or a
   `.token(.caption)` line to say so if it fits; if it does not fit, prefer no claim to a wrong one.
   Do not write "applies immediately".

7. **The supervisor mutator.** One method: given an `AgentID`, set `model` and/or `thinking` on the
   record and persist it. Reuse the existing persistence path — `P2A.3` established that writes go
   through `AtomicWriter` (temp + fsync + read-back) on **lifecycle events only**, deliberately not
   per token, because an fsync per `contentDelta` would land on the main thread. A user picking a
   model is a discrete user action, so persisting it immediately is correct and is not the thing that
   rule was guarding against.

8. **Seed from the global default, then stop consulting it.** A new agent's record already gets
   `AgentModelConfig`'s resolution at spawn. Once an agent has a per-agent value, changing the global
   Settings default must NOT retroactively move it — the record is the truth. Assert this; it is the
   whole meaning of "per-agent".

## Done when

- The managed-agent tile shows the current agent's model and thinking level, seeded from its record.
- Changing either updates `AgentRecord` and survives a relaunch (`P2A.7` restores records).
- The **next** turn spawns Pi with the chosen `--model` / `--thinking`.
- Both controls are unavailable while a turn is in flight, via `applyComposeAvailability()`.
- Two agents can hold different models at the same time.
- Changing the global Settings default does not move an existing agent's values.
- Full matrix green, no floor lowered, no check loosened.

## Watch out

- **Thinking level is `--thinking`, and `"off"` is a legal value.** `thinkingOptions` is
  `["off","minimal","low","medium","high","xhigh","max"]`. Do not filter `"off"` out as if it were a
  null; Pi accepts it.
- **Never offer a bare `gpt-5.6`.** Every id must stay fully qualified `provider/model-id` exactly as
  `modelOptions` spells it. `--model` takes a *pattern*, so a shortened string fuzzy-matches — the
  bug `P0.10` exists to prevent.
- **A role may have decided the model.** `RoleRegistry` resolves a role's model/reasoning, and
  `spawn` writes those onto the record; a child inherits its parent's values unless its role declares
  otherwise (`AgentSupervisor` ~line 523/534). A user override is legitimate and lands on the record
  the same way — but if you find that a role re-resolution would clobber a user's pick on some path,
  **report it, do not silently pick a winner.** Which of a user's choice and a role's declaration
  wins is the owner's call, and `_RUNBOOK.md`'s locked decisions do not cover it.
- **Do not touch `runnerConfig(for:)`'s reading of the record, the `PiAgentRunner` construction site,
  or `PiAgentRunner` itself.** The supervisor is the only place in the app that constructs a runner
  and a source-scan assertion enforces it (`P2A.3`). Phase 5 replaces the runner wholesale.
- **Do not build the `/model` command, the `$` skills menu, the `@` path menu, or an `NSTextView`
  compose.** Those are `P6.2`–`P6.9` and are still in phase order behind Phase 4/5.
- Do not touch the transcript views — that is `P6.0`.
