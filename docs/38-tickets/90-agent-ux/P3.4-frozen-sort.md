# P3.4 — Frozen creation-order sort
Phase: 3 · Depends on: P3.1 · Tag: autonomous · Execution-mode: medium

## Goal
**Locked decision:** rows hold their position from spawn until a lifecycle transition. Activity NEVER
reorders the list, so the screen only moves when you act. This matters doubly in a canvas app where
position is the user's index — and it is the opposite of what `AgentsBoardProjection` does today
(attention-first), which iOS keeps.

## Files
- `Sources/ContinuumRevivedAgentUI/InboxSort.swift` (new)
- `Sources/ContinuumRevivedAgentUIChecks/InboxSortChecks.swift` (new)

## Approach
`sortForInbox(rows:) -> [AgentInboxRow]`: newest-created first, stable, with children immediately
after their parent (P2D.4). Settled rows sort separately by when work *ended* (they are history).
Leave `AgentsBoardProjection.rows(from:)` attention-first for iOS — do not change it; add this as the
desktop's sort so the two surfaces can differ deliberately.

## Done when
Two sorts coexist: frozen (desktop) and attention-first (iOS glance).

## Verify
**The load-bearing check:** take a row list, apply a stream of status changes in random orders, and
assert the *sequence of ids* is identical every time and equal to creation order. Regression witness:
sorting by status must FAIL this check.

## Watch out
- "Frozen" is about *activity* not moving rows. A lifecycle transition (settle/snooze) DOES move a
  row — that is intended and must be asserted separately.
- Do not use `updatedAt` anywhere in this comparator; that is how lists start jumping.
