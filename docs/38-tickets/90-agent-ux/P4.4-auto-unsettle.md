# P4.4 — Auto-unsettle on real activity
Phase: 4 · Depends on: P4.2 · Tag: autonomous · Execution-mode: medium

## Goal
An override must never go stale silently. If a settled agent genuinely starts working again, it comes
back on its own.

## Files
- `Sources/ContinuumRevived/App/AgentSupervisor.swift`
- `Sources/ContinuumRevivedAgentUI/AgentLifecycle.swift`

## Approach
On **real activity** — a user message, a session coming alive, a new approval/input request — clear
`settledOverride` back to `.neutral` and stamp `lastActivityAt`. Deliberately NOT triggered by: a
status poll, an observer refresh, or the user merely viewing the row (reading is free, P4.9).

Only the app may clear an override for `reason: activity`; a user action is a separate explicit path.
Record which reason cleared it so the ledger/debugging can tell them apart.

## Done when
Sending a prompt to a settled agent un-settles it; a status refresh does not.

## Verify
Checks: activity event → `.neutral`; observer-only refresh → override unchanged (**regression witness**:
un-settling on a mere refresh must FAIL); viewing → unchanged.

## Watch out
- Do not un-settle on `sessionStateChanged(.ready)` alone — an agent settling into ready *is* the
  normal end of work and would immediately undo every settle.
