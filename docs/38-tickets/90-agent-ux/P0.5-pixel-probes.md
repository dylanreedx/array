# P0.5 — Numeric pixel probes
Phase: 0 · Depends on: P0.2, P0.3 · Tag: autonomous · Execution-mode: medium

## Goal
Catch "the model says it's fine but the render is wrong" — the case where a dynamic color resolved
badly at draw time. Reads pixels, but asserts thresholds, never judgment.

## Files
- `Sources/ContinuumRevived/App/UIProbePixels.swift` (new)
- reuse `VisualSnapshot.metrics(of:)` in `Sources/ContinuumRevived/App/VisualSnapshot.swift`

## Approach
Two probes over the `UIProbe` bitmap, both scoped to a view's frame converted to bitmap coords:
- `expectLegibleText(in: label)` — sample the label's rect; assert the luminance **spread**
  (max−min) exceeds a threshold. Invisible text produces a flat rect.
- `expectVisibleBorder(of: view)` — sample a short line crossing the border edge; assert a minimum
  luminance delta between inside and the border band.

Thresholds live as named constants with a comment explaining the derivation; do not scatter magic
numbers.

## Done when
Both probes exist and run over transcript cards + tile chrome in both appearances.

## Verify
`--ui-probe-check` extended. Regression witnesses that must FAIL:
- Set a label's `textColor` equal to its background → `expectLegibleText` fails.
- Set border color equal to the fill → `expectVisibleBorder` fails.

## Watch out
- Coordinate flipping: `NSBitmapImageRep` origin vs a flipped view. Convert explicitly and add a
  check that the sampled rect actually lands on the label (sample a known-colored fixture first).
- Anti-aliasing means the exact border pixel varies — sample a band, not one pixel.
- Retina backing scale: `bitmapImageRepForCachingDisplay` may be 2x. Scale the rect.
