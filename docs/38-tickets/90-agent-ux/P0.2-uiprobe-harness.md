# P0.2 — UIProbe: instantiate a component at a known size/appearance/state
Phase: 0 · Depends on: none · Tag: autonomous · Execution-mode: medium

## Goal
One harness that builds a real view at an explicit size, in an explicit `NSAppearance`, with an
explicit fixture state, and hands it back for numeric interrogation. Every later gate (P0.3–P0.6)
is a thin layer on this. Today's Component Lab check renders at a default size in whatever
appearance the process happens to resolve — which is why "vision QA passed" meant nothing.

## Files
- `Sources/ContinuumRevived/App/UIProbe.swift` (new)
- `Sources/ContinuumRevived/App/ComponentLab.swift` (reuse `LabCatalog.entries`, `place(_:in:preferredSize:)`)

## Approach
```swift
struct UIProbe {
    struct Spec { var id: String; var size: NSSize; var appearance: NSAppearanceName }
    static func render(_ spec: Spec, make: () -> NSView) -> Probed  // view + NSBitmapImageRep
}
```
Host the view in a borderless `NSWindow` exactly as `runComponentLabCheck` already does (that is
the pattern that produces a usable `bitmapImageRepForCachingDisplay`). **Set
`window.appearance = NSAppearance(named: spec.appearance)` before layout**, and wrap the
render in `appearance.performAsCurrentDrawingAppearance { }` so dynamic colors and
`.cgColor` conversions resolve in the intended appearance. Return both the live view tree (for
geometry/contrast assertions) and the bitmap (for pixel probes).

## Done when
- `UIProbe.render` returns a laid-out view whose `effectiveAppearance` matches the requested one.
- Rendering the same component in `.aqua` vs `.darkAqua` produces **different** bitmaps.

## Verify
New `runUIProbeChecks()` in the app-check family, added to `scripts/run-matrix.sh` as
`--ui-probe-check`: assert effectiveAppearance matches, assert size matches, and assert the two
appearances differ (MD5/pixel inequality). That last assertion is the regression witness for the
bug where all three of my "different appearance" renders came back byte-identical.

## Watch out
- `NSApp.appearance` is pinned to `.darkAqua` at launch (`ContinuumApp.swift`), so a probe MUST
  set appearance on its own window/view or it will silently inherit dark and the light pass will
  be fake.
- `NSColor.cgColor` resolves against `NSAppearance.current`, not the view — that is exactly
  tonight's white-on-white bug. Use the `performAsCurrentDrawingAppearance` wrapper.
- Keep it AppKit-only (this file is macOS app code, not Core).
