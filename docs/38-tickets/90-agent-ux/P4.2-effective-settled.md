# P4.2 — effectiveSettled: blockers outrank user intent
Phase: 4 · Depends on: P4.1 · Tag: autonomous · Execution-mode: high

## Goal
**The load-bearing rule of the whole inbox.** Work that needs a human must stay visible even when the
human said "done". Without this, an agent can be settled and then silently start waiting on an
approval nobody ever sees.

## Files
- `Sources/ContinuumRevivedAgentUI/AgentLifecycle.swift`
- `Sources/ContinuumRevivedAgentUIChecks/AgentLifecycleChecks.swift`

## Approach
One pure function, resolved in this precedence order:
1. **Blockers force `.active`** — pending approval, pending user input, a starting/running session, or
   a queued turn. This beats *everything*, including `settledOverride == .settled`.
2. `settledOverride == .settled` → `.settled`
3. `settledOverride == .active` → `.active` (the pin; suppresses auto-settle)
4. inactivity past `autoSettleAfterDays` (P4.3) → `.settled`
5. otherwise `.active`

Snooze composes as an overlay, not a fourth destination: a snoozed agent is hidden in the shelf unless
a blocker or a raised hand (P4.6) pulls it back.

## Done when
The function is total, pure, and blocker-precedence is proven.

## Verify
This is where the ~30-case matrix lives (P4.13 extends it): every combination of
{override × blocker × snooze × inactivity} → expected lifecycle. **Named witnesses that must FAIL if
precedence inverts:** an agent with `.settled` + pending approval MUST resolve `.active`; a `.settled`
agent with a *running* session MUST resolve `.active`.

## Watch out
- Purity: no `Date()` inside — take `now` as a parameter or the checks cannot pin behaviour.
- Do not conflate `archived` with settled in this function; archived agents are out of the list entirely.
