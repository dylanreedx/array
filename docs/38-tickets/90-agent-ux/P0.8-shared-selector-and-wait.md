# P0.8 — Shared element lookup + a non-blocking `waitUntil`
Phase: 0 · Depends on: none · Tag: autonomous · Execution-mode: medium

## Goal
Every app-driving check hand-rolls its own polling loop, and at least one (the managed-agent live
check I wrote tonight) blocked the main thread with a `RunLoop` spin — which starved the very
main-queue ingests it was waiting for and produced a false failure. Also
`descendant(withIdentifier:)` — the closest thing to a CSS selector — is trapped inside
ComponentLab.

## Files
- `Sources/ContinuumRevived/App/UITestSupport.swift` (new)
- `Sources/ContinuumRevived/App/ComponentLab.swift` (move `descendant(withIdentifier:)` out, ~:2442)

## Approach
- Move `descendant(withIdentifier:)` into the shared file as an `NSView` extension; add
  `descendants(withPrefix:)` for row collections.
- Add `waitUntil(timeout:_ condition:) async -> Bool` that **does not block the main thread**:
  poll via `DispatchQueue.main.asyncAfter` re-scheduling (the pattern that finally worked in
  `runManagedAgentLiveCheck`), or an async continuation. Document at the call site why a
  `RunLoop.current.run(...)` spin is wrong here.
- Migrate the existing managed-agent live check to the shared helper as the first consumer.

## Done when
The helper exists, ComponentLab uses it, and the managed-agent live check uses it with no
behaviour change (still passes).

## Verify
`./scripts/run-matrix.sh` green, including `--managed-agent-live-check` (needs Pi auth + network;
if unavailable it must SKIP explicitly, not silently pass).

## Watch out
- Do not convert other checks in this ticket. One migration proves the helper; the rest is churn.
- The helper must be usable from `@MainActor` contexts without `assumeIsolated` gymnastics at every
  call site.
