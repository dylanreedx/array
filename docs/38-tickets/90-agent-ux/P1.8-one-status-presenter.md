# P1.8 — Collapse six color maps and three glyph maps onto one presenter
Phase: 1 · Depends on: P1.3 · Tag: autonomous · Execution-mode: high

## Goal
`AgentStatus` → appearance is currently mapped in **six** places with **three** disagreeing glyph
sets, and the intended single source (`StatusChipPresenter`) has **zero** production consumers.
Observable consequences: `configuring` renders purple in the tile, teal on the board, and
invisible-grey in the sidebar; `◌` means *stale* in the sidebar but *configuring* in the tile.

## Files
Single source: `Sources/ContinuumRevivedAgentUI/StatusChip.swift` (`StatusChipPresenter`).
Delete/redirect these:
- `Sources/ContinuumRevivedCore/AgentsBoardProjection.swift` (`presentation(for:)`, colorToken strings, ~:93-107)
- `Sources/ContinuumRevived/Canvas/ManagedAgentTileNSView.swift` (`color(for:)` ~:322, `glyph(for:)` ~:300, `phase(for:)`)
- `Sources/ContinuumRevived/Canvas/TileNSView.swift` (`color(for:)` ~:905)
- `Sources/ContinuumRevived/App/ComponentLab.swift` (`color(for:)` ~:942, `color(forToken:)` ~:953)
- `Sources/ContinuumRevived/App/WorkspaceSidebarView.swift` (`color(for:)` ~:594, glyph ~:588)
- `ios/Continuum/Sources/ContinuumApp.swift` (`AppColors.color(for:)` ~:2147)

## Approach
Extend `StatusChipDisplay` to carry what all six callers need: `label`, `glyph`, `foreground`,
`background`, plus an `accent` (for a glyph-on-dark caller that does not want a filled pill). Then
delete each duplicate and route its caller to the presenter. Keep the exhaustive `switch` with no
`default:` so adding a status stays a compile error.

`AgentsBoardProjection`'s stringly-typed `colorToken` channel is how `configuring` became
purple-and-teal — it must not survive. It is consumed by iOS and the Lab; migrate both. If iOS
cannot be migrated in this ticket, mark the iOS half for P1.12 and leave a `// TODO(P1.12)` — but
the desktop duplicates must all go here.

## Done when
`grep -rn "case .needsAttention" Sources/ ios/` shows exactly one status→appearance mapping outside
tests/fixtures, and the sidebar/tile/board agree on glyph and hue for every status.

## Verify
Existing StatusChip checks still pass. New check: for every `AgentStatus`, the presenter's glyph and
background `hexKey` are identical to what each migrated call site now renders (assert via the
presenter, and assert the old helpers no longer exist by grep in the color-hygiene gate from P1.7).
Component Lab baselines (P0.6) will show the intended visual change — bless them deliberately and
say so in the commit body.

## Watch out
- **This is a real visual change**, not a mechanical swap: the duplicates use the status color as
  *foreground glyph on a dark fill*, while the presenter uses a *pastel background with dark
  foreground*. Decide per call site which shape it needs and use `accent` vs the pill accordingly.
- `SidebarAgentStatusKind` collapses `configuring`/`idle` into `.unknown` → don't silently change
  sidebar semantics while unifying color; if the mapping must change, note it.
