# P4.13 — The precedence matrix check
Phase: 4 · Depends on: P4.2, P4.3, P4.4, P4.6, P2D.5 · Tag: autonomous · Execution-mode: medium

## Goal
Lifecycle bugs are invisible until they hide work from a human. Pin every rule in one exhaustive,
readable table so a future change that inverts precedence fails loudly.

## Files
- `Sources/ContinuumRevivedAgentUIChecks/AgentLifecycleChecks.swift`

## Approach
A single table-driven check over the cross-product of: `settledOverride` {settled, active, neutral} ×
blocker {none, approval, input, running, queuedTurn} × snooze {none, future, elapsed} × inactivity
{fresh, stale} → expected `InboxLifecycle`. Roughly 90 combinations; write it as data with a one-line
expectation each, not as 90 hand-written assertions.

Include the **parent/child rule from P2D.5**: a parent is not settleable while any child is blocked or
running, even with `settledOverride == .settled`.

## Done when
The table covers every combination and passes, and each of these witnesses FAILS when its rule is
removed: blocker-beats-settle · `.active` pin suppresses auto-settle · activity clears an override ·
a pre-snooze failure does not wake · parent-blocked-by-child.

## Verify
`./scripts/run-matrix.sh`. Print a compact pass table so the rules are reviewable in the log.

## Watch out
- Keep it pure: inject `now` and a fixed `Calendar`.
- If a combination is genuinely undefined, that is a design gap — decide it and document it in the
  table rather than omitting the row.
