# P5.8 — Token, cost, and context meter
Phase: 5 · Depends on: P5.2 · Tag: autonomous · Execution-mode: medium

## Goal
Show what an agent actually costs. **No competitor does this** — T3 and Conductor removed cost
(Conductor's was "not accurate enough"), Happy is account-level only, Nyx has none. Pi hands us exact
numbers per message, so it is nearly free for us.

## Files
- `Sources/ContinuumRevivedCore/AgentProviders/PiEventTranslator.swift` (usage already on the wire)
- `Sources/ContinuumRevived/Canvas/ManagedAgentTileNSView.swift` (header meter)
- `Sources/ContinuumRevivedAgentUI/ContextMeter.swift` (new, pure)

## Approach
Every assistant message carries `usage` + precomputed `cost` (input/output/cacheRead/cacheWrite/total).
Sum per turn and per session; `get_session_stats` gives the aggregate plus
`contextUsage.{tokens,contextWindow,percent}`. Render a compact context ring/bar + a cost figure in the
tile header. Keep the arithmetic in a pure `ContextMeter` so it is checkable.

## Done when
The tile shows session cost and context usage, updating as turns complete.

## Verify
**Deterministic:** pure checks over a committed fixture of real `usage` payloads (one is already captured
in a local session JSONL): summation matches, percent is clamped 0…1, a missing `cost` degrades to
tokens-only rather than showing $0.00 (witness — displaying a confident zero is worse than omitting).
**Manual:** compare the displayed session cost against `get_session_stats` on a live agent.

## Watch out
- `ToolResultMessage.usage` captures nested LLM work inside tools; include it or the number is low.
- **I5:** cost/token numbers are derived aggregates and safe to sync later, but note that the taint
  scanner flags any integer in 2…4_194_304 as pid-shaped — a `tokens: 4210` field would fail. If these
  are ever published, encode as Double or allowlist explicitly with justification.
