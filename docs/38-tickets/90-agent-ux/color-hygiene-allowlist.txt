# P1.12 deleted `AppColors` — its two dark-only literals were iOS's whole
# raw-colour debt, and they are now `SurfaceToken.canvas` / `SurfaceToken.panel`.
# With them gone, ios/Continuum/Sources no longer paints a hardcoded fill at all,
# so rule 2's trap (an Apple semantic colour resolved against a literal fill) can
# no longer be sprung there and its four iOS entries went stale with it. Six
# entries removed, none added: `.primary`/`.secondary` in that file now sit on
# token surfaces that carry both appearances, which is what made them a trap in
# the first place. Rules 4 and 5 (theme resolution, zone-tint parity) took over
# the iOS-specific coverage; neither has an allowlist.
#
# That the four semantic entries are EXCUSED BY THE FILE'S STATE and not by this
# list is mechanical, not an argument: re-adding a single raw literal
# (`private let panelLiteral = Color(red: 0.10, green: 0.11, blue: 0.14)`) re-arms
# rule 2 across the whole file and turns all four back into named violations —
# observed at exit 1 on 6 lines of `.foregroundStyle(.primary)`, 24 of
# `.foregroundStyle(.secondary)`, plus `return .secondary` and the ternary. So the
# coverage did not move to this list's honour system; it moved to the absence of a
# literal fill, which the gate re-checks every run.
