# P1.9 — Live appearance switching
Phase: 1 · Depends on: P1.3 · Tag: autonomous · Execution-mode: medium

## Goal
Make the app respond to an appearance change at runtime. `layer?.backgroundColor = someColor.cgColor`
**snapshots** the value at init: `NSColor.cgColor` resolves against `NSAppearance.current` (the
system appearance outside a draw cycle), not the view's. That is exactly the bug that shipped
tonight — pinning `.darkAqua` turned text white while every CALayer fill stayed light, producing
white-on-white chrome. It was fixed pointwise with `appResolvedCGColor`; tokens must make it
systematic.

## Files
- `Sources/ContinuumRevived/App/AppearanceSupport.swift` (extend; `appResolvedCGColor` lives here)
- `Sources/ContinuumRevived/Canvas/ManagedAgentTileNSView.swift`, `Canvas/TranscriptCardViews.swift`,
  `Canvas/TileNSView.swift`, `App/WorkspaceSidebarView.swift`, `App/WorkspaceTopBarView.swift`

## Approach
Give token-consuming views a single `applyTokens()` that assigns every layer color from the resolved
token, and call it from both `init` and `override func viewDidChangeEffectiveAppearance()`. Add a
tiny protocol (e.g. `TokenThemed { func applyTokens() }`) so the pattern is uniform and greppable.
Resolve `TokenTheme` from `effectiveAppearance.bestMatch(from: [.aqua, .darkAqua])` in the app layer
— the AgentUI module stays platform-free.

Note: `NSApp.appearance` is currently pinned to `.darkAqua` at launch. Leave that pin in place in
this ticket (removing it is the light-theme rollout, and only safe once P1.10–P1.12 have adopted
tokens everywhere). The point here is that switching **works** when the pin is lifted.

## Done when
Toggling the probe's appearance re-resolves every layer color; no view retains a stale CGColor.

## Verify
`--ui-probe-check` extension: render a token-consuming view, flip the appearance, re-probe, and
assert the layer background actually changed. Regression witness: assign a raw `.cgColor` (bypassing
`appResolvedCGColor`) and confirm the assertion FAILS.

## Watch out
- `viewDidChangeEffectiveAppearance` fires on the view *and* descendants — make `applyTokens()`
  idempotent and cheap; do not rebuild view trees in it.
- Do not remove the `.darkAqua` pin in this ticket. That is a deliberate, separate rollout step.
