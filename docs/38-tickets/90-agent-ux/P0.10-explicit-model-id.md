# P0.10 — Explicit Pi model id
Phase: 0 · Depends on: none · Tag: autonomous · Execution-mode: low

## Goal
`PiAgentRunner.Config.model` defaults to `"openai-codex/gpt-5.6"`, but **there is no bare
`gpt-5.6`**. `pi --list-models` offers `gpt-5.6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra` (plus 5.4/5.5
variants). Our string has been resolving by Pi's fuzzy matcher across three candidates — silently
non-deterministic. Pi's own default is `gpt-5.6-sol`.

## Files
- `Sources/ContinuumRevivedCore/AgentProviders/PiAgentRunner.swift`
- `Sources/ContinuumRevivedCore/AgentModelConfig.swift` (new, follow the `FocusBorderConfig` shape)
- `Sources/ContinuumRevivedCore/SettingsSchema.swift` (agents section, ~:206)
- `Sources/ContinuumRevivedCoreChecks/` (new check)

## Approach
Add `AgentModelConfig` in the established `*Config` pattern: `modelKey`/`defaultModel`
(`"openai-codex/gpt-5.6-sol"`), `thinkingKey`/`defaultThinking` (`"medium"`), a shared
`modelOptions` / `thinkingOptions` list, and `resolvedFromDefaults(defaults:)` with validation.
Bind them via two `SettingsField.choice` entries in the existing `agents` section — no renderer
changes needed. `PiAgentRunner.Config.model` defaults from the resolver.

## Done when
No literal `"openai-codex/gpt-5.6"` remains in Sources; the model comes from config; Settings shows
model + reasoning-effort pickers under Agents.

## Verify
New Core check: assert the default model is a fully-qualified id (not a prefix of several
catalogue ids), assert every `modelOptions` entry is fully qualified, and assert
`thinkingOptions ⊆ {off,minimal,low,medium,high,xhigh,max}`. Plus the existing settings-schema
checks (unique keys, round-trip) pick the new fields up for free.
Manual cross-reference: `pi --list-models` lists the default id verbatim.

## Watch out
- Only `openai-codex` is authed on this machine (oauth, valid to 2026-07-30). Do not add options
  for providers with no credentials — `--list-models` only shows usable ones.
- This is a behaviour change: `-sol` may differ from whatever fuzzy match resolved before. Note it
  in the commit body.
