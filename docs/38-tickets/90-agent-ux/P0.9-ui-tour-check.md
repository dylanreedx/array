# P0.9 — `--ui-tour-check`: labeled screenshots for human review
Phase: 0 · Depends on: P0.2 · Tag: autonomous · Execution-mode: medium

## Goal
Produce a contact sheet the supervising human (or model) can scan in under a minute. **Advisory
only — it never gates.** Its real job is to make every render self-describing, because the worst
QA failure tonight was judging a 460pt fixture in an unknown appearance and calling it clean.

## Files
- `Sources/ContinuumRevived/App/UITourCheck.swift` (new)
- `scripts/run-matrix.sh` (add the flag; must NOT fail the matrix on visual grounds)

## Approach
Drive the key surfaces via `UIProbe` across a matrix of {size} × {appearance} × {state} and write
`qa-runs/<ts>/tour/<surface>-<state>-<size>-<appearance>.png`, plus `index.md` listing every image
with its parameters. Start with: managed-agent tile (ready / working / with-approval / long
transcript), transcript cards (each kind), status chips (all states), sidebar, settings.
Sizes: 320 (minimum), 640, 900. Appearances: both.

Filenames carry the parameters so a reviewer can never mistake what they are looking at.

## Done when
One command produces the tree + `index.md`, and the flag exits 0 even when something looks wrong
(it is not a gate).

## Verify
`.build/debug/continuum-revived --ui-tour-check` → tree written, `index.md` lists every file with
size + appearance. Confirm the light and dark variants of the same surface differ.

## Watch out
- Do **not** wire this as a blocking matrix leg. If it fails the build on aesthetics, workers will
  start "fixing" screenshots.
- Keep total images bounded (~40). A hundred images is not scannable, which defeats the purpose.
- Include the long-transcript state — the scroll/overflow cases are where layout actually breaks.
