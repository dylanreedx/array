# P3.2 — Five states, three colours
Phase: 3 · Depends on: P3.1, P1.8 · Tag: autonomous · Execution-mode: medium

## Goal
Reserve colour for meaning. T3 Code's shipped model: colour marks only **act now**, **in motion**,
and **broken**; the resting state is deliberately unlabelled.

## Files
- `Sources/ContinuumRevivedAgentUI/AgentInboxRow.swift`
- `Sources/ContinuumRevivedAgentUI/DesignTokens.swift` (accents from P1.3)

## Approach
```swift
public enum InboxState: String, CaseIterable, Sendable {
    case working      // sky   — in motion, shows live duration
    case approval     // amber — act now
    case input        // indigo— act now
    case failed       // red   — broken
    case ready        // NO label, NO colour: the resting state
}
```
Map from `AgentStatus` + pending-approval/input facts. `ready` covers "the agent stopped and is
waiting on you" whatever the reason (finished, asked, proposed a plan) — **it is not an error state
and must not be coloured**. Label priority when several could apply:
`working → approval → input → failed → (woke) → (done) → relative timestamp`.

## Done when
Every agent resolves to exactly one state, and `ready` renders with no accent.

## Verify
Checks: exhaustive mapping with no `default:`; a pending approval outranks `working`; `ready`
resolves to a nil accent token (regression witness: giving `ready` a colour must FAIL the check).

## Watch out
- Do not add a sixth state. If something needs surfacing, it is probably *attention* (P3.3), not state.
- Colours come from tokens (P1.3) so they are contrast-gated; do not hardcode hues here.
