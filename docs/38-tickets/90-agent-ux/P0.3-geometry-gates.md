# P0.3 — Geometry gates
Phase: 0 · Depends on: P0.2 · Tag: autonomous · Execution-mode: medium

## Goal
Catch layout bugs with numbers instead of eyes. Tonight's half-width transcript (cards sized to
the longest line and centred, scroller stranded mid-tile) and blank transcript (cards never laid
out) both passed every existing gate.

## Files
- `Sources/ContinuumRevived/App/UIProbeGeometry.swift` (new)
- `scripts/run-matrix.sh`

## Approach
Assertions over a `UIProbe`-rendered tree:
- `fills(child:parent:minRatio:)` — e.g. transcript cards must span ≥0.9 of the tile width.
- `expectNoZeroSizeViews(root)` — every arranged subview has width>0 && height>0.
- `expectCount(stack.arrangedSubviews.count == expected)` — card/row parity with the model.
- `expectNoAmbiguousLayout(root)` — recursive `!view.hasAmbiguousLayout`. **AppKit reports the
  exact class of bug I shipped** (a vertical stack row with no width pin) for free.
- `expectScrolledToBottom(scrollView)` — clip offset == max after ingest.
- A **narrow-width pass**: render at 320pt (`TileGeometry` tile minimum) and assert no clipping
  and no unsatisfiable constraints.

## Done when
Gates exist and run over the managed-agent tile at 320pt, 640pt and 900pt in both appearances.

## Verify
`--ui-probe-check` extended. Regression witnesses (must FAIL if reintroduced):
1. Remove the four width pins added in `ManagedAgentTileNSView.makeContentView()` → the
   fills-parent assertion must fail.
2. Point `reconcileCards` at an empty array → the count-parity assertion must fail.
Add both as commented-out witness snippets in the check file so the next reader can re-run them.

## Watch out
- `hasAmbiguousLayout` needs a laid-out tree — call `layoutSubtreeIfNeeded()` first.
- Some ambiguity is benign in NSStackView spacer views; if a false positive appears, scope the
  walk to identified views rather than weakening the assertion.
- Do not assert exact pixel frames — they vary with font metrics. Assert ratios and invariants.
