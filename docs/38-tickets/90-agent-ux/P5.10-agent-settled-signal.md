# P5.10 — Adopt `agent_settled` as the true idle signal
Phase: 5 · Depends on: P5.2 · Tag: autonomous · Execution-mode: low

## Goal
"The turn is really over" is currently inferred from `turnCompleted`, which is wrong when a retry,
compaction, or a queued follow-up is still pending. `agent_settled` is the signal that accounts for all
three — and correct idleness drives the inbox's state, the fade, and auto-settle.

## Files
- `Sources/ContinuumRevivedCore/AgentProviders/PiEventTranslator.swift`
- `Sources/ContinuumRevived/App/AgentSupervisor.swift`

## Approach
Map `agent_settled` → `sessionStateChanged(.ready)` and treat *that*, not `turn_end`, as the transition
out of `working`. **Verify empirically first:** `agent_settled` is documented in rpc.md's event table but
is NOT in json.md's event union, so confirm what the running Pi actually emits in rpc mode before relying
on it, and record the finding in the packet's ledger note.

If it turns out unreliable, fall back to `turnCompleted` **plus** an empty queue and no pending retry —
and say so rather than pretending the signal exists.

## Done when
An agent leaves `working` only when genuinely idle, including after a retry or a queued follow-up.

## Verify
**Deterministic:** fixture stream where `turn_end` is followed by a retry and then `agent_settled` —
assert the agent stays `working` until settled (witness: going idle at `turn_end` must FAIL).
**Manual:** confirm against a live rpc session that `agent_settled` is emitted, and capture the transcript
as the fixture.

## Watch out
- This changes when the compose row re-enables and when auto-settle's inactivity clock starts. Check both.
- Do not remove `turnCompleted` handling — per-turn cards still key off it.
