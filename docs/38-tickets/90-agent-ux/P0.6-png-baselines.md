# P0.6 — Committed PNG baselines + tolerant compare
Phase: 0 · Depends on: P0.2 · Tag: autonomous · Execution-mode: medium

## Goal
Catch regressions nobody thought to assert. Today every component PNG is written to a fresh
`qa-runs/<timestamp>/` directory and compared to nothing, ever — so a component can regress its
entire layout and stay green.

## Files
- `docs/38-tickets/90-agent-ux/baselines/` (new, committed PNGs)
- `Sources/ContinuumRevived/App/UIProbeBaseline.swift` (new)
- `scripts/run-matrix.sh`

## Approach
Baseline name: `<entry.id>-<size>-<appearance>.png`. Compare current render to the committed
baseline: count pixels whose per-channel delta exceeds a small epsilon; fail if the differing
fraction exceeds ~0.1% (anti-aliasing and font rendering drift a little). On failure, write
`actual` + a `diff` image next to the run artifacts and name both in the error so a human can look.

Blessing a change is explicit: `CONTINUUM_UPDATE_BASELINES=1 ./scripts/run-matrix.sh` rewrites
baselines. It must NEVER update them implicitly.

## Done when
Baselines exist for every static Lab entry in both appearances, and an intentional visual change
fails until blessed.

## Verify
`--ui-baseline-check` in the matrix. Change a card's corner radius → red; re-run with
`CONTINUUM_UPDATE_BASELINES=1` → the baseline diff appears in `git status`.

## Watch out
- **Do not bless baselines to make the matrix green.** If a baseline changed unexpectedly, that is
  the finding. A worker updating baselines to pass is exactly the fake-green this program forbids.
- Keep PNGs small (bounded component sizes) so the repo doesn't bloat.
- Font rendering can differ across macOS versions; if that bites, raise the tolerance once, with a
  comment, rather than per-test.
