# P0.4 — Per-appearance contrast gate, read off the real view tree
Phase: 0 · Depends on: P0.2 · Tag: autonomous · Execution-mode: medium

## Goal
Fail the build when text or a border is unreadable, **in either appearance**. The owner's Mac
resolves light appearance; every custom surface is a hardcoded dark fill; every text color was a
dynamic semantic color that resolves to BLACK in light. Measured: `labelColor` = black@85% in
Aqua, white@85% in DarkAqua. That shipped for weeks.

## Files
- `Sources/ContinuumRevived/App/UIProbeContrast.swift` (new)
- `scripts/run-matrix.sh`
- reuse `WCAGContrast` from `Sources/ContinuumRevivedCore/AgentUI/StatusChip.swift`

## Approach
Walk the probed view tree. For every `NSTextField`/`NSTextView`, resolve its `textColor` and the
**effective background behind it** (nearest ancestor with an opaque `layer.backgroundColor`,
composited if alpha < 1) *inside* `appearance.performAsCurrentDrawingAppearance { }`, convert both
`usingColorSpace(.sRGB)`, then assert `WCAGContrast.ratio >= 4.5`. Borders/glyph-only views
assert `>= 3.0`. Run the whole component set in **both** `.aqua` and `.darkAqua`.

Critically: read colors **from the view tree, not from a token table**, so a view that bypasses
the design tokens still fails.

## Done when
Every Component Lab entry passes ≥4.5:1 text / ≥3.0:1 border in both appearances, or is listed in
an explicit, commented allowlist with a reason.

## Verify
`--ui-contrast-check` in the matrix. Regression witnesses that must FAIL:
- Set a card's `bodyLabel.textColor = .tertiaryLabelColor` → must fail (2.25:1 on every card fill).
- Restore `separatorColor.withAlphaComponent(0.45)` as a card border → must fail (~1.1:1).

## Watch out
- Alpha compositing matters: semantic label colors are translucent, so the effective color depends
  on the fill beneath. Composite before computing luminance.
- Skip hidden/zero-size views or you will assert on invisible chrome.
- Do not "fix" a failure by widening the allowlist. If a pair fails, the color is wrong.
