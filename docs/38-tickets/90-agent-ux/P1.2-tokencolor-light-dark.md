# P1.2 — TokenColor carrying light + dark values
Phase: 1 · Depends on: P1.1 · Tag: autonomous · Execution-mode: medium

## Goal
The owner wants a real light theme, not just "dark that doesn't break." Today's `ChipColor` is a
single static sRGB triple — structurally incapable of expressing a theme. Introduce a token color
that carries both values and resolves by appearance.

## Files
- `Sources/ContinuumRevivedAgentUI/TokenColor.swift` (new)
- `Sources/ContinuumRevivedAgentUIChecks/TokenColorChecks.swift` (new)

## Approach
```swift
public struct TokenColor: Equatable, Sendable {
    public let light: ChipColor
    public let dark: ChipColor
    public init(light: ChipColor, dark: ChipColor)
    public init(_ both: ChipColor)                  // same in both themes
    public func resolved(for theme: TokenTheme) -> ChipColor
}
public enum TokenTheme: String, CaseIterable, Sendable { case light, dark }
```
Reuse `ChipColor` (already platform-neutral sRGB with a `hexKey`) as the leaf value and
`WCAGContrast` for ratios — do not reinvent either. Keep it `Foundation`-only; platform conversion
stays in the thin views.

## Done when
`TokenColor` exists, resolves per theme, and `TokenTheme.allCases` drives every later gate.

## Verify
New checks: resolution returns the right leaf per theme; the single-value initializer yields an
equal value in both; `hexKey` differs when the two themes differ (so a "themed" token that is
accidentally identical is detectable).

## Watch out
- Do NOT map `TokenTheme` to `NSAppearance` in this module (that would drag in AppKit). The app
  layer does that translation.
- Resist adding a `system`/`auto` case here — appearance resolution belongs to the platform layer;
  this type is a pure value.
