# P1.5 — Spacing + radius scale
Phase: 1 · Depends on: P1.1 · Tag: autonomous · Execution-mode: low

## Goal
Today: five different vertical paddings (3/6/8/10/12) against the same horizontal 12, four corner
radii with no rule, and a tile radius of 6 that nests cards at radius 8 (inverted nesting, reads as
sloppy). Fixed heights (52/92/44/24) are hardcoded and not derived from type metrics, so any type
change silently clips.

## Files
- `Sources/ContinuumRevivedAgentUI/Metrics.swift` (new)
- `Sources/ContinuumRevivedAgentUIChecks/MetricsChecks.swift` (new)

## Approach
```swift
public enum Space { public static let xs=2.0, s=4.0, m=8.0, l=12.0, xl=16.0, xxl=24.0 }   // 2pt grid
public enum Radius { public static let card=6.0, container=10.0, pill=999.0 }
public enum Inset { public static let card: EdgeInsetsToken; public static let row: EdgeInsetsToken }
```
`EdgeInsetsToken` is a neutral struct (top/left/bottom/right) converted in the views. Container
radius must be **greater** than nested-card radius. Also expose
`Metrics.rowHeight(for:TextRole, lines:Int)` so row heights derive from type instead of magic
numbers — that is what stops a type change from clipping.

## Done when
The scale exists and the agent tile's spacing is expressible with it (no bare literals needed later).

## Verify
Checks: all spacing values on the 2pt grid; the ladder is strictly increasing;
`Radius.container > Radius.card` (regression witness for today's inverted nesting);
`rowHeight` grows with line count and with a larger role.

## Watch out
- Do not adopt into views here (P1.10/P1.11).
- Do not encode the current 92pt approval-dock height as a token — it is a magic number that clips
  at the 320pt minimum tile width. Let P1.10 derive it.
