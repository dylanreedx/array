# P3.1 — AgentInboxRow presentation model
Phase: 3 · Depends on: P2B.3 · Tag: autonomous · Execution-mode: medium

## Goal
One pure value describing a row, so the list view is dumb and both platforms can share the logic
later. **Locked: the sidebar IS the inbox by default — not a mode you toggle into.**

## Files
- `Sources/ContinuumRevivedAgentUI/AgentInboxRow.swift` (new)
- `Sources/ContinuumRevivedAgentUIChecks/AgentInboxRowChecks.swift` (new)

## Approach
```swift
public struct AgentInboxRow: Equatable, Sendable, Identifiable {
    public let id: AgentID
    public let title: String            // displayName
    public let projectName: String?     // chip; project is METADATA, never a group header
    public let state: InboxState        // P3.2
    public let attention: InboxAttention// P3.3
    public let lifecycle: InboxLifecycle// .active/.snoozed/.settled — Phase 4 populates
    public let model: String?; public let role: String?
    public let branch: String?; public let isIsolated: Bool     // P2C.4
    public let elapsed: TimeInterval?   // only meaningful while working
    public let depth: Int               // 0 parent, 1 child (P2D.4)
    public let variant: RowVariant      // .card | .slim
}
```
Build from `AgentsBoardRow` + `AgentContextIndex` (P2B.3) — do not re-derive status.

## Done when
Rows are constructible from an `ActivityLogSnapshot` + context, with no AppKit import.

## Verify
Checks: totality (every `AgentStatus` maps to a state); a headless agent yields a row with no
branch/zone; `Identifiable.id` is the agent id (stable across refreshes — the list diffing depends
on it).

## Watch out
- No AppKit/UIKit in this module (it must compile for iOS).
- `elapsed` must be derived at render time from a start timestamp, not stored — a stored value goes stale.
