# P3.8 — Scope dropdown, not group headers
Phase: 3 · Depends on: P3.6 · Tag: autonomous · Execution-mode: medium

## Goal
Filter the flat list instead of grouping it. Group headers make the sidebar's width depend on the
number and length of project names; a scope control does not. Project stays metadata.

## Files
- `Sources/ContinuumRevived/App/AgentInboxView.swift`
- `Sources/ContinuumRevivedCore/WorkspaceSidebarConfig.swift` (persist the selection)

## Approach
An `NSPopUpButton` above the list: `All agents` · one entry per open project · one per workspace.
Selection persists via a new key in `WorkspaceSidebarConfig` (follow its existing key/default/clamp
shape). Filtering is pure: `filter(rows:scope:) -> [AgentInboxRow]`, so it is check-testable.

**A scope change must clear the multi-selection** (P3.11) — a bulk action must never touch rows you
cannot see.

## Done when
Scope filters the list, persists across relaunch, and clears selection on change.

## Verify
Pure checks for the filter; a UI check asserting selection is empty after a scope flip (regression
witness: retaining selection across a scope change must FAIL).

## Watch out
- Do not filter out an agent that is currently *open* in a focused tile — force-include it, or
  navigating hides your own row.
