# P5.2 — One persistent session per agent
Phase: 5 · Depends on: P5.1 · Tag: autonomous · Execution-mode: high

## Goal
Replace run-per-prompt (a fresh `pi -p` process per turn) with one long-lived rpc session per agent.
That is what makes interrupt, steering and mid-run changes possible at all.

## Files
- `Sources/ContinuumRevived/App/AgentSupervisor.swift`
- `Sources/ContinuumRevivedCore/AgentProviders/PiRpcClient.swift`

## Approach
`AgentSupervisor` (P2A.3) already owns runners and multicasts events; swap the runner implementation for
a `PiRpcClient` held for the agent's life. `send(prompt:)` becomes the `prompt` command instead of a new
process. Keep `PiEventTranslator` unchanged — the event vocabulary is identical between json and rpc.

Session continuity still comes from `--session-id` (P0.10/88.5), so history survives a client restart.
If the child dies, mark the agent `.stopped` and surface it; do **not** silently respawn mid-turn.

## Done when
An agent takes multiple prompts over one process, and the tile shows all turns.

## Verify
**Deterministic:** extend `--agent-supervisor-check` with a fake rpc client: two prompts over one
session produce two turns; killing the child marks `.stopped` and does not auto-respawn (witness).
**Manual:** two real turns against live Pi, confirming one `pi` process for both.

## Watch out
- Process lifetime now spans turns, so a leak is permanent — assert teardown on `stop()` and on app quit.
- Do not regress the GUI PATH fix: an app-launched child still needs the augmented PATH for `pi` **and** `node`.
