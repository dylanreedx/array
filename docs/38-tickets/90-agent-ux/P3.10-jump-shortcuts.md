# P3.10 — ⌘1–9 row jump with hint pills
Phase: 3 · Depends on: P3.6 · Tag: autonomous · Execution-mode: medium

## Goal
Keyboard-first triage. Because the order is frozen (P3.4), ⌘1–9 always hits the same agent — the
muscle memory actually works.

## Files
- `Sources/ContinuumRevived/App/AgentInboxView.swift`
- `Sources/ContinuumRevivedCore/ShortcutCatalog.swift` (declare the entries)
- `Sources/ContinuumRevivedCore/FocusModel.swift` (`ReservedShortcut.classify` — check for collisions)

## Approach
Bind ⌘1–9 to the first nine visible rows, declared in `ShortcutCatalog` so Settings can display them.
**Collision check first:** ⌘1–4 currently spawn launch profiles (`ContinuumApp` ~:4701-4712) and
`ReservedShortcut.classify` treats them as inviolable — resolve deliberately (either move profile
spawning to another chord and note it, or scope the inbox jumps to when the sidebar has focus). Do
**not** silently steal an existing global chord.

Holding the modifier reveals a floating hint pill per row, positioned as an **overlay** so it does not
displace the status label (T3 hit exactly this: holding ⌘ blanked out "Working").

## Done when
⌘1–9 jump to the right agents with no chord regression, and hints appear on modifier hold.

## Verify
Extend `--tile-action-check`/`--reserved-dispatch-check` style coverage: assert no duplicate chord
within a scope (`CoreChecks` already asserts this globally — it will catch a collision), and assert
hints do not change the status label's frame.

## Watch out
- `KeybindEditor` **rejects** chords colliding with inviolable globals by design — if the check fails,
  that is the collision surfacing, not a bug to work around.
