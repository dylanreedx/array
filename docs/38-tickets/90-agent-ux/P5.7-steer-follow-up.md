# P5.7 — Steer and queue messages into a running turn
Phase: 5 · Depends on: P5.2 · Tag: autonomous · Execution-mode: medium

## Goal
Say "actually, also do X" without waiting for the turn to finish or losing your place. Print mode awaits
each prompt sequentially, so this is rpc-only.

## Files
- `Sources/ContinuumRevived/App/AgentSupervisor.swift`
- `Sources/ContinuumRevived/Canvas/ManagedAgentTileNSView.swift`

## Approach
`prompt` while streaming requires an explicit `streamingBehavior` of `steer` or `followUp` — pick it
deliberately rather than defaulting: **steer** injects into the current turn, **followUp** queues for
after it. Also `set_steering_mode` / `set_follow_up_mode` for the default. Surface queued input in the
compose row ("queued · 1") so a user never wonders whether their message was lost, and show a queued
message in the transcript as pending, distinct from a sent one.

## Done when
Submitting during a turn queues or steers per the chosen mode, visibly, and nothing is silently dropped.

## Verify
**Deterministic:** fake client — submitting while streaming sends `prompt` WITH a `streamingBehavior`
(witness: omitting it must FAIL, since Pi rejects that); queue depth renders; a queued message is marked
pending until adopted.
**Manual:** steer a live turn mid-stream.

## Watch out
- The compose row currently hard-latches disabled while `working` (P0-era anti-double-submit). This ticket
  deliberately relaxes that — keep protection against *duplicate* submits while allowing an intentional
  second message.
