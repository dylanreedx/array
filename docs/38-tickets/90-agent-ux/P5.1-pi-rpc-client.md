# P5.1 — PiRpcClient: JSONL over stdin/stdout
Phase: 5 · Depends on: P2A.3 · Tag: autonomous · Execution-mode: high

## Goal
`--mode rpc` is a strict superset of `--mode json`: same event stream plus 32 commands. Every remaining
chat feature (interrupt, approvals, mid-run model/effort, real `/compact`, steering, token stats) is
**structurally impossible** without it. This ticket is the transport only.

## Files
- `Sources/ContinuumRevivedCore/AgentProviders/PiRpcClient.swift` (new)
- `Sources/ContinuumRevivedCoreChecks/PiRpcClientChecks.swift` (new)
- reuse `PiAgentRunner`'s executable/PATH resolution (`resolvedCommand`, `augmentedPath`, `liveExtraDirs`)

## Approach
Spawn `pi --mode rpc` (plus `--model`/`--thinking`/`--session-id` from `AgentModelConfig`). Framing is
**LF-only**: split on `0x0A` exactly, and do **not** use any reader that also breaks on U+2028/U+2029
— Pi's docs call this out explicitly as a spec violation that corrupts frames. Our existing byte-level
`consume`/`firstIndex(of: 0x0A)` loop in `PiAgentRunner` is already correct; reuse that shape.

Commands carry an optional `id`; keep a pending-continuation map so `send(_:) async throws -> Response`
correlates replies, while unsolicited events fan out to a stream. Drain **stderr concurrently** (the
deadlock fixed in `PiAgentRunner` — a full stderr pipe blocks the child).

## Done when
The client starts a session, sends a command, receives its correlated reply, and streams events.

## Verify
**Deterministic (matrix):** `PiRpcClientChecks` against a **scripted fake** — feed a recorded JSONL
transcript through the frame parser and assert: frames split only on LF; a payload containing a literal
U+2028 stays in ONE frame (this is the witness); ids correlate out-of-order replies; a partial trailing
line is buffered not dropped; a 100KB single frame parses.
**Manual (supervised, out of matrix):** run against real `pi --mode rpc`, capture the transcript, and
commit it as the fixture the checks use.

## Watch out
- Do not delete `PiAgentRunner` yet — P5.2 migrates callers; keeping both briefly is intended.
- `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS` is irrelevant here, but the loop's own iteration watchdog is
  not: keep any blocking read bounded.
