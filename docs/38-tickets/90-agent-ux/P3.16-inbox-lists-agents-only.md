# P3.16 — The inbox lists agents, not terminals

Phase: 3 · Depends: P2B.4, P3.1, P3.8

**PULLED FORWARD OUT OF PHASE ORDER at the owner's explicit instruction (2026-07-26).** They looked at
the built app, reported the list was full of things that are not agents, and chose "agents only —
filter terminals out" over keeping both with a visible split.

## Goal

The inbox shows **managed agents only** — agents backed by an `AgentRecord`, including orchestrator
children. Terminal-hosted agents stop being rows.

## What is true today, measured — read this before writing code

Do not start by adding a `kind == .terminal` filter. One already exists, one layer up, and the
interesting part is what it does NOT exclude.

`ContinuumApp.swift` ~line 6487 already ends the inbox row build with:

```swift
.filter { agentActivity.agentIdentities.contains($0.id) }
```

and `agentIdentities` (~line 4228) is built as:

```swift
var agentIdentities = Set(managedAgents.map(\.agentId))
for descriptor in descriptors where descriptor.agentDescriptor != nil {
    agentIdentities.insert(descriptor.tileId)
}
```

with a comment that states the current policy plainly: *"A terminal session with no
`AgentDescriptor` is a plain shell. It stays in the snapshot — the phone has always listed one, as
`Shell idle` — but it is NOT an agent on the canvas or in the sidebar, where every shell tile would
otherwise start rolling up as '1 unknown'."*

**So plain shells are already excluded.** The rows the owner is seeing are terminals whose
`agentDescriptor` is non-nil — a terminal running a recognized agent. `agentDescriptor` is derived at
runtime from the live session, not persisted in `canvas.json`, so it cannot be counted from disk;
confirm the real count by instrumenting the row build, not by reading files (the supervisor tried the
filesystem route and it does not answer this question).

**The change this ticket makes is therefore narrower and sharper than "filter terminals":** it drops
the second half of `agentIdentities` from the INBOX's definition of a row, so a row must be
`AgentRecord`-backed.

## The consequence the owner accepted, and it must stay visible

A `claude`/`codex` session the owner started in a terminal tile will **no longer appear in the
inbox**. That is a defensible reading of "agent inbox" (the inbox manages agents Continuum owns and
can settle, snooze, stop and archive — none of which it can do to a process inside someone's shell)
but it is a real loss and the owner may reverse it once they see it.

Therefore: **make it a filter, not a deletion.** The scope dropdown (`P3.8`, `InboxScope` in
`ContinuumRevivedAgentUI`) is the existing mechanism for "which rows do I want", it is already
order-preserving by construction and asserted as `filter∘sort == sort∘filter`, and it already persists
a selection. Express this as the inbox's row-source policy with the terminal-hosted set still
reachable, rather than by making those agents unrepresentable. If you conclude a new scope entry is
out of scope for this packet, then keep the policy in ONE named place with a comment pointing at this
ticket, so reversing it is a one-line change and not an archaeology exercise.

## Do NOT re-break P2B.5

`P2B.5-drop-terminal-filters` (`f3bb9e2`) deleted two filters, for good reasons, and neither of them
is this one:

- `currentAgentTileIds` — so ⌥-agent-cycle and ⌥-needs-attention reach managed-agent tiles instead of
  stepping over them.
- `SidebarTreeBuilder` — kind-agnostic since `P2B.4`, so a managed-agent tile shows its record's
  status in the outline instead of "no agent".

Its regression witnesses are live and will catch you: restoring the `SidebarTreeBuilder` filter goes
red with *"a managed-agent tile must show its record's status in the sidebar — got 'no agent'"*, and
restoring the `currentAgentTileIds` filter goes red with *"⌥-cycling must reach a managed-agent
tile"*. **Those checks passing is a requirement of this ticket, not an obstacle to it.** The inbox row
source is a different consumer; ⌥-cycling, the outline, the zone rollups and the phone timeline must
all behave exactly as they do now. If your change moves any of them, it is in the wrong place.

- `Sources/ContinuumRevivedAgentUI/InboxScope.swift` — if the reachable-filter route is taken.

## Done when

- Every inbox row is `AgentRecord`-backed; no terminal-hosted row appears by default.
- ⌥-agent-cycle, ⌥-needs-attention, the sidebar outline, the zone rollups and the phone timeline are
  unchanged — asserted, not assumed.
- The empty state is honest. `P3.8` already added a second message for "filtered out" vs "none at
  all", and this ticket makes that distinction load-bearing: a user whose only agents live in
  terminals now sees an empty inbox, and "No agents yet" would be a lie.
- Full matrix green, no floor lowered, no check loosened.

## Verify

```
swift build 2>&1 | tail -20
./scripts/run-matrix.sh
```

**Required red-green witnesses** (each observed red at exit 1 against the FINAL code, failure text
quoted verbatim at the assertion):

1. A terminal-hosted agent (a descriptor with a non-nil `agentDescriptor`) still produces a row → red.
   This is the ticket's whole assertion; a fixture without such a descriptor makes it vacuous, so
   build the fixture FIRST and confirm it produces a row before the change.
2. A managed agent dropped from the rows → red. The filter must not overshoot; this is the pair to 1.
3. An orchestrator CHILD dropped → red. `P2D.4` nests children and they are `AgentRecord`-backed;
   a filter keyed on the wrong half of the aggregate keyspace (`P3.1` flattened two id spaces into
   one) would take them with it.
4. `agentIdentities` itself narrowed instead of the inbox row source → `P2B.5`'s two witnesses go red.
   Record that you ran this one: it is the guard against fixing this in the wrong layer.
5. The empty-state distinction collapsed to one message → red (`P3.8`'s assertion).

Then confirm the owner's own case: with an agent in a terminal tile AND a managed agent present, the
inbox shows exactly one row.

## Watch out

- **The scope's force-include rule still wins.** `P3.8` guarantees the agent open in the focused tile
  is never hidden, whatever the scope says. Decide and state what that means when the focused tile
  holds a terminal-hosted agent that this filter excludes — the two rules meet head-on, and the answer
  should be written down rather than discovered. Prefer the narrower change and say so.
- **The phone must not change.** The comment at `agentIdentities` records that the phone "has always
  listed one, as `Shell idle`". This is a desktop inbox policy; iOS is `P8`'s. Do not touch the sync
  payload, and remember I5: only derived metadata crosses the boundary.
- **Reading is free** (`P4.9`) — a filter change must not mark anything read.
- Do not touch delete/archive wiring: that is `P3.15`, which is queued ahead of this and is the more
  urgent of the two.
