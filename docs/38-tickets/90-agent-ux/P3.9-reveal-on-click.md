# P3.9 — Click a row → reveal the agent
Phase: 3 · Depends on: P3.6, P2A.5 · Tag: autonomous · Execution-mode: medium

## Goal
The inbox is triage; the canvas is depth. Clicking a row takes you to the work — including across
workspaces, and including agents that currently have no tile.

## Files
- `Sources/ContinuumRevived/App/AgentInboxView.swift`
- `Sources/ContinuumRevived/App/ContinuumApp.swift` (`jumpToTileFromPalette` ~:7676, `switchWorkspaceFromSidebarIfNeeded` ~:5716)

## Approach
Reuse the existing reveal primitive **exactly as the sidebar already does**: `focusTileFromSidebar`
→ `jumpToTileFromPalette` (which frames the viewport, records focus history with `.paletteJump`, and
enters the tile scope) preceded by `switchWorkspaceFromSidebarIfNeeded` for the cross-workspace case.
Do not write new navigation.

If the agent is **headless** (`tileId == nil`), attach a view first (`supervisor.attach`, P2A.5) at a
sensible placement, then reveal it. Opening a row also clears `unread` (P3.3).

## Done when
Clicking any row — same workspace, other workspace, or headless — lands you on that agent.

## Verify
`--agent-inbox-check`: same-workspace reveal focuses the tile; cross-workspace reveal switches first;
a headless agent gets a tile attached and focused; unread clears.

## Watch out
- **Opening must not change lifecycle.** Reading is free — only *acting* un-settles (Phase 4). Do not
  un-settle on reveal.
- Do not spawn a second tile for an agent that already has one.
