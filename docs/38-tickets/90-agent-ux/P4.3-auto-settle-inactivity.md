# P4.3 — Auto-settle on inactivity
Phase: 4 · Depends on: P4.2 · Tag: autonomous · Execution-mode: low

## Goal
The list must drain itself, or it becomes a graveyard you stop reading.

## Files
- `Sources/ContinuumRevivedCore/AgentAutoSettleConfig.swift` (new, follow `FocusBorderConfig` shape)
- `Sources/ContinuumRevivedCore/SettingsSchema.swift` (agents section)
- `Sources/ContinuumRevivedAgentUI/AgentLifecycle.swift`

## Approach
`autoSettleAfterDays`: default **3**, range 1–90, **nullable = off**. Follow the established `*Config`
pattern exactly (key + default + clamp + `resolvedFromDefaults`), bound by one `SettingsField` — the
renderer needs no changes. `.neutral` records older than the threshold resolve `.settled` in P4.2's
step 4; a `.active` pin suppresses it.

## Done when
An agent untouched for longer than the threshold settles itself; the pin prevents it; nil disables it.

## Verify
Checks: at threshold−1 stays active, at threshold+1 settles, `.active` pin stays active regardless, nil
config never auto-settles. Existing settings-schema checks (unique keys, round-trip) pick up the field.

## Watch out
- "Inactivity" must mean *agent* activity (`lastActivityAt`), not the user looking at it — otherwise
  reading a row would keep it alive forever.
- Nullable-off must be representable in a `SettingsField.choice`; use an explicit "Off" option rather
  than an empty string.
