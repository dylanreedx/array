# P1.6 — Contrast-gate the token table in both themes
Phase: 1 · Depends on: P1.3 · Tag: autonomous · Execution-mode: medium

## Goal
Stop a bad token from ever shipping, independently of whether a view has adopted it yet. This is
complementary to P0.4 (which reads the live view tree and catches views that *bypass* tokens); this
one proves the palette itself is sound.

## Files
- `Sources/ContinuumRevivedAgentUIChecks/TokenContrastChecks.swift` (new)
- reuse `WCAGContrast` (moved in P1.1)

## Approach
Iterate `TokenTheme.allCases` × the **documented** text/surface pairs from P1.3 (not a
cross-product — an undocumented pair is a design error, so assert the documentation is complete
instead). Assert ≥4.5:1 for text, ≥3.0:1 for borders/separators and for accent-as-glyph. Print a
table of every pair and its ratio on success so the numbers are reviewable in the log, not just
pass/fail.

## Also: turn on the P0.4 leg
P0.4 built `--ui-contrast-check` (real view tree, both appearances) and left it **unwired** because
it is red on 177 real pairs until tokens land. Once P1.10/P1.11 have adopted tokens, add
`run_app_check .build/debug/continuum-revived --ui-contrast-check` to `run-matrix.sh` and regenerate
the matrix inventory (P0.11's sanctioned path). If pairs still fail, the tokens are wrong — fix the
tokens, never the gate.

## Done when
Both themes pass, the log shows the full ratio table, and the P0.4 leg is wired and green.

## Verify
Regression witnesses that must FAIL: (1) set `textSecondary.dark` to a 25%-white grey (today's
`tertiaryLabelColor` equivalent, 2.25:1 on card fills); (2) set `border.dark` to `white 0.25`
against `tileBody.dark` `white 0.10` (1.68:1). Include both as commented snippets so the next
reader can re-run them.

## Watch out
- Do not widen an allowlist to pass. A failing pair means the token is wrong.
- The metric anchor (white/black ≈21:1) must be in this suite too, or a broken luminance function
  could make everything "pass".
