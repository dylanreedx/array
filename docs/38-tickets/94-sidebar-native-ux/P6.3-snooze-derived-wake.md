# P6.3 — Snooze with a derived wake and a raised hand

Phase: 6 · Lifecycle and children
Execution: **autonomous**
Depends on: P6.2

## Goal

Let a row be put down until later without pausing the agent, and let it raise its own hand when something needs a human.

## Approach

1. Treat snooze as a visibility overlay: the agent keeps running, so a working row is snoozable even though it is not settleable, and only blocked-on-a-human or unadopted-prompt states refuse a snooze.
2. Derive wake rather than scheduling it: stale fields simply stop classifying as snoozed, and at most one timer exists for the earliest upcoming wake purely to trigger a re-render, with a clamped delay.
3. Implement early wake as a raised hand that never mutates the stored snooze, comparing triggers against the moment the snooze was taken rather than against its end.
4. Reject a wake time that is not strictly in the future rather than normalizing it, and offer presets whose offsets resolve at open time.

### Implementation sketch

```swift
// Wake is derived, not scheduled. The stored snooze is never rewritten.
var isSnoozed: Bool { snoozedUntil.map { $0 > now } ?? false && !raisedHand }
var raisedHand: Bool { blockedOnHuman || failedAfter(snoozedAt) || completedAfter(snoozedAt) }
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- A snoozed agent keeps working; snooze changes visibility only.
- Wake needs no daemon: a passing wake time alone un-snoozes the row, and at most one clamped timer exists.
- A raised hand returns the row without mutating the stored snooze, and compares against the snooze moment, not its end.
- A non-future wake time is rejected; presets resolve relative to when the menu opened.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- A row snoozed while already failed must stay snoozed — that snooze was the user saying “I saw it, not now” — which is why the comparison is against the snooze moment.
- A far-future wake can produce a degenerate immediate timer fire unless the delay is clamped.
- The shelf classification needs a real second-precision clock even if other derivations use a coarser tick.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
