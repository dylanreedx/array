# P2.5 — One elapsed formatter, capped and columnar

Phase: 2 · Row anatomy
Execution: **autonomous**
Depends on: P2.4

## Goal

Give durations one shared, bounded formatter and a fixed column, so a long-running agent stops eating the name's width.

## Approach

1. Move duration formatting into one shared function used by the sidebar, the tile header, and any phone payload, replacing the divergent vocabularies.
2. Coarsen past a day and cap the rendered form, so no duration can grow without bound; clamp negative and non-finite input to zero.
3. Reserve a fixed monospaced-digit column sized for the widest form the formatter can emit, so the name's width no longer depends on how long an agent has run.
4. Assert the formatter's output for a table of inputs including zero, sub-minute, sub-hour, multi-hour, multi-day, negative, and non-finite.

### Implementation sketch

```swift
static func elapsedLabel(_ seconds: TimeInterval) -> String {
    guard seconds.isFinite else { return "0s" }
    let s = max(0, Int(seconds))
    if s < 60 { return "\(s)s" }
    if s < 3_600 { return "\(s / 60)m" }
    if s < 86_400 { return "\(s / 3_600)h \((s % 3_600) / 60)m" }
    return "\(s / 86_400)d"
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Watch out

**Carried findings from the 2026-08-04 attempt (independent review, DECISION: REWORK).** The
candidate got the hard parts right — the formatter is in the leaf module with no new module edge, the
clamp is in the formatter while nil-for-negative stays in the row adapter, the out-of-fence
`"· 1m 5s"` assertion still holds, and `"12m ago"` / `"in 25m"` / `"5m ago"` all survive. Four things
must be fixed.

- **The tile header's fixed lane must measure what it actually RENDERS.** The lane was sized from the
  formatter's bare forms while the label renders `"· " + label` — two glyphs never measured. Lane
  43 pt against a 49–55 pt need, with `.byClipping`, so the live timer cuts itself mid-glyph after
  about ten minutes, with no ellipsis. Before this ticket that label had no width constraint and could
  not truncate, so this is a **regression on a surface queue 91 closed**. Size the lane from the
  rendered string, prefix included.
- **The assertion for that must be able to fail.** The header leg compared `qaElapsed` to an expected
  string — which `_RUNBOOK.md` calls vacuous in as many words — and compared the frame against the
  widest *bare* need, so it passed exactly at the boundary while the rendered string overflowed. It
  also read frames straight after the tick with no layout pass driven, so no width could move
  whatever the implementation did. Assert drawable width against the need for the **rendered** string.
- **Prove the name's width claim where it can actually vary: the SLIM row.** On a card the title's
  width is pinned to the band by P2.1 and is independent of the elapsed column before and after this
  change, so that assertion would stay green with the fixed column deleted. The slim row is the only
  row whose name shares a line with a duration, and it got no column — its relative form swings ~28 pt
  between `"0s ago"` and `"59m 59s ago"`, and `row51.title@{min,default}` already elide. Give the slim
  time label a measured column too, and assert there.
- **Pin the gate's clock, and record the real reason a key healed.** `checkSidebarTruncationGate`
  still builds its probe without pinning `probe.inbox.clock`, unlike every other leg. The corpus
  epoch makes the settled fixture render a ~993-day wall-clock distance, and *that* — day-coarsening a
  value the gate should never read — is what removed `row51.branch@wide`, not "compact exact-minute
  output" as the comment claimed. Pin the clock, then re-derive the table and record the true cause.
  A truncation table calibrated against the machine's date is not a gate.


- The tile header currently renders the same duration as minutes-plus-seconds while the sidebar renders hours; unifying them changes the header, which is why it is in the fence.
- A cap that hides real information is wrong; coarsen the unit rather than clipping the number.
