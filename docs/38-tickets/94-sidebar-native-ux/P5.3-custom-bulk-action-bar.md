Phase: 5 · Native interaction
Execution: **autonomous**

## Goal

Rebuild multi-selection actions as a Continuum surface that states exactly what it will act on.

## Approach

1. Replace the raw AppKit bulk bar with a custom surface using the tile's control family, stating the count and the scope of what will be affected.
2. Offer only actions valid for every row in the selection, hiding the rest; a mixed selection narrows the action set rather than acting inconsistently.
3. Make destructive bulk actions confirm, and make every bulk action idempotent so a double activation is a silent no-op rather than an error.
4. Assert that the bar acts on exactly the visible selection and that it appears and disappears with the selection at all three widths.

### Implementation sketch

```swift
// The bar names its own blast radius.
countLabel.stringValue = "\(selection.count) selected"
actions = BulkAction.allCases.filter { action in
    selection.allSatisfy { action.isValid(for: $0) }
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- The bar offers only actions valid for every selected row; a mixed selection narrows the set.
- Destructive bulk actions confirm before acting, and every bulk action is idempotent.
- The bar acts on exactly the visible selection — asserted with a filter active.
- The bar fits at 220 pt without truncating its count.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- An action valid for only some selected rows either fails partway or acts inconsistently; narrowing is the honest answer.
- Idempotence matters because a bulk activation can double-fire; a re-emission must not surface an error or reorder anything.
- The bar must not overlap the filter band or steal the list's scroll area.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
