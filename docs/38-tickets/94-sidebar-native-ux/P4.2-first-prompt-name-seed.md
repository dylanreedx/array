# P4.2 — Seed the name from the first prompt

Phase: 4 · Identity and naming
Execution: **autonomous**
Depends on: P4.1

## Goal

Name an agent from the user's own first words, deterministically, inside the one funnel every prompt already passes through.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing, plus
`docs/38-tickets/91-agent-tile-ux/plan-sidebar-t3code-study.md` and

## Approach

1. Seed `displayName` from the first prompt inside `AgentSupervisor.send(_:to:)`, gated on the name still being the sentinel, so a later prompt and a manual rename are both safe.
2. Derive the name with a human-cased twin of the existing worktree slug sanitizer: collapse whitespace, strip control characters, apply one length limit with one ellipsis rule.
3. Pick one limit and one truncation rule, and use it on every surface — divergent limits are how the same agent ends up reading differently in two places.
4. Assert the seed for an empty prompt, a whitespace-only prompt, a multi-line prompt, a prompt of combining marks, a right-to-left prompt, and a very long prompt.

### Implementation sketch

```swift
// One funnel, one gate, no model call.
if record.displayName == AgentRecord.defaultAgentName, !prompt.isEmpty {
    record.displayName = AgentName.fromPrompt(prompt)   // trim, collapse, cap, ellipsise
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- An agent prompted once carries a name derived from that prompt; an agent prompted twice keeps the first name.
- A manually renamed agent is never re-seeded.
- One limit and one ellipsis rule are used everywhere, asserted.
- Empty, whitespace-only, multi-line, combining-mark, right-to-left, and over-long prompts all produce a valid displayable name.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.
