# P6.1 — Lifecycle as a pure derivation

Phase: 6 · Lifecycle and children
Execution: **autonomous**

Compute lifecycle from the raw persisted fields at every read, with activity blockers outranking every override in both directions.

## Approach

1. Derive `InboxLifecycle` from the raw fields plus `now` at every read; persist no resolved lifecycle value anywhere.
2. Check activity blockers first and let them hold a row active regardless of any override: blocked on a human, a live runner, or an unadopted prompt inside a bounded grace window.
3. Use one blocker list for both the classifier and the action guard — whatever the classifier refuses to call settled, the guard must refuse as a settle target — and assert the two agree.
4. Bound the unadopted-prompt window on both sides of `now`, so a peer clock running ahead cannot pin a row active for the whole skew.

### Implementation sketch

```swift
// One blocker list, two consumers, asserted to agree.
func blockers(_ r: AgentInboxRow, now: Date) -> Bool {
    r.attention.isYours || r.hasLiveRunner || hasUnadoptedPrompt(r, now: now)
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- No resolved lifecycle value is persisted; every read derives it.
- A blocked or live row stays active even with an explicit settled override, asserted.
- The classifier and the action guard are shown to agree over the whole corpus.
- A future-stamped prompt is treated as clock skew, not as pending work, asserted in both directions.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- A cached lifecycle disagrees with itself across views the moment any input changes; derive it.
- Continuum syncs across machines, so the grace window must be two-sided.
- If “Working” hides the settle action, the same function must decide both, or a row becomes permanently undismissable.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
