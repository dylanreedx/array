# P3.2 — Gate the read behind the sweep

Phase: 3 · Status truthfulness
Execution: **autonomous**
Depends on: P3.1

## Goal

Make it structurally impossible for any surface to read agent state before reconciliation has committed.

## Approach

1. Give the supervisor an explicit readiness state and refuse to answer snapshot or row queries until the sweep has committed.
2. Start the inbox data source empty rather than from disk, so a lazily built row cannot race the sweep.
3. Make the refusal observable: a query before readiness returns an explicit not-ready value that the caller must handle, never a silently empty or default answer.
4. Assert ordering by construction: a probe that queries before readiness fails the leg.

### Implementation sketch

```swift
enum SupervisorReadiness { case reconciling, ready }
func rows() throws -> [AgentInboxRow] {
    guard readiness == .ready else { throw SupervisorNotReady() }
    …
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- A snapshot or row query issued before reconciliation commits fails explicitly rather than returning disk-derived state.
- The inbox data source begins empty and is populated only after readiness.
- Ordering is asserted by a probe that deliberately queries early and must go red.
- No caller silently swallows the not-ready value.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- Ordering the sweep before the first read is not enough on its own — a lazily materialized row can still beat it, which is why the refusal has to be explicit.
- A not-ready value that callers treat as “no agents” reintroduces the bug in a quieter form.
- Do not block the main thread on the sweep; refuse the read instead.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
