# P4.5 — Optional one-shot generated name

Phase: 4 · Identity and naming
Execution: **autonomous**
Depends on: P4.4

## Goal

Offer an explicit “rename with a model” action backed by one short-lived provider process that can never block, clobber, or leak.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing, plus
`docs/38-tickets/91-agent-tile-ux/plan-sidebar-t3code-study.md` and

## Approach

1. Add an explicit owner-triggered action that runs one short-lived provider process to propose a name, forked and failure-swallowing, with the sentinel or the existing name left intact on any failure.
2. Constrain the process: read-only sandbox, structured single-field output, prompt on stdin, a cheap model, a bounded timeout, a concurrency cap, and a process-group kill on timeout.
3. Resolve the executable path from the login shell before spawning, and set a provider config directory without overriding the home directory, so credential lookup still works.
4. Sanitize the result unconditionally — first line only, strip wrapping quotes, collapse whitespace, one length cap — and land it only through P4.3's compare-and-swap.
5. Gate the whole action on the capability being present and authenticated; when it is absent the action is hidden, not shown dead.

### Implementation sketch

```swift
// Short-lived, read-only, structured, bounded, best-effort.
let argv = ["exec", "--ephemeral", "--skip-git-repo-check", "-s", "read-only",
            "--model", cheapModel, "--output-schema", schemaPath, "-"]
// stdin: the prompt. timeout: bounded. failure: log, keep the current name.
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- The action never blocks agent creation or a turn; a failed or timed-out generation leaves the name unchanged and logs.
- A concurrent burst of requests is capped, and a timeout kills the process group rather than orphaning children.
- The result is sanitized before it can reach a name, and lands only through the compare-and-swap guard.
- With the capability absent or unauthenticated the action is hidden and no process is spawned.
- No prompt text or generated name crosses the sync boundary in violation of I5.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- This is new runtime surface: a second kind of provider process. If the capability does not exist or cannot authenticate, mark the packet `blocked` rather than simulating it.
- Overriding the home directory relocates keychain lookup and the provider CLI reports itself logged out; set the config directory instead.
- A GUI app's inherited PATH will not find the binary; resolve it from the login shell.
- No retry, no model downgrade, no provider fallback — naming is best-effort by design.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
