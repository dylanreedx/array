# P6.2 — Auto-settle on real inactivity

Phase: 6 · Lifecycle and children
Execution: **autonomous**
Depends on: P6.1

## Goal

Let quiet finished work park itself after a configurable window measured from real activity.

## Approach

1. Auto-settle on a strict inactivity comparison with day granularity, a configurable window, a sensible default, and an explicit off value.
2. Measure inactivity from real activity only — the latest prompt or turn timestamp — never from a metadata write, so a rename or a read cannot keep a dead row alive.
3. Give the explicit un-settle two outcomes: a user pin that suppresses auto-settle until real activity, and a neutral clear that is re-eligible.
4. Fail toward active: a malformed or missing timestamp must never produce a surprise auto-settle.

### Implementation sketch

```swift
// Real activity only. A metadata write is not activity.
let lastActivity = [record.latestPromptAt, record.latestTurnAt].compactMap { $0 }.max()
let settled = window.map { lastActivity < now.addingTimeInterval(-$0) } ?? false
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- A row with no real activity inside the window settles; a renamed or merely viewed row does not.
- The window is configurable with an explicit off value, and off is honoured.
- A user pin suppresses auto-settle until real activity arrives; a neutral clear is re-eligible.
- A malformed timestamp leaves the row active, asserted.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- `lastActivityAt` is bumped by metadata writes; using it directly makes a rename keep a dead agent alive forever.
- A single boolean cannot express “I un-settled this and I do not want the rule to grab it again”.
- Do not settle a row that is blocked on a human, whatever the window says — P6.1's blockers come first.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
