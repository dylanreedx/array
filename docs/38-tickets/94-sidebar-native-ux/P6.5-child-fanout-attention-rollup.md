# P6.5 — Bounded fan-out and attention roll-up

Phase: 6 · Lifecycle and children
Execution: **autonomous**
Depends on: P6.4

## Goal

Keep nested children readable when one agent spawns thirty, and make sure a child blocked on a human is never invisible.

## Approach

1. Cap visible children per parent, ordering the survivors by need — blocked and failed first, then most recently active — and render an explicit remainder affordance that expands rather than hiding the count.
2. Propagate a child's attention to its parent explicitly, so a collapsed or capped child that is blocked on a human still shows on the parent's row.
3. Keep the depth cap a presentation rule and decide what happens to a deeper agent — clamp, hide, or re-parent — pinning the choice with an assertion.
4. Keep an unfiltered enumeration of agents for bookkeeping, separate from the visible list, and make anything that owns resources read the unfiltered one.

### Implementation sketch

```swift
// Bounded fan-out, need-ordered, explicit remainder.
let shown = children.sorted(by: needFirst).prefix(Self.maxVisibleChildren)
let hidden = children.count - shown.count      // rendered, never silently dropped
parentAttention = children.map(\.attention).reduce(.none, max)
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- A forty-child parent renders a bounded set plus an explicit remainder; no child is silently dropped.
- A blocked child raises its parent's attention even when capped or collapsed, asserted.
- A depth-3 agent is handled by the pinned rule rather than drawn as though it were depth 2.
- Resource bookkeeping reads the unfiltered enumeration, asserted so a hidden child's worktree is never treated as orphaned.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- Hiding rows breaks resource bookkeeping: a hidden child still holds a worktree, and cleanup that reads the visible list will consider it orphaned. Fail closed.
- A capped child blocked on approval with no roll-up leaves no signal on any visible row — that is a real bug in the reference implementation and must not be reproduced.
- The depth cap bounds nesting, not fan-out; do not treat it as if it did.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
