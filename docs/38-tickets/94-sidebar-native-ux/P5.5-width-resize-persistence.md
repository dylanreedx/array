# P5.5 — Width, resize, and persistence

Phase: 5 · Native interaction
Execution: **autonomous**
Depends on: P5.4

## Goal

Make the sidebar resize like a native one and restore its width before the first frame.

## Approach

1. Compute the maximum width from the window rather than hardcoding it, so the sidebar may grow only while the content pane keeps its own floor; veto asymmetrically, always allowing a shrink.
2. Persist width on resize-end only, never per frame, and restore it before the first layout pass so a restored sidebar never flashes at the default width.
3. Free-drag with hard stops — no snapping and no detents — and give the divider a direction-aware cursor plus an accessible label.
4. Assert the clamp at the minimum, the default, the computed maximum, and against a window too narrow to honour both floors.

### Implementation sketch

```swift
// The maximum is computed, never hardcoded.
let maxSidebar = max(config.minimumWidth, floor(windowWidth) - contentMinimumWidth)
return min(max(config.minimumWidth, proposed), maxSidebar)
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- Width restores before the first paint with no flash at the default.
- A growth that would starve the content pane is vetoed; a shrink is always allowed.
- No snapping or detents; the clamp is asserted at minimum, default, computed maximum, and an over-narrow window.
- Persistence writes on resize-end only, asserted by counting writes during a simulated drag.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- A rejected drag produces no state change, so anything cached at layout time goes stale; subscribe to resize rather than snapshotting.
- Restoring in `viewDidAppear` is too late — the default paints first.
- Do not lower the 220 pt minimum to make a layout fit; the layout is what must fit.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
