# P5.2 — Filter band: custom scope control and search

Phase: 5 · Native interaction
Execution: **autonomous**
Depends on: P5.1

## Goal

Replace the Aqua scope popup and give the sidebar a real fixed filter band with search.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing, plus
`docs/38-tickets/91-agent-tile-ux/plan-sidebar-t3code-study.md` and

## Approach

1. Replace the scope `NSPopUpButton` with a `ChoiceButton` plus popover, pinned to the trigger's width so the band's width never depends on how many projects exist or how long their names are.
2. Add a search field to the same fixed band — a sibling of the scroll view, never a table header — with a result mode that preserves lifecycle ordering while narrowing.
3. Clear the multi-selection whenever scope or search changes, so a bulk action can never count or touch a row that is not visible.
4. Assert the band's layout at all three widths, including the longest corpus project name and an active search with no results.

### Implementation sketch

```swift
// Scope filters the list; it never lets project names dictate the band's width.
scopeButton.apply(.init(title: scope.label, accessibilityLabel: "Agent scope"))
scopePopover.preferredWidth = scopeButton.bounds.width
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace

## Watch out

- Bulk actions must never count or touch invisible rows; the selection clear is the whole safety property here.
- A search field installed as a table header scrolls away and breaks the fixed-band layout.
- Searching must not reorder rows — the frozen order rule still applies inside results.
