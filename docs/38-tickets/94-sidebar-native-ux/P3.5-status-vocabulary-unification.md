# P3.5 — One status vocabulary across every surface

Phase: 3 · Status truthfulness
Execution: **autonomous**
Depends on: P3.4

## Goal

Make the same agent read the same way in the sidebar, the tree chip, the tile header, and the phone.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing, plus
`docs/38-tickets/91-agent-tile-ux/plan-sidebar-t3code-study.md` and
`plan-sidebar-and-state-findings.md` for the evidence this program is built on. Surface is reserved
for interaction; the row's subject is its name; one owner answers what an agent is doing; a name is
never an identifier; no stock AppKit chrome belongs in the sidebar. Every geometry assertion runs at
220, 280, and 320 pt. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

## Approach

1. Reconcile the vocabularies so one agent state produces one word everywhere, and record any deliberate divergence with its reason.
2. Pin the agreement with a table asserting sidebar, chip, header, and phone labels for every state, including unconfirmed.
3. Keep the phone payload's existing contract shape; change the words it carries, not its schema, and confirm the I5 boundary is untouched.
4. Assert that a state added in future must extend the table or fail.

### Implementation sketch

```swift
// One state, one word, everywhere. Divergence must be deliberate and named.
for state in InboxState.allCases {
    assertEqual(sidebarLabel(state), chipLabel(state), headerLabel(state), phoneLabel(state))
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- Every state produces one label across sidebar, chip, header, and phone, or a named exception with a recorded reason.
- The table is exhaustive over states and fails when a new state is added without a label.
- The phone payload's schema is unchanged and the I5 boundary is re-asserted.
- The three-words-for-one-wrongness case from the findings doc can no longer occur.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- The same agent currently reads three different ways across three surfaces; unifying the words without unifying the source would just relocate the disagreement.
- Changing the phone payload's schema is out of scope and would touch queue 92's contract.
- Do not add a word for a state the runtime cannot distinguish.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
