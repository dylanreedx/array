# P3.4 — Unconfirmed rows and a frozen clock

Phase: 3 · Status truthfulness
Execution: **autonomous**
Depends on: P3.3

## Goal

Render an agent nobody has observed as unconfirmed, with a frozen duration, instead of asserting that it is working.

## Approach

1. Render `unobservedAgentIds` — already computed, currently drawn by nobody — as an explicit unconfirmed row presentation.
2. Freeze the duration for an unconfirmed row and label what the number means, so the row states a last-known fact rather than implying live progress.
3. Keep the unconfirmed presentation visually quiet: it is a confidence modifier on the status, not a sixth state.
4. Assert that no unconfirmed row renders a working label or a ticking duration, at all three widths.

### Implementation sketch

```swift
// Two orthogonal facts: what it is doing, and how sure we are.
if row.isUnconfirmed {
    statusLabel.stringValue = "Unconfirmed"
    elapsedLabel.stringValue = row.elapsed.map { "last seen \(elapsedLabel($0))" } ?? ""
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- Every agent in `unobservedAgentIds` renders as unconfirmed, asserted over the live tree.
- No unconfirmed row shows a working label, and its duration does not advance between two probe reads.
- The unconfirmed treatment is a modifier on the existing states, not a new `InboxState` case.
- A confirmed agent is unaffected by this packet.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- A ticking clock asserts a liveness nobody confirmed — freezing it is the point, and it is the one place this program improves on its reference implementation.
- Do not add a sixth state to `InboxState`; the five-state, three-colour rule is locked.
- An unconfirmed row must still be actionable — do not strand it in a state with no exit.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
