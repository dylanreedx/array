# P0.4 — Inbox geometry gate at 220, 280, and 320 pt

Phase: 0 · Foundations
Execution: **autonomous**
Depends on: P0.3

## Goal

Gate the sidebar at the widths it actually ships at, with truncation asserted by drawable width rather than by frames or strings.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing, plus
`docs/38-tickets/91-agent-tile-ux/plan-sidebar-t3code-study.md` and
`plan-sidebar-and-state-findings.md` for the evidence this program is built on. Surface is reserved
for interaction; the row's subject is its name; one owner answers what an agent is doing; a name is
never an identifier; no stock AppKit chrome belongs in the sidebar. Every geometry assertion runs at
220, 280, and 320 pt. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

## Approach

1. Add an inbox leg to `--ui-geometry-check` that renders the corpus at 220, 280, and 320 pt in both appearances.
2. For every label assert drawn width against the measured need for its exact string and font, including the 4 pt `NSTextField` cell inset, and report which element lost width when the assertion fails.
3. Un-pin the fixed 79 pt row-height assertions so a later content-derived height is not blocked by a gate that calls today's dead space correct.
4. Read the shipping default and minimum from `WorkspaceSidebarConfig` instead of restating them, so a config change cannot silently un-gate a width.

### Implementation sketch

```swift
var qaTitleDrawsWithoutTruncation: Bool {
    let needed = ceil((titleLabel.stringValue as NSString)
        .size(withAttributes: [.font: NSFont.token(.label)]).width) + 4
    return titleLabel.frame.width + 0.5 >= needed
}
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- The leg fails at 220 pt against today's row, naming the truncated element — that red is the packet's entry witness.
- Widths come from `WorkspaceSidebarConfig`; hardcoding 280 or 220 in the check is red.
- No height assertion pins 79 pt as correct after this packet.
- Both appearances are measured at all three widths.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.
