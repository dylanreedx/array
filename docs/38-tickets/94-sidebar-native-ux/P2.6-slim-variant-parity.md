# P2.6 — Slim variant parity at every width

Phase: 2 · Row anatomy
Execution: **autonomous**
Depends on: P2.5

## Goal

Bring the collapsed row up to the same standard as the card, so parked work stays scannable at 220 pt.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing, plus
`docs/38-tickets/91-agent-tile-ux/plan-sidebar-t3code-study.md` and
`plan-sidebar-and-state-findings.md` for the evidence this program is built on. Surface is reserved
for interaction; the row's subject is its name; one owner answers what an agent is doing; a name is
never an identifier; no stock AppKit chrome belongs in the sidebar. Every geometry assertion runs at
220, 280, and 320 pt. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

## Approach

1. Apply the name-first sacrifice order, measured-fit tiers, and cell inset to the slim cell, so the collapsed row is not a second layout with its own bugs.
2. Give the slim row the same interaction fills, focus treatment, and hairline discipline as the card.
3. Confirm the density rule holds: only settled and snoozed rows collapse, and the variant is derived from lifecycle rather than chosen by a caller.
4. Assert both variants at all three widths in both appearances, including a slim row whose name would truncate.

### Implementation sketch

```swift
// One surface model for both variants: only the drawn content differs.
assert(RowVariant.forLifecycle(row.lifecycle) == row.variant)
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- The slim row draws its name untruncated wherever the card would, at all three widths.
- Both variants share one fill, focus, and hairline treatment, asserted over the live tree.
- A caller cannot choose a variant that disagrees with the row's lifecycle.
- Only settled and snoozed lifecycles collapse.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- The slim cell is a separate view class and will silently keep the old measurement bugs unless it is measured too.
- Do not add a third density; the two-variant rule is locked.
- A collapsed row still needs a reachable hit target for its lifecycle action at 220 pt.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
