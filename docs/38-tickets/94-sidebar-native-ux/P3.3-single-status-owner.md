# P3.3 — One owner answers what an agent is doing

Phase: 3 · Status truthfulness
Execution: **autonomous**
Depends on: P3.2

## Goal

Make the supervisor's turn snapshot the only source of an agent's status, with activity drafts contributing the timeline and nothing else.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing, plus

## Approach

1. Let the row builder accept an optional resolved `AgentTileTurnSnapshot` per agent and derive `InboxState` from it through one total mapping.
2. Remove the arm in which a stamped activity draft outranks the derivation: drafts supply the timeline, never the status.
3. Keep the module boundary intact — the snapshot is already a Core type and the builder already sees the UI module, so no new dependency edge is needed.
4. Pin the snapshot-to-state mapping with an exhaustive truth table, so adding a snapshot state without giving it a row meaning fails to compile or fails the table.

### Implementation sketch

```swift
// Drafts carry the timeline. The snapshot carries the status. One owner.
let state: InboxState = snapshot.map(InboxState.state(forSnapshot:))
    ?? .unconfirmed
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- Row status is derived from the snapshot for every agent that has one; no code path reads a persisted status to answer “what is it doing”.
- The drafts-win arm is gone, and a check exercises the real path rather than a synthetic one.
- The mapping is exhaustive: a new snapshot state without a row meaning is a compile error or a red table.
- No new module dependency edge is introduced.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.
