# P4.4 — Naming derived and child agents by precedence

Phase: 4 · Identity and naming
Execution: **autonomous**
Depends on: P4.3

## Goal

Name an agent Continuum spawned on someone's behalf by precedence, so a nameless child is still readable.

## Approach

1. Define one precedence for a derived agent's name: explicit name, then first prompt, then the source ticket or queue item, then the parent's name with an ordinal.
2. Use the ordinal form only as the last resort, and make it parent-relative so a list of children stays distinguishable.
3. Apply the same precedence to headless and role-based spawns, so no path falls back to an identifier.
4. Assert the full precedence ladder including the ordinal fallback and a parent whose own name is still the sentinel.

### Implementation sketch

```swift
// Precedence, last resort last: name -> prompt -> source item -> "<parent> agent N"
displayName = explicit ?? prompt.map(AgentName.fromPrompt)
    ?? sourceItemId.map(AgentName.fromSourceItem)
    ?? "\(parentName) agent \(ordinal)"
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- Every derived-spawn path produces a displayable name; none falls through to a model or role id.
- The ordinal form is parent-relative and unique among that parent's children.
- A parent still carrying the sentinel produces a sensible child name.
- The precedence ladder is asserted rung by rung.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- A source ticket id is often the best name a loop-spawned agent will ever have; do not skip that rung.
- Ordinals must not renumber when a sibling is deleted — that changes a name a human has learned.
- Do not let a child inherit its parent's name verbatim; two identical rows are worse than one ordinal.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
