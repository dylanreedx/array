# P0.2 — Sidebar check leg and structural QA seam

Phase: 0 · Foundations
Execution: **autonomous**

## Goal

Give the sidebar its own executable check leg plus a QA seam over the live view tree, so later packets can assert what is painted instead of describing it.

## Context and design direction

Read `_DESIGN.md` and `_RUNBOOK.md` before editing, plus
`docs/38-tickets/91-agent-tile-ux/plan-sidebar-t3code-study.md` and
`plan-sidebar-and-state-findings.md` for the evidence this program is built on. Surface is reserved
for interaction; the row's subject is its name; one owner answers what an agent is doing; a name is
never an identifier; no stock AppKit chrome belongs in the sidebar. Every geometry assertion runs at
220, 280, and 320 pt. This ticket is deliberately scoped so another fresh agent can verify and
commit it independently.

## Approach

1. Add a `--sidebar-ux-check` leg that builds a real `AgentInboxView` inside a sized offscreen window: size the subtree **before** applying rows, then drive the list's own layout pass so cell views materialize and reposition.
2. Expose QA accessors on the row cell views: per-element drawn frames, drawable-versus-needed width for every label, painted border width and resolved fill for each row state, and the row's resolved variant.
3. Prove the seam is non-vacuous: zero materialized cell views, or a probe that silently returns a default, fails the leg.
4. Leave `--agent-inbox-check` untouched; this leg is additive and both must stay green.

### Implementation sketch

```swift
let host = SidebarProbeHost(width: 280)
host.window.contentView?.layoutSubtreeIfNeeded()   // size BEFORE content
host.inbox.apply(rows: fixtures)
host.inbox.layoutSubtreeIfNeeded()
let cells = host.inbox.qaMaterializedRowCells
guard !cells.isEmpty else { throw ProbeError("no row cells materialized") }
```

The sketch establishes ownership and direction; adapt names to the compiled code, but do not replace
the architecture with a shortcut that couples derivation, presentation, and persistence.

## Done when

- The leg renders every corpus row at a real size and reports a nonzero materialized-cell count.
- Each QA accessor reads the live view tree; none returns a constant or a value the view never painted.
- A deliberately zero-sized probe host fails with a named error rather than reporting an empty pass.
- The matrix inventory grows by exactly this leg.
- Relevant new behavior has a deterministic positive assertion and at least one required negative
  witness observed red against the final check.
- No existing matrix leg, assertion floor, contrast requirement, or I5 boundary is weakened.

## Watch out

- An offscreen `NSCollectionView` materializes nothing unless the subtree is sized before the document is applied — rows plus attributes with zero live hosts is the failure mode.
- Never assert truncation from `stringValue`: the cell elides at draw time and the string is unchanged.
- Do not restructure the inbox view in this packet; it adds probes only.
- Never stage, commit, push, rebase, or alter queue/loop machinery outside the per-ticket workflow.
- If the packet conflicts with compiled reality or a locked decision, mark it `blocked` with concrete
  evidence; do not improvise a second architecture.
