# Focus-session rulings

Decisions I made during the overnight session of 2026-08-03/04 so no packet had to wait on Dylan.
Each records the evidence and the reasoning, and each is reversible. **Read this alongside
`plan-morning-review.md`.**

## R1 — Snoozed rows order by WAKE TIME, not spawn time

**The conflict.** `_DESIGN.md` decision 11 (locked, and grepped by the program guard) says ordering
is *"by creation for active rows, **by wake time for snoozed**, by end time for settled, always with a
stable id tie-break."* `InboxSort.swift` currently orders the snoozed section by spawn time, and its
in-code comment justifies that on stability grounds.

**Why the code loses.** The comment's premise is factually wrong: `snoozedUntil` is a **stored
constant** on the record, not a moving value, so ordering by it is exactly as stable as ordering by
creation. The justification for the deviation does not hold, and `_DESIGN.md` is the contract.

**Ruling.** Follow decision 11. Order the snoozed section by wake time with the id tie-break, and
**replace the wrong comment** rather than leaving a stale reason next to corrected code. Assert the
ordering, and assert the tie-break separately so two rows waking in the same second cannot flap.

## R2 — A lane-level fence allowance for `AgentSupervisor.swift` and `ContinuumApp.swift`

**The problem.** No Phase 6 packet's fence contains a record *writer* or the builder's *call site*,
and no Phase 5 packet's fence contains the file its own check section lives in. Six forced deviations
in Phase 6; four in Phase 5. Taken literally, several packets cannot satisfy their own Approach.

**Ruling.** Granted, per ticket, with the runbook's own mechanism: *"If a compile-enforced migration
requires a directly related call site outside it, document the reason in the ledger before touching
it."* The precedent is already set — P0.4's Approach step 3 required editing the five height pins in
`ContinuumApp.swift`, which its fence omits, and that deviation is recorded in its ledger row.

**Limits, so this does not become a blank cheque.** The allowance covers (a) a call site a compile
error forces, (b) an assertion whose *expected value* the packet deliberately moves, and (c) a
printed summary that would otherwise state something false. It does **not** cover new behaviour in
those files, and it does not cover `ComponentLab.swift` (committed baselines) or the P0.3 corpus
(shifts every fixture index).

## R3 — P4.5 (generated name) is BLOCKED, and that costs nothing tonight

**The evidence.** The packet specifies a one-shot `codex exec --ephemeral -s read-only
--output-schema` process. **That CLI is never spawned anywhere in this repo.** The only provider
process actually spawned is `pi`; `codex` exists solely as a terminal profile and as a rollout
*reader*. So the packet as written cannot be implemented against compiled reality.

**Ruling.** Mark P4.5 `blocked` with this evidence rather than substituting a different provider.

**Why blocking is right here and not elsewhere.** Substituting `pi --no-session` would be a new
capability decision with I5 consequences — a name generated by a model from the user's first prompt
is prompt-derived text crossing a new process boundary — and `_DESIGN.md` decision 9 already makes
naming **best-effort**: *"failure leaves the sentinel and logs."* So a blocked P4.5 degrades to
exactly the behaviour the design specifies for failure. Nothing else in the queue depends on it, and
the deterministic first-prompt seed (P4.2) is what actually fixes the screenshot. This is the one
place where proceeding under an assumption would be a worse outcome than stopping.

**If you want it:** the substitution is a two-line change to the argv plus an I5 assertion that the
generated name is scrubbed at the sync boundary. Say the word and it is a short ticket.

## R4 — Phase 6 must precede the parts of Phase 1–2 it makes reachable

**The finding, verified twice.** `AgentInboxRowBuilder` hardcodes `InboxLifecycle.active` and
`InboxLifecycle.resolve` has **zero** production callers. Extended by the second design pass:
nothing can *write* a parked fact either — `settledOverride` is assigned in exactly two places and
**both write `.neutral`**, while `settledAt` / `snoozedUntil` / `snoozedAt` / `archivedAt` have no
assignment anywhere in production.

So the shelf header, settled tail, paging footer, slim variant, crossfade, and the `.snoozed` /
`.settled` arms of the action guard **never render in the shipped app.** They exist only in fixtures
and checks.

**Ruling.** P6.1 (lifecycle as a pure derivation) runs **ahead of its stated gate dependency**, on
the same basis as the plan's standing deviation: the packets' `Depends on:` lines encode loop
sequencing, not code dependencies. After P6.1 the only reachable non-`.active` value is `.settled`
via the auto-settle rung — whose config already ships with a 3-day default — and that is enough to
light up everything above. The shelf and `.woke` still need P6.3's writer.

**Consequence to expect, not to fear:** P6.1 requires deleting a shim in `ContinuumApp.swift` and
rewriting three honest-limit comments that currently say lifecycle is asserted *around* the shipped
row rather than *through* it. Those comments becoming false is the ticket succeeding.

## R6 — the loop runs at medium thinking (2026-08-04, owner-directed)

Dylan directed a rethink of loop pace after P2.6 consumed three hours. The evidence:
`agent-tile-ux-loop.sh` — the queue-91 loop that landed ten tickets on 07-30 — runs
`PI_THINKING=medium` for worker and review alike, with the same worker→review→matrix→commit
structure and the same REWORK protocol. This queue's loop copied the structure and set `max`,
which taxed every pass 3-4x in wall clock (25-35 min worker passes, 15-25 min reviews, twice per
ticket) without preventing the defects the reviews then caught anyway (the widened resize gate and
the self-agreeing slim oracle were both produced AT max).

Both loop defaults are now `medium`; the program guard holds the new deliberate setting against
silent drift, exactly as it held the old one. Review structure, repair budget, fences, the final
matrix, and every quality gate are unchanged — the enforcement was never the latency.
