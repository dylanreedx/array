Key structural facts:

- `main` and `feat/phase-6-core-data-model` diverged at `7a3b75f`. `main` took a
  short, reviewed hotfix lineage; the feature branch kept going for 32 commits.
  This is why "moving to main" lost features — `main` was never behind by a merge,
  it was a *sibling lineage*.
- `integration/phase-6-reintegration` is a **strict descendant of `main`** with a
  linear history. `main` can be updated at any time with a fast-forward — no merge,
  no conflicts, nothing to lose:
  ```sh
  git checkout main && git merge --ff-only integration/phase-6-reintegration
  ```
  Preserve this property: never commit to `main` directly while the integration
  branch is active.
- **There is no remote.** Every commit, branch, and the stash exist only on this
  machine. This is the single largest risk in the repo.

## 3. Risks, ranked

1. **No remote / no backup.** One disk failure loses ~6,300 lines of unmerged
   work plus the stash. → Create a private remote and push all branches + tags
   today. (Mitigated locally by the `backup/` branch and `archive/` tag.)
2. **Stash as a storage medium.** `git stash drop`/`clear` by any agent would have
   destroyed 3,500 lines. → Mitigated: pinned at `backup/stash-phase-6-qa-ux`.
   Once slices 5–6 land, drop the stash entry; the branch remains.
3. **Ignore rules are local-only.** `qa-runs/`, `.pi/agent-runs/`, `.pi/cache/`,
   `.pi/tmp/` are ignored via `.git/info/exclude` (not versioned). Any fresh clone
   or worktree loses these rules and agents may commit gigabytes of QA artifacts.
   → Move these patterns into `.gitignore` and commit.
4. **Binary QA atlas on the feature branch.** 113 PNGs / 3.7 MB under
   `test/qa-round-5/**` are committed history on the feature branch. Do **not**
   migrate them in slice 4; treat screenshots as local artifacts (ignored), keep
   only `review.md` text if the findings matter.
5. **Doc drift** (see §6): the phased plan, ADR-0017 status, and the bug backlog
   contradict the actual branch state, which misleads agents picking up work.

## 4. Target end state (branch model)

- `main` is the only long-lived branch — the trunk. Always buildable, always
  passes the full deterministic check matrix.
- Feature work happens on short-lived `feat/<topic>` branches cut from `main`,
  merged back via fast-forward or small merges within days, then deleted.
- `integration/phase-6-reintegration` is temporary scaffolding: when the last
  slice lands, fast-forward `main` to it, then delete it.
- `feat/phase-6-core-data-model` becomes read-only reference: the
  `archive/feat-phase-6-tip-20260610` tag already pins it; delete the branch after
  slice 6 lands (the tag keeps everything reachable).
- `backup/stash-phase-6-qa-ux` is deleted only after slices 5–6 are committed and
  verified.
- Agents: never commit to `main`; never `git stash` as a hand-off mechanism —
  commit to a `wip/` branch instead; never merge the archived feature branch.
