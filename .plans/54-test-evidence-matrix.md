## Root screenshot protocol

1. Agents submit absolute PNG/diff paths in `report.json`; Wave-0 validation confirms path containment, PNG structure, SHA-256, expected state ID, dimensions/scale, appearance/zoom, semantic link, and baseline/diff provenance.
2. Repetitions are semantic batches. Capture one deterministic representative per unique visual state/appearance/zoom plus every failure; do not create ten visually identical PNGs just because a semantic test repeats ten times.
3. Root uses the local image viewer on every primary actual/contact sheet and every nonzero/failing diff. If there is no contact sheet, root opens each individual state. A manifest path without root inspection is not visual approval.
4. Root records `PASS`, `FAIL`, or `NEEDS_JUDGMENT` for each viewed image. A missing approved baseline is candidate-only and requires judgment; it is never silently blessed.
5. The morning report embeds the most diagnostic absolute PNG paths so Dylan can see them in the main task. Raw repetition captures and semantic JSON stay linked in the run manifest.
