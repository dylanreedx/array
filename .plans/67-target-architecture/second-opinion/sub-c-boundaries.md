## Judgment

ARC-1/2/3 target real structural defects. ARC-4 has the right direction but its provenance rule is internally inconsistent with the decided policy: growth caused by a spawn or resize pushes neighboring zones, yet the design refuses every `.system` zone move and the harness equates stability with “no move without `.user`.” A granted agent spawn is `.agent(grant)` and may cause a legitimate push; mount-time grow-to-contain is `.system` by its own description. The model needs a *causal transaction* with the initiator, affected closure, pre/post geometry and persisted outcome, not a simple “user or no movement” test. ARC-5 can check this only after the rule is made precise. A random sequence is useful as fuzzing, not a substitute for fault injection and explicit boundary scenarios.

## Additional concrete failure mechanisms absent from the board

1. **Workspace switching can leak target controllers when preparation fails.** `WorkspaceRuntime.switchWorkspace` acquires each arriving live project in a loop (`WorkspaceRuntime.swift:1523-1534`). A later `registry.acquire` can throw, and there is no `defer`/catch releasing earlier acquisitions before the method exits. `ZoneRuntimeRegistry.acquire` creates or increments a ref count (`ZoneRuntimeRegistry.swift:35-43`); `closeAll` releases only `acquiredProjectIds` (`WorkspaceRuntime.swift:813-820`), which is not assigned the new list until `switchWorkspace:1618`. Static consequence: a two-project target where project one acquires and project two fails leaves the first controller and its project lock held while the old scene remains mounted. This is independent of document single-writer or all-zone layers. Add a prepare/commit boundary that rolls back all newly acquired resources on every thrown pre-commit path. Inject a failure on the second acquisition and assert the registry's project ids/ref counts and filesystem lock ownership equal the pre-switch snapshot.

2. **The layout persistence barrier acknowledges partial transactions.** `persistLayoutTransaction` silently ignores a transaction zone ID absent from the freshly loaded document (`ContinuumApp.swift:14678-14682`), a tile ID absent from `ambientTiles` (`:14693-14696`), a project missing from the registry (`:14704-14706`), a missing project canvas (`:14706-14708`), and tile IDs absent from each loaded canvas (`:14718-14723`). It still returns `true` (`:14742-14746`), so `CanvasNSView.persistGeometrySnapshot` treats the geometry as committed and keeps the preview (`CanvasNSView.swift:2779-2785`). The board's “one document writer” and serialized canvas queue do not establish *transaction completeness*. This is a static fact about the success path; a concrete reproducer needs a seeded missing canvas/project or stale tile identity. Require each promised zone and tile update to resolve exactly once to an owned store before writing, and fail the whole layout transaction otherwise. Fault witness: delete one seeded target canvas between capture and commit in an isolated fixture; UI must roll back and no workspace/project file may advance.

3. **Registry ownership and document scope are still a cross-file transaction.** Picker confirmation assigns and saves project ownership (`ContinuumApp.swift:14905-14908`) before `commitProvisionalZone`/`setZoneScope` emits the document mutation (`:14923-14936`). `WorkspaceRuntime.commitCreatedZone` independently assigns and saves registry ownership before appending and saving the new zone (`WorkspaceRuntime.swift:116-135`). If the subsequent document save fails, ownership has advanced without the zone. The in-memory document has advanced too, because append precedes `persistWorkspaceDocument`. ARC-1 says “setZoneScope (project + home atomically)” and removes duplicate ownership fields, but a single document owner does not make the registry plus workspace file atomic. The reachable failure is inferred from the ordered writes; injected store failure should establish its visible effect. Define a durable protocol across files (prepare, write, reconcile on mount, or rollback), with a witness failing the document write after registry success. Test both newly created and existing-zone reassignment.

4. **Synchronous document mutation can report failure after changing the live truth.** `commitZonePlacement` replaces `document.zones[index]` then calls a throwing save (`WorkspaceRuntime.swift:108-114`); `commitClosedZone` removes the zone and its tile membership before the same throwing call (`:143-154`). `setActiveZone` mutates document/canvas then discards immediate save errors with `try?` (`:402-428`). `removeDocumentLinks` explicitly saves a prior value and restores it on failure (`:1412-1417`), showing this rollback is local, not a general runtime guarantee. ARC-1's `commit(mutation)` must specify whether a failed flush rolls back memory/UI, or retains a visibly dirty mutation for retry. “One writer” alone does not prevent a failed create/close/rename from later being saved by an unrelated flush. Fault-inject each mutation's store write and assert memory, disk, chrome, and return status agree on committed versus pending state.

5. **Mount and switch preparation can write outside a declared scene commit.** `WorkspaceRuntime.install` calls `membership(forProject:...)` while building layers (`WorkspaceRuntime.swift:699-706`); its repair path saves a project canvas with `try?` (`:541`, as identified in the reports). Thus merely mounting can rewrite `.array/canvas.json` before the scene is complete, and any error is suppressed. This conflicts with ARC-4's “frame only changes in a named layout transaction” if membership repair changes stamps, and with ARC-5's “crash-style remount” if the harness assumes remount is read-only. Treat legacy repair as a staged migration with an explicit source and report, or at least assert mount idempotence by comparing project file bytes after a second mount. The code establishes the write; any claim of user-visible loss requires a fixture.

6. **Project canvas flush can announce durability after a failed write.** The debounced path ignores `saveCanvas` errors with `try?` and still schedules `onCanvasStatePersisted` (`ZoneRuntimeController.swift:690-700`). The synchronous path also ignores the error, clears `isCanvasDirty`, and calls the same callback (`:735-746`). `flushMountedWorkspaceState` calls this through `flushAll` before switch/quit (`WorkspaceRuntime.swift:798-807`), so its throwing workspace-document save cannot prove all project canvases reached disk. ARC-1's serial queue fixes ordering but must carry write failure and acknowledgment to the caller. Inject a project canvas write failure, then switch or quit; the action must refuse or clearly retain a retryable dirty state, and no “persisted” observer may fire.

## Architecture refinements

**ARC-1.** Stamp workspace identity and centralize document writes, but include registry ownership in the consistency contract. A version/generation in one file only prevents wrong-target saves; it does not ensure the registry, workspace document, project canvases, and agent records represent the same action. The current layout writer attempts rollback of earlier canvas saves on later failure (`ContinuumApp.swift:14726-14740`), but the rollback itself can fail (`:14737-14738`); ARC-1 should define recovery from an interrupted or failed multi-file transaction. The proposed quarantine must also distinguish a genuinely foreign zone from a temporarily unresolvable project. `mountableZones` currently asks `exclusiveWorkspaceOwner` for every project zone and can throw for one bad registry entry, aborting the whole mount (`WorkspaceRuntime.swift:1677-1685`). A “quarantine on load” path needs an explicit invalid/missing-owner state rather than assuming every rejected zone has a known other owner.

**ARC-2.** All mounted zones having layers removes the half-real scene and flat fallback. Keep the term “all mounted zones” exact: project-less ambient/group zones also need a layer and their `ambientTiles` views. It is safer to assert a bijection of document zone IDs to layer IDs and of persisted tile identities to views *within the zone/project ownership boundary*. A duplicate tile UUID in separate project canvases is a distinct identity collision; a simple global `tileView(for:)` count can hide it. The hydration budget should count actual live runtimes independently of layer count, including after a failed runtime acquisition.

**ARC-3.** Derivation from placement, registry and rollup is sound. Make missing registry entry a first-class “bound but unresolved” presentation; otherwise the pure function can faithfully display the old misleading “Needs Project” for a zone that still has a `projectId`. The saved zone identity must remain visible even when the registry lookup fails. Agent rollup updates should invalidate only rollup-dependent presentation and never rewrite name/home inputs.

**ARC-4.** The decided policy is **growth pushes neighbors exactly as a drag does and never overlaps**. Apply collision resolution to the complete mounted scene, including ambient zones, and persist pushed zones plus *all their member tile frames* in one causal transaction. The transaction's source should distinguish direct user gesture, user-commanded spawn, granted agent action, lifecycle materialization, and legacy repair. Its allowed effects can be a computed closure of the initiator's push chain; arbitrary peer movement remains forbidden. A materialize view swap should preserve the exact world frame and membership and produce no geometry transaction. The proposed prod “self-heal by grow-to-contain” contradicts its refusal of `.system` zone moves; decide whether repair is a separately authorized migration logged on mount, a quarantined invalid scene, or a nonpersistent visual containment. Silent auto-repair would itself be the unrequested movement Dylan is trying to eliminate.

**ARC-5.** Start with deterministic two-workspace traces, but add fault schedule coverage at boundaries: second controller acquisition throws; registry save succeeds/document save fails; project canvas missing during layout commit; final project canvas write succeeds/document write fails/rollback fails; debounce fires after workspace switch; process stops after each durable write. Record action seed *and fault index*, initial fixture hash, channel, runtime generations, and per-file checksums. Assert both scene state and disk state after every action and remount. Positive controls should perturb each oracle independently (header, tile frame, ownership, layer, store acknowledgment). A random 200-step sequence alone may never choose a rare interleaving or a failure at a specific file write, and `clean quit-remount` exercises a different path from an interrupted process. Existing green checks cannot be used as evidence for these cases; no checks were run in this review.
