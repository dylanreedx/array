# Dropdowns and UI that escapes WKWebView

Research date: 2026-11-05. Array baseline: release 0.7.44, d41dad0486829bb2b92cdbf08ee49d3d75279fdb. No product changes, UI probes, live tile operations, synthetic system input, builds, matrix, tmux, commits or pushes. Labels apply to each paragraph or table row. GUESS includes recommendations and deductions not witnessed on this Mac. MEASURED is deliberately absent: nothing here establishes runtime behavior on Dylan's installed WebKit.

## Why the dropdown floats

**READ IN SOURCE:** A native select becomes an AppKit NSMenu backed by NSPopUpButtonCell in Array's UI process. WebPopupMenuProxyMac populates it, attaches it to the select rectangle in the web view, selects the current item and calls PAL::popUpMenu synchronously. The menu is native UI outside the page bitmap, rather than a DOM overlay. It is anchored over or below the control, with direction-sensitive offsets. Its hide methods cancel menu tracking; cleanup follows tracking's return. [WebPopupMenuProxyMac.mm](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/mac/WebPopupMenuProxyMac.mm).

**READ IN SOURCE:** PAL converts view bounds through the containing window into screen coordinates, adds popup placement adjustments, then invokes AppKit's private menu implementation. This explains why canvas clipping is not a boundary for the menu. The actual backing menu window implementation belongs to AppKit and was not inspected. [PAL PopupMenu.mm](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/PAL/pal/system/mac/PopupMenu.mm).

**READ IN SOURCE:** WebPageProxy explicitly accounts for a nested run loop during popup presentation, including stopping its responsiveness timer. An upstream fix describes focus changing to a different frame during tracking, with the old routing leaving the select's popup-visible state stuck. This is evidence of reentrancy, not proof that Array hits that particular upstream bug. [WebPageProxy.cpp](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/WebPageProxy.cpp), [upstream change 313449](https://results.webkit.org/commit?uuid=177915231300).

**GUESS:** The main thread remains inside native tracking while servicing the nested loop. It is wrong to claim either that Array completely freezes or that all other agents continue normally. Work eligible for the tracking mode may run; default-mode timers and continuations may be delayed. Main-thread reentrancy can interleave unrelated work. Exact Swift concurrency/IPC progress and cross-agent throughput need a safe runtime witness.

**GUESS:** The likely explanation for Dylan's symptom is that opening the native menu and choosing its item span separate agent steps, while interruption cancels the agent rather than the native tracking session. No owner cancels that session. Some menus may dismiss on a later outside click; this is not a lifetime guarantee. The installed OS's exact dismissal behavior has not been measured.

## What release 0.7.44 actually does

**READ IN SOURCE:** BrowserAutomationScript.swift maps single selects to combobox and multiple/size>1 selects to listbox. The current selected labels appear as value. Combobox is in LEAF_ROLES, so the outline does not enumerate a collapsed native select's options. Listbox children are walked, subject to visibility/size filtering. A WKSnapshot captures web content, not an authoritative representation of native menus.

**READ IN SOURCE:** BrowserAutomation.click resolves a ref through target(), scrolls it into view, obtains its center and tests hit landing. deliverClick converts CSS coordinates using pageZoom and view/window conversion, calls webView.mouseDown and mouseUp directly, then restores the prior responder. It does not route option picking through a select-specific path. The script's operation named `select` selects text for clear-and-type; it does NOT select a dropdown option. SELECT is not editable under target(). No menu cancellation exists in BrowserAutomation.swift.

**READ IN SOURCE:** Available primitives are click, pressKey and page-world evaluate. There is no first-class select-option tool in this baseline. Thus evaluate can set a select's value and dispatch change, or an agent may attempt native click/keys; the implementation supplies no reliable native-popup option-ref path. Prior plan research records a JS select assignment working with untrusted events, but that old observation was not rerun here. Sources: `git show d41dad04:Sources/ContinuumRevived/BrowserEngine/{BrowserAutomation.swift,BrowserAutomationScript.swift}`; `.plans/80-browser-computer-use/research/wkwebview-feasibility.md`.

**READ IN SOURCE:** WKWebViewBrowserRuntime.swift:1241–1310 already routes alerts to immediate completion, confirm to false, prompt to nil and file chooser to nil while isEngaged. Downloads are tagged at initiation and sent to agentDownloadDestination without a save panel. Agent targetFrame=nil navigation is canceled and forwarded to agentPopupRequest. These are useful precedents, but cancellation is not task completion: an automatically canceled confirm cannot complete a workflow requiring acceptance. Asynchronous presentation after isEngaged ends also needs ownership beyond an action-scoped boolean.

## Other escape surfaces and a popup-free route

## Contract and compatibility

**GUESS — recommendation:** Add `array_browser_select_options(ref)` returning values, labels, indices, optgroups, disabled/selected flags and multiple. Add `array_browser_select(ref, values[])` with explicit index disambiguation for duplicate values, atomic validation, disabled-option rejection and readback. Use a native SELECT-only contract; custom ARIA combobox/listbox widgets require their own page interactions. Support same-origin frames/shadow roots through stable refs; explicitly report unreachable frames.

**GUESS — recommendation:** DOM selection should call the platform prototype setters, update selectedness, emit bubbling input then change only when changed, and read back after framework reconciliation. React tracked inputs can require bypassing an instance setter so its event system notices the change; Vue v-model listens to the appropriate input/change path, but modifiers and rerenders can alter results. Verify application state, not just the immediately assigned DOM value. User-defined handlers, controlled rerenders and isTrusted checks can still reject this. Never call DOM assignment fully equivalent to trusted user interaction. Date/color normalization, validity and disabled controls need explicit results.

**READ IN SOURCE:** The inspected public WKUIDelegate has no native-select delegate. The inspected private UIDelegate header contains no PopupMenu hook. This limited search does not prove there is no SPI anywhere. WKWebViewPrivate declares `_dismissContentRelativeChildWindows`; its actual implementation/coverage was not inspected, so it is only a candidate, not a verified universal cancel API. [WKWebViewPrivate.h](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/API/Cocoa/WKWebViewPrivate.h).

**GUESS:** I found no supported preference establishing “disable all native popup UI.” A feature flag that disables one input type may change HTML semantics rather than redirect its picker. Private SPI must be availability-checked and witnessed per supported OS. Do not promise suppression based on header presence. An in-page replacement listbox avoids AppKit but changes page structure, styling, accessibility, focus and framework bindings; prefer a semantic tool over mutating every site's UI. Programmatic Escape or blur is weaker than preventing presentation and may affect the wrong surface.

## Lifetime guarantee and replay obligation

**GUESS — recommendation:** Prevention must be the primary safety net. Intercept all agent routes to native select/picker activation, including coordinate clicks, labels, keys, page showPicker(), delayed handlers and frames. Use semantic actions or fail before delivery. An action-scoped click filter alone cannot guarantee this for arbitrary page JS. Keep a persistent agent-surface policy, with every native callback owned by a page/session/action generation. Cancel pending replies on timeout, navigation, cancellation and teardown. Complete callbacks exactly once. A best-effort dismiss in defer is not a guarantee if menu tracking prevents the defer from running.

**GUESS — limitation:** With public WKWebView APIs alone, this research does not establish a universal “no popup ever” guarantee for arbitrary trusted input and arbitrary web content. If prevention cannot cover a surface, reject that operation or use a separately isolated browser backend. Do not drive system Escape, close unrelated menus or steal focus to clean up.

**GUESS — required replay:** In an isolated off-screen nonactivated harness, run native select, multiple select, duplicate/disabled options, React/Vue controlled examples, date/color/datalist, custom ARIA listboxes, and immediate/delayed showPicker. Interrupt before open, while pending, and between open/choose; also timeout, navigate and destroy. Prove final DOM and application state, event order/trust, exactly-once callbacks and zero surviving owned surfaces. Concurrently prove another agent's operations and a main-thread heartbeat finish on deadline. Record frontmost app, key/main window, responder, pointer and canvas camera before/after; none may change. A harness that cannot guarantee no on-screen UI must not run here. Safe API/header reading does not substitute for this replay.
