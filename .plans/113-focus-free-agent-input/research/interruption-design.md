# Interruption and sharing design

Scope: release commit `d41dad04`. Research only, 2026-11-05. All file:line references below refer to that commit, under `Sources/ContinuumRevived/`. READ IN SOURCE means code inspection, not reproduced behavior. GUESS includes proposed policy and inferred risks requiring replay. No live input, builds, checks, windows, tmux, product edits, commits or pushes were performed. No VENDOR DOCS claims are used. No runtime behavior was MEASURED.

## Most consequential findings

- READ IN SOURCE: responder restoration is unaware of user activity elsewhere. Typing saves the window responder across asynchronous work, then restores it if this browser's input counter is unchanged (`BrowserEngine/BrowserAutomation.swift:250-291`). That counter only sees keys/clicks whose responder/hit ancestor belongs to this browser (`:629-648`). GUESS: clicking another composer during typing can therefore be overwritten by the final restore; the next real key can go to the previously restored browser or other old surface. This is a concrete risk path, not a witnessed misdelivery.
- READ IN SOURCE: takeover is not a durable pause for an agent-owned browser. A real browser click calls `takeBackBrowser`, releases engagement and removes navigation hooks (`App/WorkspaceAPIService+Browser.swift:137-150`), but admission still accepts the same controlling owner (`:72-75`), and the next action clears the taken-over marker (`:541`). GUESS: the agent can reclaim the page on its next request while Dylan is still using it.
- READ IN SOURCE: refs are document-local names without document identity. Bootstrap starts `next: 1` in each document; refs use `e` plus that counter (`BrowserEngine/BrowserAutomationScript.swift:17-18,104-110`). GUESS: after navigation and another outline, an old `e1` can address a different element. Snapshot generation in replies does not prevent this because click requests supply a bare ref.
- READ IN SOURCE: the per-tile queue already avoids concurrent agent actions and remembers uncertain outcomes. Preserve this foundation; the missing boundary is between a running action, real user ownership, and view/runtime lifecycle.

## Lifetime of a request

READ IN SOURCE: `App/WorkspaceAPIService+Browser.swift:408-423` decodes the request with a default 15-second arrival-time budget; wait requests use at least 15 seconds or requested wait plus five. Admission resolves an explicit tile in the mounted scene and the agent's project; multiple occurrences, foreign projects, wrong owner, and absent live runtimes are rejected (`:39-84,464-470`). Ownerless browsers require handover; Free permission is insufficient for control. Approval waits may reset or extend budgets (`:458-460,478,504,531`).

READ IN SOURCE: the service canonicalizes JSON excluding the idempotency key and captures runtime identity, input count, revocation generation and permission (`:479-507`). `BrowserActionQueue` is MainActor, FIFO per tile, with one active entry and capacity 64 (`App/BrowserActionQueue.swift:8-13,65-70,127-148,168-195`). Separate tiles can interleave whenever MainActor tasks suspend. Head-of-queue authorization rechecks current scene, project, grants, cancellation and runtime identity; input-count changes reject queued work (`:198-215`; service `:487-499`). Domain policy and lease engagement run before invoking `BrowserActionExecutor` (`service :519-543`).

READ IN SOURCE: engine input is MainActor; JavaScript and WebKit callbacks suspend the action. A ref click queries/scrolls/hit-tests its element, may wait 50 ms after hidden-to-visible transition, checks input control, and sends mouse-down then mouse-up directly to the WKWebView (`BrowserEngine/BrowserAutomation.swift:222-232,475-497`). There is **no explicit asynchronous gap between down and up** in this implementation, even for double-click; both are synchronous method calls. GUESS: native tracking inside `mouseDown` can reenter AppKit and defeat the assumption that the pair is uninterrupted; native select menus need a dedicated replay, not an assertion that MainActor alone makes it atomic.

READ IN SOURCE: typing waits for one second since this tile's last user key, records input count, optionally resolves/clicks the field, waits 50 ms, checks DOM focus, optionally selects existing content, then emits characters with 5 ms yields and a counter/deadline check before each (`:250-291,651-658`). Submit follows the text. With a ref it waits another 100 ms and reads the value. `pressKey` saves/restores the responder unconditionally after its body (`:319-334`). Scroll uses isolated-world JavaScript rather than an OS scroll event (`:337-348`).

READ IN SOURCE: action completion means input was dispatched plus a best-effort settle; it does not prove the website operation succeeded. `act` waits 120 ms and up to five seconds while loading; settle errors are swallowed. It optionally computes outline differences, reports navigation, URL/title, dialogs, console errors and typed value (`:408-437`). Explicit wait polls every 100 ms, capped at 30 seconds, and idle means not loading, ready and 500 ms mutation quiet (`:355-389`). JavaScript/screenshot calls race callbacks against a main-queue deadline gate; timeout suppresses a later reply but does not cancel page execution (`:676-715`).

READ IN SOURCE: adapter errors become `browserNotLive`, `outcomeUnknown` for timeout, `busy` for user input, `targetConflict` for stale/covered/noneditable/focus issues, or `invalidRequest` for script failures (`App/BrowserActionExecutor.swift:95-106`). Queue timeout before execution is busy; during execution is outcomeUnknown. An active timed-out action retains the tile queue until its task returns, preventing overlapping late effects (`App/BrowserActionQueue.swift:151-192`). At finish, changed authorization or input turns the result into outcomeUnknown (`:218-244,261-264`). GUESS: these tool errors are recoverable protocol outcomes; whether a model stops its overall run depends on its harness/prompt and was not established here.

## Refs, wrong destinations and retry

READ IN SOURCE: retained element identity survives new snapshots and unrelated focus/camera changes while the same document/node lives. Removed nodes return stale; covered/invisible targets produce actionable text (`BrowserAutomation.swift:35-49`; script `:212-249`). No document epoch accompanies bare refs. GUESS: qualify refs with runtime + tab + document epoch and reject old epochs, including after back/forward restoration; revalidate the exact node and geometry immediately before dispatch.

READ IN SOURCE: synthetic keys call the specific `webView.keyDown/keyUp`, not the window's current first responder (`BrowserAutomation.swift:512-527`). Thus there is no explicit “send agent text to current composer” route in this layer. GUESS: native WebKit tracking, input methods and popup routing still require witness coverage; direct delivery is not proof of their isolation. The more evident reverse hazard is stale restoration putting Dylan's next key in the page. Within the page, no-ref type/pressKey follows current DOM focus; a ref type verifies focus once, then sends the whole stream across yields without checking that field each character (`:267-288`). GUESS: script-driven focus change can misdirect remaining characters to another page field.

READ IN SOURCE: same key + principal + canonical request joins/replays the queue result; mismatched payload conflicts. Uncertain replies are retained as tombstones and cannot be evicted to replay effects. Settled entries can be evicted at capacity 64 (`BrowserActionQueue.swift:89-138,266-286`). GUESS: a new key, an evicted settled key, service restart, or retry after partial input can double-apply. This is bounded session deduplication, not persistent exactly-once website effects.

## Proposed sharing contract

GUESS (design): preserve a per-tile FIFO but bind each action to a control epoch, runtime/tab/document identity and principal. One writer holds the tile; readers may observe without stealing ownership, mutating another client's comparison baseline or claiming that observation equals control. Multiple agents must explicitly transfer writer ownership at a completed action boundary. Do not interleave multi-step user/agent mutations on one document.

GUESS (design): unrelated clicks, composer typing, pan/zoom, zone/workspace navigation, occlusion and app inactivity never pause the writer. Keep its actual runtime/input surface alive independently of the mounted scene; protect active actions as well as running turns against eviction. Preserve the actual visible WKWebView, with no tile picture swap. If a truly background-capable trusted-input backend cannot maintain this contract, return an explicit capability failure before input rather than pretending focus save/restore is isolation.

GUESS (design): real pointer-down or keyboard interaction directed into the driven tile means immediate user takeover; include direct page scroll, touch/gesture interaction and profile/tab change. Mere pointer hover or navigation elsewhere does not. Increment control epoch synchronously in the real event monitor before normal delivery; stop new agent effects, release any agent-held buttons/modifiers and dismiss only agent-owned native tracking UI. Allow Dylan's original event through. Hold queued mutations in a paused state or return userTakeover with no effects; never silently resume after one quiet second. Explicit “Return to agent” in the tile hands back control and requires a fresh snapshot. Closing the tile ends control permanently; reopening creates a new identity.

GUESS (design): every result should include actionId, control epoch, state (completed/paused/rejected/outcomeUnknown), effects (none/partial/committed/unknown), retryability and freshSnapshotRequired. For text report delivered character count where knowable, while warning that DOM handlers may transform it. Cancellation after dispatch must never be described as no effect. Do not automatically replay click, Enter/submit, evaluate or append-type after takeover/timeout. Use the same idempotency key for transport retries; preserve uncertain tombstones across restart or explicitly end the retry session. Re-observe page state before a new semantic action. An idempotency key cannot roll back a website POST.

GUESS (design): a quiet existing header chip can show “Agent working”, “You have control”, and a tile-local handback action. Use Array's existing typography, colors and Choice components. Draw agent cursor/click feedback entirely inside the tile, clipped to its content; it must never move the system pointer, create an accent edge/one-sided border, pop an app-wide panel, grab focus, pan the camera or replace the tile with an image. Agent native selects need a background-safe selection path or an explicit unsupported result; a floating system menu is not acceptable feedback. Light/dark rendering must be verified before preview.

## Required production-path witnesses

GUESS (proposed tests, not executed): mount with `AppDelegate.mountWorkspaceSceneAtBoot`, use production MCP/service/queue and a real WKWebView fixture. Inject real user event paths with `NSApp.sendEvent` in an isolated QA host, never Dylan's live app. Assert responder, focus broker, composer contents, page event/value logs, key window, pointer position, camera, control epoch, queue outcome and popup absence across the whole action, not only after restore. Deterministic barriers must stop at action boundaries without replacing production delivery. No source-string witness suffices.

GUESS (replay inventory):

1. “user types in another composer during click”: interleave at target lookup and any native mouse-down tracking; page receives one click, composer receives every real key, focus stays in composer.
2. “user clicks another composer during type”: interleave during the 50 ms focus wait, each character yield and final value read; no stale restoration.
3. “user pans during type” and “user zooms during click”: actual camera events, unchanged delivery destination, uninterrupted action, no camera reversal.
4. “user switches zone/workspace during click/type/wait”: continue against original runtime/document without revealing it; return successful bounded result rather than mounted-scene scope failure.
5. “user clicks driven tile during type”: prefix only before takeover; original user click and next key reach intended field; later queued and new mutations stay paused until explicit handback.
6. “user scrolls driven tile during click” and “user changes tab/profile”: epoch changes, no stale coordinate/ref delivery.
7. “agent opens native select while user types elsewhere”: no floating menu, focus/pointer loss or swallowed keys; takeover dismisses only agent tracking.
8. “two agents submit mutations to one tile”: wrong owner rejects; authorized handoff waits for old writer quiescence; concurrent readers cannot corrupt mutation identity.
9. “navigation between snapshot and click”: same numeric ref on new page rejects by epoch; node removal/cover/focus-script changes cannot misdirect text/click.
10. “close/evict/park during each type yield”: no post-termination characters; in-flight action has precise partial/unknown result; next tile never inherits events.
11. “hide/occlude/deactivate/sleep during action”: no focus activation on resume, deadlines reconcile, no late replay or queue overlap.
12. “retry same key during/after timeout/takeover/restart”: at most one dispatch, payload conflict rejected, unknown remains unknown, queued expiry explicitly says no effect.

GUESS (gate requirement): register each behavioral leg with run-matrix, establish red on the released behavior and green on the eventual implementation, and confirm the final matrix report lists every new leg. Future visual QA must show light/dark and no tile-image swap. These are proposed witnesses, not claims that they pass today.
