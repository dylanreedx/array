The native unfold code introduced the bug. It took AppKit-owned reusable card views into an animation overlay. A newly inserted live card could be treated as an outgoing ghost while it temporarily had no superview; after a status reload attached it to its row, animation retirement still detached it and restored its old local frame. The slot went blank and the retained content appeared at the local origin. Fold geometry also read a retained detached card's zero frame rather than its table slot.

The fix leaves table-owned cards in AppKit's hierarchy/reuse pool. Live cards animate on their own layers, not recycled table-row layers. Only departing visible children are captured into disposable image views owned by the overlay; cleanup cannot detach a table-owned card. Native fold destinations come from table row rectangles and authoritative visible views. Opening remains native Core Animation, with no image capture or per-frame layout. Reversal retains the appropriate outgoing image and current presentation position. The shared light implementation is unchanged.

Witness: `--sidebar-row-presentation-check` (registered in the matrix and inventory; no full matrix run). It samples actual title/content `presentation()` layers through their row ancestors, converts those into sidebar coordinates, and compares them with assigned table slots. Every existing visible row must retain a presentation layer. Ordinary updates must remain inside their slots; intentional unfold/reflow motion is bounded by the family region, never the list origin. All four styles run completion, arrival, reload, route change, re-sort, and unfolding variants. The critical case finishes the middle helper without changing row order while the unfold is active, then introduces a new helper.
