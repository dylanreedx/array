## Gotchas
- Similar lifecycle gaps can recur for any tile with mutable AppKit view state when the tile writes directly from its view instead of letting AppDelegate coordinate debounced saves and close-time flushes. Sources/ContinuumRevived/App/TileSpawner.swift:291 Sources/ContinuumRevived/App/ContinuumApp.swift:687.
- The domain knowledge gap is that a file-tree tile has no process runtime, but it still has mutable persisted view state that must be flushed with browser and note state before teardown. Sources/ContinuumRevived/App/ContinuumApp.swift:617 Sources/ContinuumRevivedCore/FileTreeState.swift:15.
- One alternative was to keep `FileTreeTileNSView.onPersist` writing immediately, but that was rejected because the task explicitly requires AppDelegate `scheduleFileTreeSave` and `flushFileTreeSave` to mirror the existing debounced persistence pattern. Sources/ContinuumRevived/App/TileSpawner.swift:610 Sources/ContinuumRevived/App/ContinuumApp.swift:720.
