## What is broken
- A fresh canvas could not remain empty because launch filled missing terminal state for smoke boot paths before any empty-state UI could be observed. Sources/ContinuumRevived/App/ContinuumApp.swift:103
- `CanvasNSView` only hosted tile views, so a zero-tile canvas had no direct Spawn Claude, Spawn Shell, Spawn Browser, or Open in Editor action surface. Sources/ContinuumRevived/Canvas/CanvasNSView.swift:13

## Why
- The empty-canvas smoke flow existed, but it only captured the canvas and did not assert that zero tiles installed an empty-state view or that spawning removed it. Sources/ContinuumRevived/App/ContinuumApp.swift:1646
- Tile creation already belongs behind `TileSpawner`, so the empty-state buttons needed AppDelegate closures that call the existing terminal and browser spawn seams instead of constructing tiles in the view. Sources/ContinuumRevived/App/TileSpawner.swift:72

## Fix
- Fresh project canvas state now starts with zero tiles, while smoke tests seed the default terminal only for non-empty-canvas flows. Sources/ContinuumRevived/App/ContinuumApp.swift:86
- `CanvasNSView` now installs `CanvasEmptyStateNSView` when `canvasState.tiles` is empty and removes it after `install(tileView:for:)` appends the first tile. Sources/ContinuumRevived/Canvas/CanvasNSView.swift:119
- `CanvasEmptyStateNSView` renders four centered monospaced AppKit buttons and only hit-tests button clicks so background pan and zoom routing stay on the canvas. Sources/ContinuumRevived/Canvas/CanvasEmptyStateNSView.swift:42
- AppDelegate wires the empty-state actions to `spawnTerminalFromProfile("claude")`, `spawnTerminalFromProfile("shell")`, `spawnBrowserDefault()`, and the existing Neovim editor handoff path. Sources/ContinuumRevived/App/ContinuumApp.swift:130

## Gotchas
- Similar first-launch regressions can recur if boot code injects default tiles before canvas construction, because an empty-state overlay depends on `canvasState.tiles.isEmpty` at `CanvasNSView` init time. Sources/ContinuumRevived/App/ContinuumApp.swift:90
- The domain knowledge gap is that the overlay must be a pass-through AppKit view outside the tile registry, otherwise it can steal canvas pan and zoom events from `scrollWheel(with:)`. Sources/ContinuumRevived/Canvas/CanvasEmptyStateNSView.swift:42
- The rejected alternative was to implement the four buttons as synthetic tiles, because that would make the canvas non-empty and prevent the same `TileSpawner` spawn transition from proving overlay removal. Sources/ContinuumRevived/Canvas/CanvasNSView.swift:36
