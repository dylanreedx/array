## What is broken
- The palette Core lift existed in source, but `docs/09-decisions.md` stopped at ADR-0020 and did not document why `LaunchPaletteModel` belongs in Core for AppKit-free checks. docs/09-decisions.md:766
- The undocumented boundary matters because `LaunchPaletteModel` owns row construction, action filtering, selectability, and file containment while `LaunchProfilePalette` owns AppKit rendering and interaction. Sources/ContinuumRevivedCore/LaunchPaletteModel.swift:75 Sources/ContinuumRevived/App/LaunchProfilePalette.swift:57

## Why
- `LaunchPaletteModel` is pure Core code that imports Foundation only, so the palette logic can be tested without constructing AppKit views. Sources/ContinuumRevivedCore/LaunchPaletteModel.swift:1
- `ContinuumRevivedPaletteChecks` exercises the model through `LaunchPaletteModel.makeRows`, `filterRows`, selectability, and `isFileURL` while importing `ContinuumRevivedCore` directly. Sources/ContinuumRevivedPaletteChecks/main.swift:1 Sources/ContinuumRevivedPaletteChecks/main.swift:27
- The Core purity invariant requires Core to avoid UI and runtime imports and to cover new Core types through executable checks. memory/44a57b2d-fc94-4058-9b43-82a15b0996aa

## Fix
- Added ADR-0021 to document that palette row modeling and filtering live in Core while AppKit remains an adapter for view wiring, focus, keyboard commands, rendering, and callbacks. docs/09-decisions.md:766
- The ADR records the verification contract for `scripts/prepare-ghosttykit.sh`, `swift build`, `ContinuumRevivedCoreChecks`, `ContinuumRevivedPaletteChecks`, and the smoke test. docs/09-decisions.md:781
- The ADR rejects fuzzy ranking as deferred because the current Core model preserves row order and filters rather than scoring rows. docs/09-decisions.md:789
