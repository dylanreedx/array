## What is broken
- The file tree remained a deferred Phase 6 deliverable even though docs require async scanning, ignore lists, search/filter, open-with, and cheap git status badges. docs/06-browser-code-file-surfaces.md:196
- ADR-0017 deliberately shipped note and single-file tiles without expanding into a file tree, so there was no implementation-ready design for the missing workspace-context surface. docs/09-decisions.md:524

## Why
- The existing single-file preview helper reads one file and applies size and binary checks, so it does not define metadata-only directory scanning or cancellation. Sources/ContinuumRevivedCore/FilePreview.swift:9
- The existing file tile can dispatch one non-local file load in `Task.detached`, but local file loads still happen directly and the view has no tree-walk, ignore-list, search, or git-status model. Sources/ContinuumRevived/Canvas/FileTileNSView.swift:47
- ADR-0017 explicitly deferred the file tree because async directory scan, ignore lists, git status badges, and filtering were too large for the note/file MVP. docs/09-decisions.md:602

## Fix
- Added a design-only file tree tile spec that defines Core-owned `FileTreeState`, background scanner tasks, cancellation on tile teardown, hardcoded heavy-folder ignores, inline `NSSearchField` filtering, preferred-editor open-with fallback, cheap git status badges, persistence, verification gates, deferred scope, and rejected alternatives. docs/superpowers/specs/2026-05-09-file-tree-tile-design.md:1
- Kept the change documentation-only so the brainstorming hard gate and task instruction not to implement remain intact. docs/superpowers/specs/2026-05-09-file-tree-tile-design.md:4
