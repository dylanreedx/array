## What is broken
- File tiles had no AppKit view or spawn path, so a persisted `.file` tile could not render a read-only text preview from `TileMetadata.filePath`. Sources/ContinuumRevived/App/TileSpawner.swift:215
- The preview policy needed to reject missing, oversize, binary, and non-UTF-8 files before the view displayed content. Sources/ContinuumRevivedCore/FilePreview.swift:9

## Why
- File tile content belongs in Core preview classification because binary and oversize decisions are data policy, not AppKit layout behavior. Sources/ContinuumRevivedCore/FilePreview.swift:21
- The AppKit view still owns sync versus async loading because local-volume checks decide whether the UI thread can read immediately or must defer work. Sources/ContinuumRevived/Canvas/FileTileNSView.swift:53

## Fix
- `FilePreview.load(path:)` returns text only for existing regular UTF-8 files under 1 MB and returns explicit unavailable messages for missing, oversize, BOM, decode, and null-byte binary cases. Sources/ContinuumRevivedCore/FilePreview.swift:12
- `FileTileNSView` installs a read-only selectable `NSTextView`, loads local files synchronously, loads network-volume files from a detached task, and returns UI updates to the main actor. Sources/ContinuumRevived/Canvas/FileTileNSView.swift:15
- `TileSpawner.spawnFile` creates `.file` tiles with `TileMetadata(filePath:)`, installs the file tile view, persists the canvas, and `installFileTile` reuses the same view for restore work. Sources/ContinuumRevived/App/TileSpawner.swift:485

## Gotchas
- Similar restore wiring will be needed in the boot-loop task because this task adds `installFileTile` but does not yet call it from startup reconstruction. Sources/ContinuumRevived/App/TileSpawner.swift:517
- The domain gap is that binary detection is only a preview safety heuristic, so UTF-8 decode, non-UTF-8 BOMs, and null-byte scans are used together instead of trying to identify every file format. Sources/ContinuumRevivedCore/FilePreview.swift:31
