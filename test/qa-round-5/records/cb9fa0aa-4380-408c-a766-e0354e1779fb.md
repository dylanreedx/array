## What is broken
- The boot loop installed `.note` and `.file` tiles as descriptor placeholders, so persisted note and file tiles did not restore into their live AppKit tile views. Sources/ContinuumRevived/App/ContinuumApp.swift:123
- Note text changes had no AppDelegate-level debounce or close-path flush, so edited note bodies could remain only in the `NSTextView` when the window closed. Sources/ContinuumRevived/App/TileSpawner.swift:414

## Why
- The boot loop switch grouped `.note` and `.file` into one placeholder arm instead of routing each kind through the TileSpawner install methods created for Phase 6 restore. Sources/ContinuumRevived/App/ContinuumApp.swift:123
- `NoteTileNSView` reports edits through `onTextChange`, but AppDelegate had only canvas and browser save timers before this task. Sources/ContinuumRevived/Canvas/NoteTileNSView.swift:50

## Fix
- AppDelegate now tracks note views by note id, wires `notePersistenceHandler`, and routes `.note` and `.file` boot-loop arms through `installInitialNoteTile` and `installInitialFileTile`. Sources/ContinuumRevived/App/ContinuumApp.swift:46
- `scheduleNoteSave()` uses a 400ms debounce and `flushNoteSave()` writes each tracked note view body through `TileSpawner.writeNoteSnapshot`. Sources/ContinuumRevived/App/ContinuumApp.swift:586
- `windowWillClose` now flushes canvas, browser, and note saves before terminal descriptor stamping or runtime teardown starts. Sources/ContinuumRevived/App/ContinuumApp.swift:501

## Gotchas
- A similar restore gap existed for file tiles because `TileSpawner.installFileTile` was present but the AppDelegate boot loop did not call it before this fix. Sources/ContinuumRevived/App/TileSpawner.swift:517
- The domain knowledge gap is close-path ordering because note flushing must happen before `canvasView` and `tileSpawner` are cleared, while browser and terminal runtime teardown must keep the ADR-0014/0015 order intact. docs/superpowers/specs/2026-05-09-phase-6-file-note-tiles-design.md:306
- The rejected alternative was to save note text directly from `NoteTileNSView`, but the existing browser persistence pattern keeps debounce and close flush ownership in AppDelegate. Sources/ContinuumRevived/App/ContinuumApp.swift:569
