## What is broken
- File-tree nodes carried a persisted-capable `gitStatus` field, but scanner snapshots always populated nil and no cheap git status process existed for the `.cheap` badge mode. Sources/ContinuumRevivedCore/FileTreeState.swift:49 Sources/ContinuumRevived/Canvas/FileTreeScanner.swift:72.
- The file-tree view model installed tile snapshots from directory scans only, so `.cheap` badges could not be added as a follow-up nonblocking update. Sources/ContinuumRevived/Canvas/FileTreeViewModel.swift:30.
- The smoke seam only proved file-tree view installation and tracking, not deterministic leaf visibility or `.git` filtering. Sources/ContinuumRevived/App/ContinuumApp.swift:1338.

## Why
- The design requires one opportunistic `git -C <root> status --porcelain=v1 -z` refresh, transient snapshot-only status mapping, and no per-row shell calls. docs/superpowers/specs/2026-05-09-file-tree-tile-design.md:116.
- The existing scanner was already the data-binding layer that creates `FileTreeNode` values, so status assignment belonged there rather than in AppKit row rendering. Sources/ContinuumRevived/Canvas/FileTreeScanner.swift:64 Sources/ContinuumRevived/Canvas/FileTreeTileNSView.swift:71.
- The view model already owns scan generations and stale snapshot rejection, so the badge refresh needed to merge through the same generation guard. Sources/ContinuumRevived/Canvas/FileTreeViewModel.swift:35 Sources/ContinuumRevived/Canvas/FileTreeViewModel.swift:91.

- Extended `FileTreeViewModel.start` with `gitBadgeMode`, emitted the scan snapshot first, then merged cheap status results into the latest snapshot for the same generation. Sources/ContinuumRevived/Canvas/FileTreeViewModel.swift:30 Sources/ContinuumRevived/Canvas/FileTreeViewModel.swift:51.
