## What is broken
- Cmd-K only listed terminal launch profile rows, so the existing note and file spawn paths were not reachable from the palette. Sources/ContinuumRevived/App/LaunchProfilePalette.swift:17
- The AppDelegate palette callback accepted only a profile id, so there was no route from a palette row to `spawnNote` or `spawnFile`. Sources/ContinuumRevived/App/ContinuumApp.swift:110

## Why
- The palette backing state was `[TileSpawner.AnnotatedProfile]`, which could not represent non-terminal actions like `New Note` or `Open File...`. Sources/ContinuumRevived/App/LaunchProfilePalette.swift:14
- File selection needs a post-panel project-root containment check because setting `NSOpenPanel.directoryURL` starts browsing at the root but does not prove the chosen URL remains inside it. Sources/ContinuumRevived/App/ContinuumApp.swift:482

## Fix
- `LaunchPaletteModel` now appends `New Note` and `Open File...` action rows after profile rows, filters them by action tokens, and rejects sibling-prefix paths in project-root containment checks. Sources/ContinuumRevivedCore/LaunchPaletteModel.swift:84
- `LaunchProfilePalette` now renders profile and action rows from the shared model, keeps unresolved profile rows disabled, and calls separate profile or action callbacks on selection. Sources/ContinuumRevived/App/LaunchProfilePalette.swift:17
- AppDelegate wires `New Note` to `spawner.spawnNote(title: "New Note")` and `Open File...` to an `NSOpenPanel` followed by `LaunchPaletteModel.isFileURL` validation before `spawner.spawnFile`. Sources/ContinuumRevived/App/ContinuumApp.swift:463
