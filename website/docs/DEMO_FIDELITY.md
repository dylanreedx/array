# Demo fidelity to the shipped Mac app

This note compares the production website demo with the shipped AppKit app. The app screenshots under [`.plans/72-launch-night/qa/app`](../../.plans/72-launch-night/qa/app) and the Swift/AgentUI sources are the visual authority. The website demo is a local, scripted illustration; it does not launch agents, run shell commands, modify files, or browse the network.

## Use one continuous workspace

At revision `c7ff27e9`, the production page server-rendered `DemoIsland`/`MacWorkspace`, then hid that tree for the `NativeFilm` segment. The current replacement is `GuidedWorkspace`: it reuses `AgentTile`, `BrowserTile`, `ShellTile`, `NoteTile`, glyphs and native colors in one server-rendered scene. All six tile nodes survive the complete hero/assembly/narrative sequence. A pure DOM controller projects scroll state without hydrating React or replaying timed reducer events. `ScrollStory.astro` remains an unused legacy composition, not the new homepage's UI source.

The audit below records native fidelity targets, with the existing app captures and sources as authority. The new stage follows the native inbox width, save-state label, tile hierarchy, Command Center entry point and provider controls; its small creation menu intentionally condenses the complete native Command Center. It illustrates an example workspace and does not run a provider or execute a terminal command.

## Story accuracy

Show one workspace with a bound project zone, then create or choose an agent, submit a prompt, show its transcript/tool activity, place a separate tool tile beside it, and surface an attention state that the user can resolve. The actual app's state is durable and connected to local provider sessions; the website fixture is not. In particular, `ShellTile` returns canned output for a small allowlist, `BrowserTile` navigates only among local fixture routes, and `AgentTile` advances through reducer timers. Do not caption those beats as a real build/test run, live browser session, or action on the visitor's account. Either keep the on-screen contents clearly illustrative or use a claim supported by the fixture itself.

The app's zone labels come from project resolution, its agent state comes from the current session, and its transcript is provider-derived. Keep demo names and copy generic enough to avoid presenting fixture details as a screenshot of a real user's workspace. Pending approval can remain visible beside the work, but describe it as a demo approval state unless it is driven by the native provider flow.
